[코딩 11장](coding/11-mastery.md)에서 "AI는 빠른 후배처럼 쓰기"를 원칙으로 봤어요.

## 1. AI 코딩 도구의 종류

| 종류 | 예 | 특징 |
|---|---|---|
| **대화형 AI** | Claude, ChatGPT 웹·앱 | 질문·설명·짧은 코드. 파일을 직접 고치진 않음 |
| **편집기 속 자동 완성** | GitHub Copilot 등 | 코드를 쓰는 중에 다음 줄 제안 |
| **AI 에이전트(코딩 에이전트)** | **Claude Code**, Cursor 등 | 프로젝트 파일을 읽고, 여러 파일을 고치고, 명령을 실행하고, 테스트까지 |
| **노코드 AI 빌더** | 말로 설명하면 앱을 만들어 주는 서비스들 | 빠른 시제품. 복잡해지면 한계 |

## 2. 공식 권장 작업 흐름: 탐색 → 계획 → 구현 → 커밋

Claude Code 공식 문서는 4단계 흐름을 권해요.

```
1. 탐색 (Explore)   — 코드를 고치지 말고 먼저 읽고 이해하게 하기
2. 계획 (Plan)      — 무엇을 어떻게 바꿀지 계획을 세우게 하고, 내가 검토·수정
3. 구현 (Implement) — 계획대로 만들고, 계획과 비교하며 확인
4. 커밋 (Commit)    — 설명이 담긴 커밋 메시지로 저장 (6장 Git)
```

- **계획 모드(Plan mode)**: 탐색과 실행을 분리해서, 엉뚱한 문제를 푸는 걸 막아 줘요. (단축키 등은 공식 문서 확인)
- **작고 분명한 수정**(오타, 이름 바꾸기)은 계획 없이 바로 해도 돼요. 계획은 **방법이 불확실하거나 여러 파일이 바뀌거나 처음 보는 코드**일 때 효과가 커요.

## 3. CLAUDE.md — 프로젝트 규칙 문서

- 프로젝트 맨 위에 두는 **"AI에게 주는 이 프로젝트 설명서"** 예요. Claude Code가 매번 읽어요.
- `/init` 명령으로 초안을 만들고 다듬으라고 공식 문서가 안내해요.
- 넣을 내용 예:
```markdown
# 이 프로젝트
- 수제 그래놀라 쇼핑몰. Next.js + PostgreSQL.

# 명령어
- 개발 서버: npm run dev
- 테스트: npm test
- 린트: npm run lint

# 규칙
- 결제 금액은 항상 서버에서 계산 (클라이언트 값 믿지 않기)
- 비밀 키는 .env에만, 커밋 금지
- 새 기능에는 테스트 추가
- 사용자에게 보이는 문구는 존댓말 "-요"체
```
- 너무 길게 쓰지 말고, **문제가 생길 때마다 고치고 정기적으로 정리**하라는 게 공식 조언이에요. (이 레포도 처음에 CLAUDE.md로 "애매하면 먼저 물어보기" 규칙을 썼었어요.)

## 4. 요청을 잘하는 법

### 좋은 요청의 5요소
| 요소 | 예 |
|---|---|
| **목표** | "장바구니에 쿠폰 적용 기능을 추가해 줘" |
| **배경** | "쿠폰은 정액·정률 두 종류, 1주문 1쿠폰" |
| **제약** | "기존 결제 흐름(39장) 바꾸지 말고, 금액 계산은 서버에서" |
| **완료 기준** | "쿠폰 적용·만료·중복 사용 테스트가 통과하면 완료" |
| **확인 방법** | "끝나면 테스트 실행 결과와 바뀐 파일 목록을 보여 줘" |

### 나쁜 요청 → 좋은 요청
| ❌ | ✅ |
|---|---|
| "쇼핑몰 만들어 줘" | "먼저 상품 목록 페이지만 만들자. 상품은 이름·가격·사진, DB 테이블 설계부터 보여 줘" |
| "버그 고쳐 줘" | "결제 후 주문 상태가 '결제대기'로 남는 버그. 재현 방법은 ○○. 원인부터 찾아서 설명해 줘" |
| "보기 좋게 해 줘" | "모바일에서 첫 화면에 제목·설명·버튼 하나가 스크롤 없이 보이게 (38장 A1)" |

## 5. 작업 단위 — 작게 나누기

```
❌ 한 번에: "회원가입·로그인·상품·장바구니·결제·관리자 페이지 다 만들어 줘"

✅ 단계별:
  1단계: 프로젝트 뼈대 + 상품 목록 (DB 설계 확인) → 커밋
  2단계: 상품 상세 → 커밋
  3단계: 장바구니 → 테스트 → 커밋
  4단계: 결제 (테스트 키, 39장 흐름) → 테스트 → 커밋
  5단계: 회원·로그인 → 커밋
  6단계: 관리자 → 커밋
  7단계: 출시 전 30가지 (38장) → 커밋
```
- 단계마다 **직접 화면을 눌러 보고**(50장) 커밋 → 잘못되면 그 단계로 되돌리기 (6장 Git).

## 6. 검증 — AI 결과를 믿기 전에

공식 문서도 **결과를 확인하는 것**을 강조해요. 직접 다시 해 보는 것보다 **증거(테스트 결과·실행 화면)를 보여 달라고 하는 게** 빠르다고 해요.

| 확인 | 방법 |
|---|---|
| 동작하나 | 직접 실행·클릭 (50장) |
| 테스트 | "테스트를 실행하고 결과를 보여 줘" |
| 바뀐 내용 | `git diff`로 무엇이 바뀌었는지 확인 (8장) |
| 보안 | "보안 관점으로 리뷰해 줘" (37장) + 내가 핵심 확인: 권한 확인, 금액 서버 계산, 비밀 키 |
| 이해 | **"이 코드를 한 줄씩 설명해 줘"** — 내가 설명할 수 없는 코드는 아직 쓰지 않기 |

## 7. 흔한 실수와 대처

| 실수 | 대처 |
|---|---|
| 한 번에 너무 큰 일을 맡김 | 단계로 나누기 (5절) |
| 대화가 길어져 앞 내용을 잊음 | 중요한 규칙은 CLAUDE.md에, 큰 단계마다 새 대화 |
| 같은 오류를 계속 반복 | 멈추고 "원인 가설 3가지를 먼저 말해 줘", 오류 메시지 전문 제공 |
| 없는 라이브러리·함수를 지어냄 | 공식 문서 링크 요구, 설치·실행으로 확인 |
| 테스트를 통과시키려고 테스트를 고침 | "테스트는 바꾸지 말고 코드를 고쳐 줘" |
| 비밀 키를 코드에 넣음 | CLAUDE.md 규칙 + 커밋 전 확인 (6·37장) |
| 실제 숫자·후기를 지어냄 | "모르는 건 빈칸, 지어내지 마" (38·46장) |
| 운영 DB에 바로 명령 | 스테이징에서만 (6장), 위험한 명령은 실행 전 확인 |

## 8. 초보자가 AI로 만들 때의 현실적인 범위

| 쉬움 (AI로 혼자 가능) | 중간 (주의 필요) | 어려움 (전문가 검토 권장) |
|---|---|---|
| 랜딩 페이지, 블로그, 계산기·도구 사이트 | 회원제 서비스, 쇼핑몰 직접 개발, 관리자 페이지 | 결제·정산 시스템, 개인정보 대량 처리, 실시간 멀티 게임, 금융 |
| 오목 AI 대전(혼자) | 웹소켓 1:1 대전 (20장) | 수십 명 실시간 게임 (40장) |

> 💡 처음엔 **빌더(쇼핑몰)** 나 **간단한 사이트**를 AI와 함께 만들어 출시해 보고, 경험이 쌓이면 범위를 넓히는 게 안전해요.

### 이 장 요약
1. 공식 권장 흐름: **탐색 → 계획 → 구현 → 커밋**, 프로젝트 규칙은 **CLAUDE.md**에.
2. 요청은 **목표·배경·제약·완료 기준·확인 방법**, 일은 **작게 나눠 단계마다 커밋**.
3. 결과는 **테스트·diff·직접 실행으로 검증**하고, **내가 설명할 수 없는 코드는 쓰지 않는다**.
