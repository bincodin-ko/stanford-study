# 25. 모바일 앱 사업

웹사이트와 앱은 비슷해 보이지만, **배포·업데이트·수수료**가 완전히 달라요.
특히 "업데이트"와 "되돌리기"가 웹보다 훨씬 어렵다는 점이 이 장의 핵심입니다.

> ⚠️ 수수료와 심사 규칙은 앱 마켓 정책이라 자주 바뀝니다. 2026년 10월 조사 기준이며 Apple·Google 공식 문서를 확인하세요.

---

## 1. 웹 vs 앱 — 무엇이 다른가

| 항목 | 웹사이트 | 모바일 앱 |
|---|---|---|
| 손님이 쓰려면 | 주소만 치면 됨 | **설치**해야 함 (큰 장벽) |
| 출시·업데이트 | 내가 올리면 즉시 반영 | **앱 마켓 심사**를 통과해야 함 (몇 시간~며칠) |
| 되돌리기(롤백) | 이전 버전으로 몇 분 | **손님 폰에 이미 깔린 버전은 되돌릴 수 없음** |
| 여러 버전 동시 존재 | 거의 없음 | 업데이트 안 한 사람 → **옛 버전이 계속 돌아다님** |
| 결제 | PG사 | 디지털 상품은 대부분 **앱 마켓 결제 + 수수료** |
| 다시 부르기 | 이메일, 광고 | **푸시 알림** (강력하지만 남발하면 삭제) |
| 기기 기능 | 제한적 | 카메라, GPS, 알림 등 자유롭게 |

---

## 2. 앱 마켓 수수료 (디지털 상품·구독 기준)

| 마켓 | 일반 | 소규모·조건부 할인 (보도 기준) |
|---|---|---|
| **애플 앱스토어** | 30% | 연 수익 100만 달러 이하 개발자는 **스몰 비즈니스 프로그램**으로 15%. 자동 갱신 구독은 2년 차부터 15% |
| **구글 플레이** | 30% | 매년 **첫 100만 달러까지 15%** (신청 필요하다는 설명이 많음), 자동 갱신 구독은 15% |

- **실물 상품**(쇼핑, 배달 음식)이나 **오프라인 서비스**(택시) 결제는 보통 앱 마켓 결제를 쓰지 않고 PG로 처리해요.
- 한국은 2021년 **앱 마켓이 특정 결제 방식만 강제하는 것을 막는 법**(일명 인앱결제 강제 금지법)을 세계에서 처음 만들었어요. 그래서 다른 결제 방식도 쓸 수 있지만, 그 경우에도 수수료가 붙는 구조라 계산을 꼼꼼히 해야 합니다.

### 수수료 반영한 계산 예
```
월 구독료        4,900원
− 앱 마켓 15%     −735원
− 부가세 등 고려
= 내 몫         약 4,000원 이하
```

## 3. 앱의 업데이트와 배포 — 웹보다 조심해야 하는 이유

### 웹(7장)과 다른 점
1. **심사 대기**: 급한 버그를 고쳐도 심사를 통과해야 나감 → **긴급 수정(핫픽스)이 느림**
2. **롤백 불가**: 잘못된 버전을 받은 사람 폰에서는 되돌릴 수 없음
3. **옛 버전 공존**: 서버를 바꿀 때 **옛 앱도 계속 작동하게** 만들어야 함

### 그래서 쓰는 장치
| 장치 | 설명 |
|---|---|
| **단계적 출시** | 새 버전을 손님 1% → 10% → 100%에게 순서대로 배포 (7장 카나리와 같은 원리, 마켓이 기능 제공) |
| **베타 테스트** | 정식 출시 전 테스터에게 먼저 (TestFlight, 구글 플레이 내부 테스트 트랙) |
| **기능 플래그** | 서버에서 기능을 켜고 끄기 → 앱 업데이트 없이 문제 기능 차단 (7장) |
| **서버에서 내려주는 화면/설정** | 문구·배너·이벤트는 서버 설정으로 바꾸면 심사 불필요 |
| **강제 업데이트** | 아주 오래된 버전은 "업데이트해야 사용 가능" 안내 |
| **API 버전 관리** | 서버가 옛 앱 요청과 새 앱 요청을 모두 처리 |
| **크래시 리포트** | 앱이 꺼지면 자동으로 원인 보고 (Firebase Crashlytics 등) |

## 4. 앱 사업의 지표

| 지표 | 뜻 |
|---|---|
| **설치 수(다운로드)** | 깔린 횟수 |
| **CPI** | 설치 1건당 광고비 |
| **D1 / D7 / D30 리텐션** | 설치 후 1·7·30일 뒤에도 쓰는 비율 (20장) |
| **크래시 없는 사용자 비율** | 앱이 안 꺼진 사람 비율. 낮으면 별점 폭락 |
| **앱 평점·리뷰** | 마켓 검색 순위와 설치율에 큰 영향 |
| **푸시 알림 수신 동의율** | 다시 부를 수 있는 사람 비율 |

### 마켓 안 검색 최적화 (ASO)
- **ASO** = 앱스토어 안에서 검색에 잘 뜨게 하기. 앱 이름, 부제, 키워드, 스크린샷, 평점이 중요.

## 5. 앱을 꼭 만들어야 할까?

| 앱이 유리 | 웹으로 충분 |
|---|---|
| 매일 여러 번 쓰는 서비스 (메신저, 가계부, 운동 기록) | 가끔 검색해서 오는 서비스 (정보, 계산기) |
| 카메라·GPS·알림이 핵심 | 처음 시작 단계 (반응 확인 전) |
| 게임 | 쇼핑몰 초기 |

> 💡 처음엔 **모바일에서 잘 보이는 웹**으로 시작해 반응을 보고, 매일 쓰는 사람이 늘면 앱을 만드는 순서를 많이 추천해요. 웹을 앱처럼 설치하게 하는 **PWA**라는 중간 방법도 있어요.

---

### 이 장 요약
1. 앱은 **심사·롤백 불가·옛 버전 공존** 때문에 업데이트가 웹보다 어렵다.
2. 그래서 **단계적 출시, 베타 테스트, 기능 플래그, 서버 설정**으로 위험을 줄인다.
3. 디지털 상품 결제는 **앱 마켓 수수료(15~30%)** 를 꼭 계산에 넣는다.
