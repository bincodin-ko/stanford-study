# 73. 성장 운영 — 피드백·로드맵, 이벤트, 추천인 프로그램, B2B 영업

## 1. 손님 의견 모으기와 기능 요청 관리

### 의견이 들어오는 곳
문의(30장), 리뷰, 해지 사유(51장), SNS 댓글, 사용성 테스트(48장), AI 기능 👎(67장), 검색 기록(66장).

→ **한 곳에 모으세요.** 노션·스프레드시트 하나면 충분해요.

| 날짜 | 누가 | 원문 (그대로) | 분류 | 관련 기능 | 같은 요청 수 |
|---|---|---|---|---|---|
| 11/1 | 단골 A | "정기 배송 날짜를 바꾸고 싶어요" | 기능 요청 | 정기 배송 | 7 |

### 기능 요청을 고르는 법
- **요청 수만 보지 않기**: "누가"(돈을 내는 손님인가, 핵심 손님층인가), **"왜"**(진짜 문제가 뭔가)를 함께 봐요.
- 손님이 말하는 해결책보다 **문제**를 들으세요. "엑셀 내보내기 해 주세요" → 진짜 문제는 "세무사에게 매출 자료를 보내야 해요"일 수 있어요.
- 점수로 비교하는 간단한 방법 (**RICE**):

| 기준 | 질문 |
|---|---|
| **R**each (도달) | 몇 명에게 영향? |
| **I**mpact (효과) | 얼마나 크게? (3 큼 / 2 보통 / 1 작음) |
| **C**onfidence (확신) | 근거가 얼마나 확실? (100% / 80% / 50%) |
| **E**ffort (노력) | 몇 주 걸리나? |

점수 = 도달 × 효과 × 확신 ÷ 노력. 정답 계산기가 아니라 **비교를 위한 도구**예요.

### 로드맵 — 무엇을 언제 할지
```
지금 (이번 달)     다음 (1~3개월)      나중 (아이디어)
- 정기배송 날짜 변경  - 선물 포장 옵션     - 앱
- 결제 오류 수정      - 영어 페이지        - 해외 배송
```
- 날짜를 약속하지 말고 **"지금·다음·나중"**으로 나누면 1인 사업자도 지킬 수 있어요.
- 요청한 손님에게 **"반영했어요"** 연락 → 가장 강한 단골 만들기 방법이에요.
- 공개 로드맵·업데이트 소식(변경 이력, 7장)은 손님 신뢰를 줘요.

## 2. 이벤트·프로모션 운영

| 종류 | 예 | 주의 |
|---|---|---|
| **할인** | 첫 구매 20%, 시즌 세일 | "정가"를 부풀려 할인율을 키우면 허위 표시 (10장) |
| **쿠폰** | 장바구니 쿠폰, 재구매 쿠폰 | 다계정 남용 막기 (41장) |
| **추첨 경품** | 리뷰 쓰면 추첨 | 당첨 기준·발표일·개인정보 이용 공지, **5만 원 넘는 경품은 22% 원천징수** (71장) |
| **선착순** | 100명 한정 | 서버 몰림 대비 (50장 부하 테스트), 재고와 실제 수량 일치 |
| **SNS 이벤트** | 팔로우·공유하면 추첨 | 플랫폼별 이벤트 규정 확인 |
| **리뷰 이벤트** | 리뷰 쓰면 적립금 | **좋은 리뷰에만 보상하면 안 됨**, "적립금 받고 쓴 후기" 표시 (62장) |

### 이벤트 공지에 꼭 넣을 것
```
□ 기간 (시작·끝 날짜와 시각)
□ 참여 방법과 대상 (만 14세 미만 제외 여부 등)
□ 혜택 내용과 수량
□ 당첨자 선정 방법·발표일·발표 방법
□ 개인정보 수집 항목·목적·보관 기간 (10장)
□ 세금 부담 (경품 5만 원 초과 시)
□ 부정 참여 시 취소 기준
```

### 끝나고 볼 것
- 이벤트 기간 매출 **− 할인액 − 경품비 − 광고비** = 정말 남았나? (61장 손익분기)
- **이벤트로 온 손님이 다시 샀나?** (51장 코호트) — 할인 때만 오는 손님만 모았다면 다음엔 방식 변경.

## 3. 추천인(레퍼럴) 프로그램 — 손님이 손님을 데려오게

드롭박스의 "친구 초대하면 둘 다 용량"(33장 사례)이 대표적이에요.

| 설계 | 예 |
|---|---|
| **양쪽 보상** | 초대한 사람 3,000원, 초대받은 사람 첫 구매 3,000원 할인 |
| **보상 조건** | 가입이 아니라 **첫 구매 완료(환불 기간 지난 뒤)** 에 지급 → 어뷰징 방지 |
| **상한** | 한 사람이 받을 수 있는 보상 상한 |
| **공유 쉽게** | 개인 링크·코드, 카카오톡 공유 버튼, 주문 완료 화면에 노출 |
| **추적** | 링크마다 코드 → 누가 데려왔는지 DB에 기록 (59장) |

### 막아야 할 어뷰징 (41장)
- 자기 자신을 초대 (다계정): 같은 기기·결제 수단·주소·전화번호 확인
- 보상만 받고 환불: 환불 기간 지난 뒤 지급
- 추천 코드를 쿠폰 사이트에 뿌리기: 상한, 이상 패턴 감시

> ⚠️ **"초대할수록 계속 돈을 번다"**처럼 하위 단계까지 수당을 주는 구조는 **다단계(방문판매법)** 문제가 될 수 있어요. 한 단계 보상만, 금액은 적당히.

## 4. B2B 영업 — 회사에 파는 법

B2B는 손님이 알아서 찾아오기를 기다리기보다 **먼저 찾아가는** 경우가 많아요(12장).

### 영업 흐름
```
① 이상적인 손님 정하기 → ② 목록 만들기 → ③ 첫 연락 → ④ 상담·데모
→ ⑤ 제안서·견적 → ⑥ 계약 → ⑦ 도입 지원(온보딩) → ⑧ 사례로 만들기
```

### ① 이상적인 손님 (ICP)
"직원 5~30명 미용실 체인, 예약을 전화·카톡으로 받아 노쇼가 많은 곳"처럼 **업종·규모·문제**를 구체적으로.

### ③ 첫 연락 — 콜드메일
```
제목: ○○미용실 노쇼 줄이는 방법 (3분)

원장님 안녕하세요, 미용실 예약 도구를 만드는 ○○입니다.
[왜 이 회사에 연락했나 — 한 줄, 진짜 이유]
비슷한 규모의 △△미용실은 예약 알림을 바꾼 뒤 노쇼가 줄었어요. [진짜 사례·숫자만]
다음 주 15분만 화면으로 보여 드려도 될까요?
관심 없으시면 답장 주시면 다시 연락드리지 않을게요.
```
- **짧게, 상대 이야기로 시작, 요청은 하나(15분 통화).**
- 같은 내용을 수백 곳에 뿌리지 말고 **10곳에 제대로**. 답이 없으면 1~2번만 정중하게 다시.
- 회사 대표 메일·공개된 업무용 연락처로. **개인 연락처를 무단 수집해 광고성 연락**을 하면 법 문제가 될 수 있어요(30장 광고 메시지 규칙, 69장 크롤링).

### ④ 데모(시연)
- 기능 투어가 아니라 **상대의 문제 → 해결 장면 → 숫자** 순서로.
- 먼저 **질문**: "지금 어떻게 하세요? 한 달에 노쇼가 몇 건이에요?" (42장 인터뷰)
- 끝에 **다음 단계**를 정하기: 무료 체험 2주, 견적서 발송 날짜 등.

### ⑤ 제안서·견적서 (B2B는 서류가 중요)
| 넣을 것 | 내용 |
|---|---|
| 상대의 문제 (그들의 말로) | 데모에서 들은 것 |
| 해결 방법과 범위 | 무엇을 하고 **무엇은 안 하는지** |
| 기대 효과 | 숫자 근거와 함께 (과장 금지) |
| 가격·결제 조건 | 월·연 단위, 세금계산서 발행, 결제일 (43장) |
| 일정과 지원 | 도입 기간, 교육, 문의 응답 시간 (12장 SLA) |
| 보안·개인정보 | 데이터 보관 위치, 처리 위탁 계약 (10장) |

- 회사는 **결재**가 필요해요. 담당자가 윗사람에게 그대로 올릴 수 있게 **한 장 요약**을 맨 앞에.

### 공공기관에 팔기 (B2G) — 참고
- 정부·공공기관은 **조달 시스템(나라장터 등)**과 혁신 제품 구매 제도로 사요. 서류·인증·실적 요건이 많아서 초기 1인 사업자보다는 **B2B 실적이 쌓인 뒤** 검토하는 경우가 많아요.
- 지원사업(45장)으로 공공기관과 처음 연결되는 경우도 있어요.

---

### 이 장 요약
1. 손님 의견은 **한 곳에 원문 그대로** 모으고, 해결책보다 **문제**를 보고, **지금·다음·나중** 로드맵으로. 반영하면 요청자에게 알린다.
2. 이벤트는 **공지 7항목·경품 세금·끝난 뒤 손익과 재구매** 확인. 추천인 보상은 **첫 구매 완료 후, 상한, 한 단계만**.
3. B2B는 **이상적인 손님 → 짧은 콜드메일 → 문제 중심 데모 → 결재용 제안서** 순서로.
