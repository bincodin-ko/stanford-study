# 66. 서비스에 자주 들어가는 기능 만들기 — 업로드·검색·알림·예약 작업·관리자 화면

> 구조 설계는 [58장](58-architecture-and-modules.md), 데이터는 [59장](59-database-design.md), 보안은 [37장](37-security-must-dos.md)과 함께 보세요.

어떤 서비스를 만들든 거의 꼭 들어가는 기능 5가지예요. 각 기능마다 **어떻게 만드는지**와 **어디서 사고가 나는지**를 정리했어요.

## 1. 파일·이미지 업로드

### 어디에 저장하나
| 방법 | 설명 |
|---|---|
| ✕ 웹 서버 폴더에 그냥 저장 | 서버를 바꾸거나 늘리면 파일이 사라지거나 흩어짐. 백업도 따로 |
| ○ **파일 저장소(오브젝트 스토리지)** | AWS S3, 클라우드플레어 R2, 수파베이스 Storage 등. 용량 걱정 적고 **CDN**(5장)과 연결하기 쉬움 |

- DB에는 **파일 자체가 아니라 저장 위치(주소)**만 저장해요(59장).
- 큰 파일은 서버를 거치지 않고 **브라우저에서 저장소로 바로** 올리게 하는 방식(미리 서명된 주소)을 많이 써요. 서버 부담이 줄어요.

### 업로드에서 사고가 나는 곳
| 위험 | 막는 법 |
|---|---|
| 이미지인 척한 **악성 파일** (`hack.jpg` 안에 서버 명령 코드) | 파일 이름이 아니라 **내용 앞부분으로 형식 확인**, 허용 형식만 |
| 너무 큰 파일로 저장 용량·요금 폭탄 | **크기 제한** |
| 업로드한 파일이 서버에서 **실행**됨 | 저장소는 실행 안 되는 곳, 파일 이름은 서버가 새로 만들기 |
| 남의 개인 파일을 주소만 알면 열람 | 개인 파일은 **비공개 저장 + 짧은 유효 기간 주소** |
| 사진 속 **위치 정보(EXIF)** 노출 | 업로드 때 메타데이터 제거 |
| 불법·음란 이미지 업로드 | 신고 기능, 필요하면 자동 검사 (16·41장) |

내용 앞부분으로 진짜 형식을 확인하는 예:

```python
MAX_BYTES = 5 * 1024 * 1024                     # 5MB
SIGNATURES = {                                  # 파일 앞부분의 "진짜 형식" 표시
    b"\xff\xd8\xff": "jpg",
    b"\x89PNG\r\n\x1a\n": "png",
    b"RIFF": "webp",                            # (webp는 8~12번째 바이트도 WEBP)
}

def check_image(filename, data):
    if len(data) > MAX_BYTES:
        return False, "5MB보다 커요"
    for sig, kind in SIGNATURES.items():
        if data.startswith(sig) and (kind != "webp" or data[8:12] == b"WEBP"):
            return True, f"{kind} 이미지예요"
    return False, f"{filename}: 이름과 상관없이 이미지 파일이 아니에요"

print(check_image("cat.jpg", b"\xff\xd8\xff\xe0" + b"0" * 100))
print(check_image("cat.png", b"\x89PNG\r\n\x1a\n" + b"0" * 100))
print(check_image("hack.jpg", b"<?php system($_GET['c']); ?>"))
print(check_image("big.jpg", b"\xff\xd8\xff" + b"0" * (6 * 1024 * 1024)))
```

실행 결과 (직접 돌려 확인했어요):
```
(True, 'jpg 이미지예요')
(True, 'png 이미지예요')
(False, 'hack.jpg: 이름과 상관없이 이미지 파일이 아니에요')
(False, '5MB보다 커요')
```
> 실제 서비스에서는 이미지 라이브러리로 **한 번 다시 저장**(재인코딩)까지 하면 더 안전하고, 동시에 크기도 줄일 수 있어요(68장 속도).

## 2. 사이트 안 검색

| 규모 | 방법 |
|---|---|
| 상품·글 수백 개 | DB의 `LIKE '%검색어%'` 로 충분 |
| 수천~수십만 개 | DB의 **전문 검색(Full-Text Search)** 기능 (PostgreSQL, SQLite FTS5 등) |
| 그 이상, 오타 보정·자동완성·필터 | 검색 전용 도구 (Meilisearch, Algolia, Elasticsearch 등) |

### 한국어 검색의 함정 — 조사
영어는 띄어쓰기로 단어가 나뉘지만, 한국어는 **"그래놀라와", "견과류로"**처럼 조사가 붙어요. 기본 검색은 이걸 다른 단어로 봐서 못 찾을 수 있어요. 실험해 봤어요.

```python
import sqlite3
ROWS = [
    ("무설탕 그래놀라", "설탕 없이 귀리와 견과류로 만든 아침 식사"),
    ("초코 그래놀라", "카카오 닙스를 넣은 달콤한 그래놀라"),
    ("그릭 요거트", "그래놀라와 함께 먹기 좋은 진한 요거트"),
]
db = sqlite3.connect(":memory:")
db.execute("CREATE VIRTUAL TABLE basic USING fts5(name, description)")
db.execute("CREATE VIRTUAL TABLE korean USING fts5(name, description, tokenize='trigram')")
db.executemany("INSERT INTO basic VALUES (?, ?)", ROWS)
db.executemany("INSERT INTO korean VALUES (?, ?)", ROWS)

for word in ["그래놀라", "견과류"]:
    for table in ["basic", "korean"]:
        rows = db.execute(f"SELECT name FROM {table} WHERE {table} MATCH ? ORDER BY rank", (word,)).fetchall()
        print(f"{table:6} '{word}' →", [r[0] for r in rows])
```

실행 결과 (SQLite 3.45에서 직접 확인했어요):
```
basic  '그래놀라' → ['초코 그래놀라', '무설탕 그래놀라']
korean '그래놀라' → ['초코 그래놀라', '그릭 요거트', '무설탕 그래놀라']
basic  '견과류' → []
korean '견과류' → ['무설탕 그래놀라']
```
- 기본 방식은 "그래놀라**와**", "견과류**로**"를 못 찾았어요.
- **3글자씩 잘라 찾는 방식(trigram)**은 찾았어요. 단, 이 방식은 **3글자 이상** 검색어만 돼요("설탕"처럼 2글자는 안 잡혀서 `LIKE`를 함께 써야 해요 — 직접 확인).
- 규모가 커지면 **한국어 형태소 분석기**를 지원하는 검색 도구를 고려하세요.

### 검색 기능 체크
- **검색 결과 0건 화면**: "다른 검색어 추천", 인기 상품 (48장 빈 화면 문구)
- **사람들이 무엇을 검색했나 기록** → 없는 상품 아이디어, 63장 키워드 조사에 활용
- 검색어를 그대로 SQL에 붙이지 않기 (**SQL 인젝션**, 37장) — 위 예처럼 `?` 자리 표시 사용

## 3. 알림 — 이메일·문자·카톡·앱 푸시·사이트 안 알림

| 종류 | 좋은 용도 | 주의 |
|---|---|---|
| **이메일** (거래용 메일 서비스) | 가입 확인, 영수증, 비밀번호 재설정 | 도메인 인증 SPF·DKIM·DMARC (30장) |
| **카카오 알림톡** | 주문·배송·예약 안내 | 정보성만, 템플릿 심사 (64장) |
| **문자(SMS)** | 인증번호, 알림톡 실패 시 대신 | 건당 비용, 문자 폭탄 공격 막기 (41장) |
| **앱 푸시** | 앱 사용자에게 즉시 | 광고성 푸시도 동의·야간 규칙 (30장) |
| **사이트 안 알림** (종 모양) | 댓글·답변·상태 변경 | 비용 없음 |

설계 원칙:
- 알림 보내는 코드를 **한 모듈에 모으기** (58장 감싸기). "주문 완료 → 알림 모듈 호출 → 모듈이 메일·카톡 중 무엇을 보낼지 결정".
- **손님이 알림 종류별로 켜고 끌 수** 있게.
- 보낸 기록 저장 (언제·누구에게·무엇을·성공 여부) → 문의 대응에 필요.
- 알림 보내기는 오래 걸리고 실패할 수 있으니 **4절 백그라운드 작업**으로.

## 4. 예약 작업과 백그라운드 작업

### 예약 작업 (정해진 시간에 자동 실행)
| 예 | 시간 |
|---|---|
| 매일 새벽 DB 백업 확인 (8장) | 매일 04:00 |
| 결제 대사 — PG 정산과 내 주문 비교 (39장) | 매일 09:00 |
| 정기 결제 청구 (39장) | 매일 |
| 보관 기간 지난 개인정보 파기 (10장) | 매일 |
| 재구매 알림 대상 찾기 (64장) | 매일 |
| 주간 매출 보고서를 나에게 메일 | 매주 월요일 |

- 리눅스의 **크론(cron)**, 호스팅의 예약 작업 기능(Vercel Cron, 클라우드 스케줄러 등), 깃허브 액션 예약 실행 등으로 해요.
- 크론 시간 표기 예: `0 4 * * *` = 매일 4시 0분. **서버 시간대가 UTC인지 한국 시간인지** 꼭 확인(59장 시간).

### 백그라운드 작업 (요청과 따로 처리)
- 손님이 버튼을 눌렀는데 **오래 걸리는 일**(메일 발송, 영상 변환, AI 처리, 엑셀 만들기)은 기다리게 하지 말고 **줄(큐)에 넣고 바로 응답**해요. 일은 뒤에서 따로 처리(코딩 11장 메시지 큐).
- 작은 서비스는 DB 표 하나를 작업 줄로 써도 충분해요: `jobs(id, type, payload, status, tries, run_at)`.

### 꼭 지킬 것
| 원칙 | 이유 |
|---|---|
| **두 번 실행돼도 괜찮게** (멱등성, 60장) | 서버 재시작·재시도로 같은 작업이 또 돌 수 있어요. 정기 결제가 두 번 청구되면 큰일 |
| **실패하면 재시도 + 횟수 제한** | 일시적 오류는 다시, 계속 실패하면 멈추고 알림 |
| **실패를 알림으로** | 예약 작업은 **조용히 멈추면 아무도 몰라요.** "매일 백업 성공 알림이 안 오면 이상" 같은 감시 (9장) |
| **실행 기록 남기기** | 언제 돌았고 몇 건 처리했나 |

## 5. 관리자 화면 (어드민)

손님 화면만큼 중요해요. **매일 운영하는 곳**이니까요(9장).

### 최소 기능
| 화면 | 할 수 있는 것 |
|---|---|
| **대시보드** | 오늘 주문·매출·가입·문의 수, 이상 신호 |
| **주문 관리** | 검색(주문번호·이름·전화), 상태 변경, 환불 |
| **회원 관리** | 검색, 정지, 문의 이력 |
| **상품·콘텐츠 관리** | 등록·수정·숨김 |
| **문의 관리** | 답변, 템플릿 (30장) |
| **설정** | 배송비·쿠폰·공지 (코드 수정 없이 바꾸게, 58장) |

### 관리자 화면 보안
- **주소를 숨기는 것만으로는 부족**: 강한 비밀번호 + **2단계 인증** 필수, 가능하면 접속 IP 제한
- **역할별 권한** (65장): 상담 직원은 환불 승인 ✕, 회원 전체 다운로드 ✕
- **누가 무엇을 했는지 기록(감사 로그)**: "11/1 14:02 김직원, 주문 #42 환불" → 실수·내부 유출 확인, 개인정보 접속 기록 보관 의무(37장)
- **엑셀 다운로드**는 최소한으로, 다운로드도 기록 (37장: 흔한 유출 경로)
- 위험한 동작(대량 삭제, 전체 메일 발송)은 **한 번 더 확인** 화면

> 💡 직접 만들기 부담스러우면: 빌더의 관리자 화면, 수파베이스 대시보드, 또는 관리자 화면 생성 도구(Retool·Appsmith 같은 내부 도구 빌더, 장고 어드민 등)를 쓸 수 있어요.

---

### 이 장 요약
1. 업로드는 **파일 저장소 + 내용으로 형식 확인 + 크기 제한 + 개인 파일 비공개**.
2. 한국어 검색은 **조사 때문에 기본 방식이 놓칠 수 있다** — trigram·형태소 지원 도구 고려. 알림은 **한 모듈로 모으고 손님이 끌 수 있게**.
3. 예약·백그라운드 작업은 **두 번 실행돼도 안전하게, 실패는 알림으로**. 관리자 화면은 **2단계 인증·역할 권한·감사 로그**.
