# 04. 기획과 설계 — 아이디어에서 출시까지

사이트를 만드는 일은 **집 짓기**와 같아요.
설계도 없이 벽돌부터 쌓으면 나중에 부수고 다시 지어야 합니다.

---

## 전체 흐름 한눈에

```
① 문제 확인 → ② 손님 정의 → ③ 기능 목록 → ④ 화면 설계 → ⑤ 디자인
  → ⑥ 개발 → ⑦ 테스트 → ⑧ 출시(런칭) → ⑨ 측정하고 고치기 → (다시 ③으로)
```

⑨에서 ③으로 돌아가는 **"반복"** 이 핵심입니다. 인터넷 사업은 한 번 만들고 끝이 아니에요.

---

## ① 문제 확인 — "누가 무엇 때문에 불편한가"

- 내가 팔고 싶은 것보다 **손님이 돈 내고 해결하고 싶은 불편**을 먼저 찾습니다.
- 확인 방법: 예상 손님 5~10명과 직접 이야기하기, 경쟁 사이트 리뷰(특히 불만 리뷰) 읽기, 검색량 확인(네이버 데이터랩, 구글 트렌드).

## ② 손님 정의 — 페르소나

> 예) "33세 맞벌이 직장인, 퇴근 후 아이 간식을 고민함. 성분표를 꼼꼼히 봄. 인스타그램을 많이 씀."

이렇게 정해 두면 디자인·문구·광고 채널을 고를 때 기준이 생겨요.

## ③ 기능 목록 — 꼭 필요한 것만 (MVP)

기능을 전부 적은 뒤 **MoSCoW 방법**으로 나눕니다.

| 구분 | 뜻 | 쇼핑몰 예 |
|---|---|---|
| **Must** | 없으면 장사가 안 됨 | 상품 보기, 장바구니, 결제, 주문 확인 |
| **Should** | 있으면 많이 좋음 | 회원 적립금, 리뷰 |
| **Could** | 여유 있으면 | 위시리스트, 추천 상품 |
| **Won't (이번엔 안 함)** | 나중에 | 앱, 정기 배송 |

**첫 출시는 Must만.** 나머지는 손님 반응을 보고 추가합니다.

## ④ 화면 설계 — 정보 구조(IA)와 와이어프레임

- **IA(정보 구조)** = 사이트 메뉴의 지도.
  ```
  홈
  ├─ 전체 상품
  │   ├─ 쿠키
  │   └─ 그래놀라
  ├─ 브랜드 이야기
  ├─ 고객센터 (FAQ, 1:1 문의)
  └─ 마이페이지 (주문 내역, 배송 조회)
  ```
- **와이어프레임** = 색 없이 네모 상자로만 그린 화면 뼈대. 종이에 그려도 됩니다.
- **사용자 흐름(User flow)** = 손님이 "들어와서 → 결제 완료"까지 몇 번 클릭하는지. **클릭이 적을수록 잘 팔립니다.**

## ⑤ 디자인

- **모바일 먼저(모바일 퍼스트)**: 쇼핑 방문의 대부분이 휴대폰에서 일어나므로 휴대폰 화면부터 설계.
- **디자인 시스템**: 색·글꼴·버튼 모양을 미리 정해 두면, 페이지가 늘어나도 통일감이 유지되고 수정이 쉬워요.
- 도구 예: Figma(피그마).

## ⑥ 개발 — 만드는 방법 3가지

| 방법 | 설명 | 추천 대상 |
|---|---|---|
| **쇼핑몰/사이트 빌더** | 카페24, 아임웹, 쇼피파이, 윅스 등. 템플릿을 고르고 조립 | 처음 시작하는 1인 사업자 (가장 추천) |
| **CMS + 플러그인** | 워드프레스 + 우커머스 등 | 블로그·콘텐츠 중심, 조금 더 자유롭게 |
| **직접 개발** | 코드를 짜서 만듦 | 남들과 다른 기능이 꼭 필요한 SaaS·플랫폼 |

> 빌더를 쓰면 **서버, 보안 패치, 백업 일부를 업체가 대신** 해 줍니다. 대신 자유도가 낮고 매달 이용료가 들어요.
> 직접 개발하면 **6~9장의 일(배포, 백업, 모니터링)을 전부 내가** 해야 합니다.

## ⑦ 테스트

출시 전에 **"손님처럼"** 끝까지 해 봅니다.
- 휴대폰(아이폰·안드로이드)과 PC에서 각각 회원가입 → 구매 → 취소까지
- 실제 카드로 소액 결제 후 환불
- 이메일·문자 알림이 제대로 오는지
- [출시 전 체크리스트](14-checklists.md#1-출시-전-체크리스트)

## ⑧ 출시 — 조용히 먼저, 크게 나중에

- **소프트 런칭**: 지인·소수에게 먼저 공개해 문제를 찾음
- **정식 런칭**: 광고·이벤트와 함께 크게 알림

## ⑨ 측정하고 고치기

출시 후에는 [11장](11-growth-and-data.md)의 숫자를 보며 ③으로 돌아가 개선합니다.

---

## 문서로 남겨야 할 것 (작은 사업이라도)

| 문서 | 내용 | 왜 필요? |
|---|---|---|
| **기획서(PRD)** | 목표, 손님, 기능 목록, 우선순위 | 만들다 길을 잃지 않게 |
| **화면 설계서** | 와이어프레임 + 설명 | 디자이너·개발자와 오해 방지 |
| **운영 매뉴얼** | 주문 처리, 환불, 문의 답변 방법 | 내가 아파도 누군가 대신 할 수 있게 |
| **계정·서비스 목록** | 도메인, 호스팅, PG, 메일 등 어디에 가입했는지 | 갱신을 놓쳐 사이트가 꺼지는 사고 방지 |

> **PRD** = Product Requirements Document, 제품 요구사항 문서.

---

### 이 장 요약
1. 문제 → 손님 → 기능 → 화면 → 디자인 → 개발 → 테스트 → 출시 → 측정, 그리고 반복.
2. 첫 출시는 **Must 기능만** (MVP).
3. 처음이면 **빌더**로 시작하는 게 운영 부담이 가장 적다.
