# 42. 아이디어 검증·시장조사 — 만들기 전에 확인하기

1인 창업에서 가장 흔한 실패는 **"아무도 원하지 않는 걸 열심히 만드는 것"** 이에요.
이 장은 코드를 한 줄 쓰기 전에 **"정말 돈 낼 사람이 있나?"** 를 싸고 빠르게 확인하는 방법이에요. (4장 기획, 33장 사례와 이어져요)

> ⚠️ 2026년 11월 조사 기준. ([참고 자료 모음](sources.md))

---

## 1. 검증의 순서

```
① 문제 확인     "이 불편이 진짜 있나? 얼마나 아픈가?"
② 손님 확인     "누가, 몇 명이나, 어디에 있나?"
③ 해결책 확인   "내 방법을 원하나?"
④ 지불 확인     "돈을 낼까?"  ← 가장 중요, 가장 많이 건너뜀
⑤ 경로 확인     "그 사람들에게 닿을 수 있나?" (32장 채널)
```

> 💡 **"좋네요!"는 검증이 아니에요.** 사람들은 예의상 칭찬해요. 검증은 **행동**(이메일 남기기, 사전 결제, 시간 쓰기)으로 해요.

---

## 2. 손님 인터뷰 — 질문하는 법

### 좋은 질문 vs 나쁜 질문
| ❌ 나쁜 질문 (미래·가정·칭찬 유도) | ✅ 좋은 질문 (과거·실제 행동) |
|---|---|
| "이런 앱 있으면 쓰실 거예요?" | "지난번에 이 문제가 생겼을 때 어떻게 하셨어요?" |
| "월 1만 원이면 사실래요?" | "이 문제 해결하려고 돈이나 시간을 써 본 적 있으세요? 얼마나요?" |
| "제 아이디어 어때요?" | "그 과정에서 제일 짜증 났던 게 뭐예요?" |
| "이 기능 필요하세요?" | "지금은 어떤 도구를 쓰세요? 뭐가 아쉬워요?" |

- **내 아이디어 설명은 최대한 늦게.** 먼저 상대의 실제 경험을 들어요.
- 이런 원칙을 정리한 책으로 『The Mom Test』(롭 피츠패트릭)가 유명해요. 핵심은 "엄마조차 거짓말할 수 없게, **상대의 과거 행동**을 물어라"예요.

### 인터뷰 진행
- **5~10명**이면 패턴이 보이기 시작해요. 같은 불만이 3번 이상 나오면 진짜일 가능성이 높아요.
- 녹음(동의 받고) 또는 바로 메모 → 문장 그대로 적기 (내 해석 말고)
- 마지막 질문: **"이 얘기 나눌 만한 다른 분 소개해 주실 수 있어요?"**

## 3. 책상에서 하는 시장조사

| 무엇을 | 도구·방법 |
|---|---|
| **검색 수요** | 네이버 데이터랩·검색광고 키워드 도구, 구글 트렌드 — 사람들이 이 문제를 검색하나? |
| **경쟁 서비스** | 같은 문제를 푸는 곳 5개 이상 찾기 → 가격, 기능, 손님 수(대략), **리뷰의 불만** |
| **불만 수집** | 앱스토어·쇼핑몰 1~2점 리뷰, 커뮤니티 글 — "이게 안 돼서 불편" = 기회 |
| **시장 크기** | TAM·SAM·SOM (3장) — 큰 숫자보다 **"내가 1년 안에 닿을 수 있는 손님 수"** 가 현실적 |
| **공공 통계** | 통계청(KOSIS), 업종별 협회 자료 |

> 💡 **경쟁자가 있다 = 나쁜 신호가 아니에요.** 시장이 있다는 뜻일 수 있어요. 진짜 나쁜 신호는 "경쟁자도 없고 검색하는 사람도 없음"이에요.

---

## 4. 만들기 전에 팔아 보기 — 행동 테스트

| 테스트 | 방법 | 확인하는 것 |
|---|---|---|
| **랜딩 페이지 테스트** | 서비스 소개 한 페이지 + "출시 알림 받기"(이메일) → 소액 광고로 방문자 보내기 | 방문자 중 몇 %가 이메일을 남기나 |
| **사전 판매·예약** | "얼리버드 할인, 출시 시 결제" 또는 실제 선결제(환불 보장) | **돈을 내나** — 가장 강한 신호 |
| **가짜 문 테스트** | "프리미엄 기능" 버튼을 만들고 누르면 "준비 중입니다" 안내 | 그 기능을 원하는 사람 비율 (속였다는 느낌 안 들게 정직하게 안내) |
| **수작업 서비스(컨시어지)** | 자동화 전에 **사람이 직접** 서비스 제공 (예: 엑셀·카톡으로 주문 받기) | 사람들이 계속 쓰나, 무엇이 핵심인가 |
| **크라우드펀딩** | 와디즈 등 (23장) | 수요 + 초기 자금 |
| **커뮤니티 반응** | 관련 커뮤니티에 문제 정리 글 (홍보 금지 규칙 지키기) | 공감 댓글·DM 수 |

> 33장의 배달의민족(전단지 직접 입력), 글로시에(블로그로 먼저 팬 모으기)가 모두 **"만들기 전에 확인"** 의 실제 사례예요.

### 판단 기준 (예시 — 업종마다 다름)
| 신호 | 해석 |
|---|---|
| 랜딩 페이지 이메일 등록률이 아주 낮음 | 문제가 약하거나, 메시지가 안 통하거나, 손님이 아님 → 메시지·대상 바꿔 재시험 |
| 사전 결제한 사람이 있음 | 강한 신호 → 최소 버전(MVP) 만들기 |
| 인터뷰에서 "지금 엑셀로 억지로 하고 있다" | 대체할 가치가 있음 |

## 5. 출시 후: 제품-시장 적합성(PMF) 확인

**션 엘리스 테스트(40% 규칙)**: 실제로 써 본 사용자에게 묻기
> "이 서비스를 더 이상 쓸 수 없게 되면 어떤 기분일까요?"
> ① 매우 실망 ② 약간 실망 ③ 실망하지 않음

- **"매우 실망"이 40% 이상**이면 제품-시장 적합성(PMF, 3장)에 가까운 신호라고 알려져 있어요. 창안자가 약 100개 스타트업을 보고 만든 기준이라고 해요.
- 한 번 써 본 사람보다 **반복해서 쓰는 사람**에게 묻는 게 좋다는 조언이 있어요.
- 40% 미만이면: "매우 실망"이라고 답한 사람들의 공통점을 찾아 **그들에게 집중**하기.

---

## 6. 검증 체크리스트

- [ ] 문제를 한 문장으로: "○○한 사람은 ○○ 때문에 불편하다"
- [ ] 예상 손님 5~10명 인터뷰 (과거 행동 질문)
- [ ] 경쟁 서비스 5곳 + 그 리뷰 속 불만 정리
- [ ] 검색량 확인
- [ ] 랜딩 페이지 + 이메일 수집 또는 사전 판매 테스트
- [ ] "돈을 낸 사람" 또는 "명확한 행동을 한 사람"이 있다 → 만들기 시작
- [ ] 출시 후 40% 테스트로 재확인

---

### 이 장 요약
1. 검증 순서: **문제 → 손님 → 해결책 → 지불 → 경로**. 칭찬은 검증이 아니고 **행동**이 검증이다.
2. 인터뷰는 **과거 행동**을 묻고, 내 아이디어 설명은 최대한 늦게.
3. **랜딩 페이지·사전 판매·수작업 서비스**로 만들기 전에 팔아 보고, 출시 후엔 **40% 테스트**로 확인.
