# 75. 설치형 프로그램 배포 — 코드 서명과 "바이러스 경고" 없애기

> 모바일 앱 배포는 [25장](25-mobile-apps.md), 보안 기본은 [37장](37-security-must-dos.md)에 있어요. 이 장은 **PC에 설치하는 프로그램(.exe, .msi, 맥 .app/.dmg)**을 직접 나눠 줄 때 이야기예요.

> ⚠️ 운영체제 회사의 정책과 인증서 가격은 자주 바뀌어요. 2026년 11월 조사 기준이고, 마이크로소프트·애플 공식 문서를 꼭 확인하세요. ([참고 자료 모음](sources.md))

---

## 1. 어떤 경고가 뜨나

내가 만든 프로그램을 손님이 내려받아 실행하면 이런 화면이 뜰 수 있어요.

| 어디서 | 경고 | 손님 반응 |
|---|---|---|
| **윈도우** (Microsoft Defender SmartScreen) | "Windows의 PC 보호" — 알 수 없는 게시자 | 대부분 여기서 **취소**해요 |
| **브라우저 다운로드** (엣지·크롬) | "일반적으로 다운로드되지 않는 파일" | 다운로드부터 포기 |
| **백신 프로그램** (V3, 알약, 디펜더 등) | 악성 코드로 **잘못 판단**(오탐)해 삭제 | "바이러스 있는 프로그램"이라는 후기 |
| **맥** (Gatekeeper) | "확인되지 않은 개발자", 실행 차단 | 설정에 들어가 "그래도 열기"를 눌러야 함 |

→ 프로그램이 아무리 좋아도 **첫 실행 화면에서 손님을 잃어요.** 그래서 정식으로 배포하려면 아래 준비가 필요해요.

---

## 2. 코드 서명이란 — 프로그램에 찍는 "디지털 도장"

**코드 서명** = 인증기관(CA)에서 신원 확인을 받은 인증서로 프로그램 파일에 서명하는 것이에요. 두 가지를 증명해요.

1. **누가 만들었나** — 경고 창에 "알 수 없는 게시자" 대신 **내 이름이나 회사 이름**이 나와요.
2. **중간에 바뀌지 않았나** — 누가 파일에 악성 코드를 끼워 넣으면 서명이 깨져요.

### 꼭 알아야 할 오해
> ❌ "서명만 하면 경고가 바로 사라진다"

- 윈도우 SmartScreen은 **평판**(얼마나 많은 사람이 문제없이 내려받았나)을 봐요. **새 인증서나 새 프로그램은 처음에 경고가 뜰 수 있고**, 다운로드가 쌓이면서 줄어들어요.
- 예전에는 비싼 **EV 인증서**를 쓰면 처음부터 평판이 있었지만, 마이크로소프트 공식 문서 기준으로 **이 혜택은 이제 없어요**(2024년 무렵 변경). 지금은 OV와 EV가 SmartScreen 평판 면에서 같다고 안내돼요.
- 그래도 서명은 **필수 출발점**이에요. 서명이 없으면 평판이 쌓이기 어렵고, 업데이트할 때마다 "처음 보는 프로그램"이 돼요.

## 3. 윈도우 — 서명하는 방법 고르기

| 방법 | 비용 (조사 기준) | 누가 받을 수 있나 | 특징 |
|---|---|---|---|
| **OV 코드 서명 인증서** | 연 수십~수백 달러 (판매처마다 큰 차이) | 사업자 (회사·개인사업자) | 가장 일반적. 회사 이름이 표시됨 |
| **IV (개인 인증) 인증서** | OV와 비슷 | **개인** 개발자 | 사업자등록 없이도 가능한 상품이 있음. 내 실명이 표시됨 |
| **EV 인증서** | 연 수백 달러 이상 | 사업자 (검증이 더 엄격) | 즉시 평판 혜택은 없어짐. 드라이버 서명 등 특수한 경우에 필요 |
| **Azure Artifact Signing** (옛 이름 Trusted Signing, 마이크로소프트 클라우드 서명) | 월 약 10달러부터 | 커뮤니티 답변 기준 **개인은 미국·캐나다만**, 법인은 미국·캐나다·EU·영국 | 싸고 자동화가 쉬움. **한국 개인 개발자는 현재 쓰기 어려울 가능성이 큼** (공식 확인 필요) |
| **마이크로소프트 스토어로 배포** | 개발자 계정 비용 | 개인·회사 | 스토어가 서명·배포를 맡아 SmartScreen 문제를 피하기 쉬움. 대신 심사 |

### 2023년 6월부터 바뀐 규칙
- 인증기관 업계 규칙(CA/B 포럼)에 따라, 코드 서명 인증서의 **비밀 키는 반드시 보안 하드웨어**(USB 토큰이나 HSM)에 보관해야 해요. 예전처럼 파일(.pfx)로 받아 PC에 두는 방식은 안 돼요.
- 그래서 실제로는 **① USB 토큰을 배송받아 꽂고 서명**하거나, **② 인증기관의 클라우드 서명 서비스**를 써요. 자동 빌드(CI)로 서명하려면 ②가 편해요.

### 서명할 때 같이 할 것
- **타임스탬프 붙이기**: 서명 시점을 기록해 두면 **인증서가 만료돼도 기존 파일의 서명이 계속 유효**해요. 꼭 켜세요.
- **설치 파일과 실행 파일 모두** 서명 (설치 프로그램 .exe/.msi와 설치된 .exe·.dll).
- **게시자 이름을 계속 같게** 유지 — 평판은 게시자 신원에 쌓여요.
- 인증서 **만료일을 계정 목록에** (9·34장처럼 갱신 놓치면 사고).

## 4. 백신이 내 프로그램을 바이러스로 잡을 때 (오탐)

- 처음 보는 프로그램, 압축·난독화된 프로그램, 자동 업데이트·키보드 입력·화면 캡처 기능이 있는 프로그램은 **오탐이 잘 나요.**
- 대응:
  1. **코드 서명**부터 (서명된 파일은 오탐이 줄어드는 경우가 많아요)
  2. 백신 회사의 **오탐 신고 창구**에 파일 제출 — 마이크로소프트(디펜더)는 보안 인텔리전스 사이트에 파일 제출 기능이 있고, 국내 백신 회사들도 오탐 신고 메뉴를 운영해요
  3. 여러 백신으로 미리 검사해 보기 (VirusTotal 같은 서비스 — 올린 파일이 백신 회사들과 공유될 수 있으니 비공개 프로그램은 주의)
  4. 불필요한 실행 파일 압축(패킹)·난독화 줄이기
- 손님 안내 페이지에 **"오탐이 나면 이렇게 해 주세요 + 신고 진행 중"**을 솔직하게 적으면 신뢰를 지킬 수 있어요.

## 5. 맥(macOS) — 서명 + 공증

| 단계 | 내용 |
|---|---|
| **① 애플 개발자 프로그램 가입** | 연회비가 있어요 (금액은 애플 공식 페이지 확인). 개인·회사 모두 가능 |
| **② Developer ID 인증서로 서명** | 앱스토어 밖에서 나눠 줄 앱용 인증서 |
| **③ 공증(Notarization)** | 애플 서버에 앱을 올려 **자동 악성 코드 검사**를 받고 "공증 티켓"을 받음 |
| **④ 티켓 붙이기(staple)** | 인터넷이 없어도 확인되게 앱에 티켓을 붙임 |

- 애플 공식 문서 기준, **macOS 10.15부터 Developer ID로 배포하는 앱은 공증이 필수**예요. 없으면 Gatekeeper가 막아요.
- 대안: **맥 앱스토어**로 배포하면 애플 심사로 대신해요(수수료·심사 있음).
- 2026년 개발자 포럼에는 공증한 **.pkg 설치 파일**이 막혔다는 개별 사례도 올라와 있어요. 배포 전 **새 맥에서 직접 내려받아 테스트**하세요(50장).

## 6. 1인 개발자에게 추천하는 순서

```
1. 정말 설치형이어야 하나?  →  웹으로 되면 웹 (설치·서명·경고 문제 자체가 없음)
2. 설치형이 꼭 필요하면    →  앱스토어(마이크로소프트 스토어·맥 앱스토어) 배포를 먼저 검토
3. 직접 나눠 줘야 하면     →  윈도우: OV/IV 인증서(클라우드 서명), 맥: Developer ID + 공증
4. 출시 직후              →  다운로드 페이지에 "처음엔 경고가 뜰 수 있어요" 안내 + 오탐 신고
```

> 💡 웹 서비스도 **PWA**(25장)로 만들면 바탕화면 아이콘·앱처럼 쓰기를 설치 경고 없이 제공할 수 있어요. 일렉트론(Electron) 같은 도구로 웹을 데스크톱 앱으로 감싸는 경우에도 서명은 똑같이 필요해요.

## 7. 배포 체크리스트

```
□ 설치 파일·실행 파일 모두 코드 서명 + 타임스탬프
□ 게시자 이름이 내 사업자 이름과 같은가
□ 다운로드는 https 내 도메인에서만 (34·37장), 파일 해시(SHA-256) 공개
□ 자동 업데이트 파일도 서명 확인 후 설치되게 (업데이트 서버가 해킹되면 모든 손님 PC가 위험)
□ 새 PC·새 맥에서 직접 내려받아 경고 화면 확인 (50장)
□ 여러 백신으로 검사, 오탐이면 신고
□ 설치 안내 페이지: 경고 화면 캡처와 설명, 문의 창구 (30장)
□ 인증서·개발자 계정 만료일을 계정 목록에 (9장)
□ 개인정보를 수집하면 처리방침, 설치 시 동의 (10장)
□ 제거(언인스톨)가 깨끗하게 되는가 — 안 되면 "악성 프로그램" 후기가 달려요
```

> 💡 Claude에게: "이 일렉트론 앱을 윈도우·맥용으로 배포하려고 해. 코드 서명(윈도우는 클라우드 서명 인증서, 맥은 Developer ID + 공증)을 빌드 과정에 넣는 설정을 만들어 주고, 비밀 키·인증서 정보는 깃허브 비밀 설정(Secrets)으로만 쓰게 해 줘."

---

### 이 장 요약
1. 설치형 프로그램은 **코드 서명**이 출발점: 누가 만들었는지 + 바뀌지 않았음을 증명. 윈도우는 서명 후에도 **평판이 쌓일 때까지 경고**가 뜰 수 있고, **EV의 즉시 평판 혜택은 없어졌다**.
2. 2023년부터 서명 키는 **USB 토큰이나 클라우드 HSM**에만. **타임스탬프**를 꼭 붙이고, 백신 오탐은 **신고 창구**로.
3. 맥은 **Developer ID 서명 + 공증**이 필수. 1인 개발자는 **웹 → 앱스토어 → 직접 배포+서명** 순서로 검토.
