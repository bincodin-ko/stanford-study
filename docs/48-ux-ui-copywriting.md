# 48. UX·UI 디자인과 문구 쓰기

- **UI(사용자 인터페이스)** = 눈에 보이는 화면: 버튼, 색, 글꼴, 배치
- **UX(사용자 경험)** = 쓰면서 느끼는 전체 경험: 쉽게 찾나, 헷갈리지 않나, 기분 좋나
- **카피(문구)** = 화면 속 글: 제목, 버튼 글자, 안내, 오류 메시지

예쁜 화면보다 **헷갈리지 않는 화면**이 더 잘 팔려요. 이 장은 디자이너가 아니어도 지킬 수 있는 원칙이에요. (38장 출시 전 체크와 이어져요)

## 1. 쓰기 쉬운 화면의 원칙 10가지

| # | 원칙 | 예 |
|---|---|---|
| 1 | **한 화면에 주인공 하나** | 강조 버튼은 1개 (38장 첫 화면 CTA) |
| 2 | **익숙한 걸 따르기** | 로고는 왼쪽 위, 장바구니는 오른쪽 위 — 사람들은 다른 사이트에서 배운 대로 찾아요 |
| 3 | **지금 상태를 보여 주기** | 로딩 중, 저장됨, 결제 진행 단계(1/3) |
| 4 | **실수를 막고, 되돌릴 수 있게** | 삭제 전 확인, "실행 취소" |
| 5 | **외우게 하지 말고 보이게** | 이전 단계에서 입력한 내용을 다시 보여 주기 |
| 6 | **단계는 짧게** | 회원가입·결제 칸 수 줄이기 (11장 퍼널) |
| 7 | **일관성** | 같은 기능은 같은 색·같은 위치·같은 단어 |
| 8 | **여백** | 빽빽하면 아무것도 안 보임 |
| 9 | **모바일 먼저, 엄지손가락 크기** | 버튼은 손가락으로 누르기 충분한 크기 |
| 10 | **오류는 친절하게** | "오류 발생" ✕ → "전화번호는 숫자만 입력해 주세요" ○ |

## 2. 화면 만드는 순서 (4장 복습 + 도구)

```
1. 사용자 흐름: 들어와서 → 목표(구매·가입)까지 몇 단계?
2. 와이어프레임: 종이·피그마로 네모 상자만
3. 디자인 시스템: 색 2~3개, 글꼴 1~2개, 버튼 모양 정하기
4. 시안 → 실제 화면 (AI에게 "이 와이어프레임대로 만들어 줘" 가능)
5. 사용성 테스트 (4절) → 고치기
```

### 피그마(Figma) 기초
- 웹에서 쓰는 디자인 도구. **프레임**(화면), **컴포넌트**(재사용 버튼), **오토 레이아웃**(자동 정렬), **프로토타입**(눌러 보는 시안)
- 무료로 시작 가능. 커뮤니티에 무료 템플릿·UI 키트가 많아요 (라이선스 확인, 47장)

### 색·글꼴 간단 규칙
- 색: **주 색 1 + 보조 색 1 + 강조 색 1**, 나머지는 흰색·회색
- 글자 대비: 본문 글자와 배경의 명도 대비를 충분히 (38장 접근성)
- 글꼴: 본문은 읽기 쉬운 고딕 계열 1개 + 제목용 1개 정도 (상업 사용 가능한 폰트, 47장)

## 3. 문구(카피) 쓰는 법

### 첫 화면 제목 공식
> **[누구]가 [무엇]을 [얼마나 쉽게/빠르게] 하게 해 준다**
> 예: "아침 거르는 직장인을 위한 3분 그래놀라"
> 예: "엑셀 없이 1분 만에 끝내는 가게 매출 정리"

### 버튼 문구
| ❌ | ✅ |
|---|---|
| 확인 | 무료로 시작하기 |
| 제출 | 상담 신청하기 |
| 클릭 | 10% 할인 받고 구매하기 |
- **누르면 무슨 일이 생기는지**를 동사로.

### 혜택을 말하기 (기능이 아니라)
| 기능 (만든 사람의 말) | 혜택 (손님의 말) |
|---|---|
| "AI 자동 분류 기능 탑재" | "영수증을 찍기만 하면 장부가 정리돼요" |
| "무설탕 원료 사용" | "당 걱정 없이 매일 아침" |

### 손님의 말을 그대로
- 인터뷰(42장)·리뷰·문의(30장)에 나온 **손님의 표현**을 문구에 쓰면 공감이 커요.

### 오류·빈 화면·안내 문구
- 오류: **무엇이 잘못됐고 어떻게 고치는지**
- 빈 화면: "아직 주문이 없어요. 첫 상품 둘러보기 →"
- 말투: 서비스 전체에서 **존댓말 수준·말투 통일**

> ⚠️ 과장 표현("국내 최초", "100% 효과")은 근거가 없으면 **표시광고법** 문제 (10·23장).

## 4. 사용성 테스트 — 5명이면 시작할 수 있다

닐슨 노먼 그룹은 **비슷한 사용자 5명**으로 테스트하면 사용성 문제의 **약 85%** 를 찾을 수 있다고 설명해요. 그래서 15명 예산이 있다면 **5명씩 3번**(테스트 → 고치기 → 다시 테스트) 하라고 권해요. (사용자 유형이 여러 개면 유형별로 더 필요해요. "5명이면 충분하다"는 데 반론도 있어요.)

### 하는 법
```
1. 과제 3~5개 준비: "이 사이트에서 3만 원 이하 선물을 찾아 장바구니에 담아 보세요"
2. 화면을 보며 생각을 소리 내어 말하게 함 ("지금 뭘 찾고 계세요?")
3. 나는 도와주지 않고 관찰만 — 막히는 곳, 헤매는 곳 기록
4. 끝나고 "가장 헷갈린 곳은?"
5. 공통으로 막힌 곳부터 고치기
```
- 친구·가족도 괜찮지만 **목표 손님과 비슷한 사람**이 더 좋아요.
- 원격(화면 공유)으로도 가능.

## 5. 다크 패턴 — 하지 말아야 할 디자인

**다크 패턴** = 손님을 속이거나 원치 않는 행동을 하게 만드는 디자인.

| 다크 패턴 | 예 |
|---|---|
| 숨은 비용 | 결제 마지막에 갑자기 수수료 추가 |
| 해지 미로 | 가입은 1클릭, 해지는 전화로만 |
| 몰래 체크 | 마케팅 수신 동의가 기본 체크 (30장) |
| 가짜 긴급함 | 매일 "오늘만 할인", 가짜 "남은 재고 1개" |
| 거절 망신 주기 | "아니요, 저는 할인을 싫어해요" 같은 거절 버튼 |

→ 신뢰를 잃고, 전자상거래법·표시광고법·개인정보 규칙에 걸릴 수 있어요. 정부도 온라인 다크 패턴 규제를 강화하는 추세예요.

## 6. AI(Claude)와 함께 디자인·문구 작업하기

| 요청 예 |
|---|
| "이 페이지를 처음 온 사람 입장에서 헷갈리는 곳 5가지를 찾아 줘" |
| "첫 화면 제목 후보 10개를 '누가·무엇을·얼마나 쉽게' 공식으로 써 줘. 과장 표현 없이" |
| "버튼 문구를 누르면 무슨 일이 생기는지 보이게 바꿔 줘" |
| "오류 메시지를 '무엇이 잘못됐고 어떻게 고치는지' 형식으로 다시 써 줘" |
| "이 화면에 다크 패턴이 있는지 점검해 줘" |

---

### 이 장 요약
1. 예쁜 것보다 **헷갈리지 않는 것**: 주인공 하나, 익숙한 배치, 상태 보여 주기, 짧은 단계, 친절한 오류.
2. 문구는 **누구·무엇·얼마나 쉽게**, 버튼은 **동사로**, 기능이 아니라 **혜택**을 손님의 말로.
3. **5명 사용성 테스트**를 반복하고, **다크 패턴은 쓰지 않는다**.
