# 85. 프록시·동적 딜레이·브라우저 자동화 — 바르게 쓰는 법과 내 서비스에서 막는 법

> 크롤링의 법적 쟁점(야놀자·여기어때 판례)은 [69장](69-automation-and-data-collection.md), 어뷰징·봇 막기는 [41장](41-abuse-and-cheat-prevention.md), 테스트 자동화는 [50장](50-testing-in-practice.md), 재시도·백오프는 [81장](81-optimization-and-stabilization.md), 보안 전체 지도는 [83장](83-security-map-all-layers.md)에 있어요.

> 이 장의 바탕이 되는 인터넷 지식(IP·NAT·HTTPS·프록시 터널·X-Forwarded-For·쿠키·캐시·브라우저 렌더링)은 [86장](86-internet-fundamentals.md)에 있어요.

프록시, 동적 딜레이, 브라우저 시뮬레이션(자동화)은 **같은 기술이 정반대로 쓰여요.**

| 기술 | ✅ 바르게 쓰는 예 | ❌ 문제가 되는 예 |
|---|---|---|
| **프록시** | 회사 보안 게이트웨이, 내 서비스 앞단(리버스 프록시), 다른 나라에서 내 사이트가 어떻게 보이는지 확인 | 차단당하자 IP를 계속 바꿔 가며 남의 사이트를 긁기 |
| **동적 딜레이** | 상대 서버가 힘들어하면 **스스로 느려지는** 예의 바른 수집, API 재시도 | "차단 안 당할 만큼만" 속도를 맞춰 남의 데이터를 몰래 대량 수집 |
| **브라우저 자동화** | **내 서비스 테스트**(손님처럼 클릭), 모니터링, 화면 캡처, 허가받은 업무 자동화 | 사람인 척 위장해 봇 차단·캡차를 피하기, 가짜 가입·리뷰·예매 |

이 장은 **왼쪽(바르게 쓰는 법)**과, 내 서비스를 운영하는 입장에서 **오른쪽을 막는 법**을 다뤄요. 차단을 **우회하는 기법**은 다루지 않아요(이유는 5절).

> ⚠️ 법 해석은 기사·판례 해설 기준이에요. 남의 사이트 데이터를 수집하는 사업이라면 **시작 전에 변호사 상담**을 받으세요(69장). ([참고 자료 모음](sources.md))

## 1. 프록시 — "대신 전달해 주는 중간 서버"

| 종류 | 누구 편 | 하는 일 | 예 |
|---|---|---|---|
| **포워드 프록시** | 요청하는 쪽(나·회사) | 내 요청을 대신 밖으로 보냄. 접속 기록·필터·캐시 | 회사 인터넷 게이트웨이, **이 교재를 만든 작업 환경도** 허용된 주소로만 나가도록 프록시를 거쳐요 |
| **리버스 프록시** | 서비스 쪽(나의 서버) | 손님 요청을 먼저 받아 내 서버로 전달. **HTTPS 처리·캐시·방화벽·요청 제한** | Nginx, Caddy, **클라우드플레어**(36·68장) |
| **VPN** | 사용자 | 기기 전체 통신을 암호화된 길로 | 공용 와이파이 보호, 원격 근무 |
| **SOCKS 프록시** | 사용자 | 웹 말고 다른 프로그램 통신도 전달 | 개발·관리 도구 |

### 1인 사업자에게 실제로 필요한 것: 리버스 프록시
내 서비스 앞에 리버스 프록시(예: 클라우드플레어)를 두면:
- **HTTPS 인증서 자동 관리**
- **캐시·CDN**으로 속도 향상 (68장)
- **DDoS 방어·웹 방화벽(WAF)·요청 제한** (41·83장)
- **봇 관리**: 2025년 7월부터 클라우드플레어는 새 고객 사이트에 **AI 크롤러를 기본 차단**하고, 사이트가 AI 크롤러에게 **돈을 받고 허용**하는 시범 기능(pay per crawl)도 내놨어요.

### 다른 나라에서 내 사이트 확인하기 (52장)
해외 손님에게 가격·언어·결제가 제대로 보이는지, **내 사이트를** 다른 지역에서 열어 보는 건 정당한 용도예요. 브라우저 개발자 도구의 위치 설정, 클라우드의 해외 지역 서버, 상업용 지역 테스트 서비스를 쓰면 돼요.

### ⚠️ "주거용 프록시"를 조심해야 하는 이유
- **주거용 프록시** = 일반 가정의 인터넷 주소를 빌려 쓰는 프록시예요. 차단을 피하려는 수집에 많이 쓰여요.
- 문제는 그 "가정"이 **동의 없이 끌려온 기기**인 경우가 많다는 거예요. 2026년 1월 구글은 세계 최대급 주거용 프록시망 **IPIDEA**를 차단했어요.
  - **어떻게 기기를 모았나**: 게임·유틸리티 앱에 "수익화" 코드를 숨겨 넣어, 사용자 모르게 기기를 프록시로 만들었어요. 동의 절차가 없었다고 분석됐어요.
  - **누가 썼나**: 한 주 동안 **550개가 넘는 해킹 조직**이 이 망을 쓴 것으로 추적됐어요.
- **내 사업에 주는 의미**:
  - 이런 프록시를 쓰면 **범죄 인프라를 돈 주고 쓰는 셈**이 될 수 있어요.
  - 내가 만든 앱에 출처 모를 "수익화 SDK"를 넣으면 **내 손님의 기기가 프록시로 팔릴 수 있어요**(79장 공급망).

## 2. 동적 딜레이 — 상대 서버에 맞춰 속도를 조절하기

**동적 딜레이** = 고정된 간격이 아니라, **상대의 반응을 보고** 요청 간격을 늘리거나 줄이는 방법이에요. 81장의 "지수 백오프 + 지터"를 수집·API 호출에 적용한 거예요.

### 예의 바른 수집의 규칙
| 규칙 | 내용 |
|---|---|
| **공식 API·공공데이터 먼저** | 있으면 그걸 쓰기 (69장) |
| **robots.txt 지키기** | 2022년 인터넷 표준(RFC 9309)이 됐어요. 막아 둔 경로는 수집하지 않기 |
| **정직한 신분 표시** | User-Agent에 **봇 이름 + 안내 페이지 주소 + 연락처**. 사람인 척하지 않기 |
| **천천히, 한 번에 하나씩** | 같은 사이트에 동시 요청을 몰지 않기, 사람이 적은 시간대에 |
| **429·503이면 물러나기** | "너무 많아요" 응답의 **Retry-After**(기다릴 시간)를 지키고 간격을 늘리기 |
| **같은 걸 두 번 받지 않기** | 받아 둔 것은 저장(캐시), 바뀌었을 때만 다시 받기 |
| **로그인 뒤 영역은 수집하지 않기** | 접근 권한 문제가 커져요 (69장) |

robots.txt의 `Crawl-delay`(요청 간격 지정)는 **표준에 들어가지 않았어요**. 구글은 무시하고 일부 검색 엔진만 따라요. 그래서 간격은 **상대 서버의 실제 반응(429·응답 속도)**을 보고 정하는 게 맞아요.

### 실습 — 스스로 느려지는 수집기
연습용 사이트(내 컴퓨터에서만 실행)는 robots.txt로 `/admin`을 막아 두고, 1초에 2번 넘게 요청하면 429로 답해요.

```python
import random, time, urllib.request, urllib.error, urllib.robotparser

BASE = "http://127.0.0.1:8077"
UA = "GranolaLabBot/1.0 (+https://granolalab.example/bot; bot@granolalab.example)"  # 누구인지·연락처를 정직하게

robots = urllib.robotparser.RobotFileParser(BASE + "/robots.txt")
robots.read()

class PoliteFetcher:
    """사이트 반응에 맞춰 스스로 속도를 조절하는 수집기 (동적 딜레이)."""
    def __init__(self, delay=0.3, max_delay=5.0):
        self.delay, self.max_delay = delay, max_delay

    def get(self, path):
        url = BASE + path
        if not robots.can_fetch(UA, url):
            return f"건너뜀 (robots.txt가 금지): {path}"
        for attempt in range(4):
            time.sleep(self.delay + random.uniform(0, self.delay / 2))   # 기본 간격 + 지터
            req = urllib.request.Request(url, headers={"User-Agent": UA})
            try:
                with urllib.request.urlopen(req, timeout=5) as r:          # 타임아웃 (81장)
                    self.delay = max(0.3, self.delay * 0.9)                 # 잘 되면 아주 조금씩만 빠르게
                    return r.read().decode()
            except urllib.error.HTTPError as e:
                if e.code in (429, 503):
                    wait = float(e.headers.get("Retry-After", self.delay * 2))
                    self.delay = min(self.max_delay, max(self.delay * 2, wait))   # 느리게 (백오프)
                    print(f"  {e.code} 받음 → 간격을 {self.delay:.1f}초로 늘림")
                else:
                    return f"오류 {e.code}"
        return "포기 (계속 거절됨)"

f = PoliteFetcher()
for p in ["/a", "/b", "/c", "/d", "/admin/users", "/e"]:
    print(p, "→", f.get(p))
```

실행 결과 (연습용 사이트를 함께 띄워 직접 확인했어요):
```
/a → /a 내용
/b → /b 내용
  429 받음 → 간격을 1.0초로 늘림
/c → /c 내용
/d → /d 내용
/admin/users → 건너뜀 (robots.txt가 금지): /admin/users
/e → /e 내용
```
- 429를 받자 **간격을 늘려** 더 이상 거절당하지 않았어요. 금지된 `/admin`은 **아예 요청하지 않았어요.**
- 핵심은 **"상대가 힘들다고 하면 내가 느려진다"**예요. 반대로 "어디까지 빨리 해도 안 걸리나"를 찾는 데 쓰면 같은 코드가 문제가 돼요.
- 내 서비스가 **외부 API를 부를 때**(결제·문자·AI)도 똑같이 적용돼요. 429를 받으면 물러나는 코드가 없으면 계정이 정지될 수 있어요.

> 💡 연습용 사이트 코드는 이 장 끝 "부록"에 있어요. **남의 사이트에 이 수집기를 돌리기 전에 69장 체크리스트**부터 확인하세요.

## 3. 브라우저 자동화(시뮬레이션) — 손님처럼 클릭하는 프로그램

**브라우저 자동화** = 프로그램이 진짜 브라우저(크롬 등)를 열어 **클릭·입력·스크롤**을 대신하는 것이에요. 화면 없이 돌리면 **헤드리스(headless)** 브라우저라고 해요. 대표 도구는 **Playwright**, **Puppeteer**, **Selenium**이에요.

### 1인 사업자에게 가장 쓸모 있는 용도
| 용도 | 예 | 장 |
|---|---|---|
| **E2E 테스트** (처음부터 끝까지 손님처럼) | 가입 → 장바구니 → 결제(테스트 모드) → 완료 화면을 배포 전마다 자동 확인 | 50 |
| **화면 깨짐 확인** | 휴대폰·PC 크기로 주요 페이지 캡처해 비교 | 48·68 |
| **합성 모니터링** | 5분마다 "로그인 → 핵심 기능"이 되는지 자동 확인, 안 되면 알림 | 9·81 |
| **접근성·속도 측정** | Lighthouse 자동 실행 | 68 |
| **허가받은 업무 자동화** | 내 계정의 관리 화면에서 반복 작업 (API가 없을 때) | 69 |
| **자바스크립트로 그리는 공개 페이지 읽기** | 허가된 범위에서, 2절 규칙대로 | 69 |

### 실습 — 한 바퀴 앱을 손님처럼 테스트하기
80장에서 만드는 한 바퀴 앱을 실제 브라우저(휴대폰 크기)로 열어 **스텝을 열고 → 체크하고 → 완료로 바꾸고 → 진행표에 반영됐는지** 확인해요.

```javascript
// 브라우저 자동화로 "손님처럼" 한 바퀴 돌아보는 테스트 (50장 E2E)
const { chromium } = require('playwright');
(async () => {
  const browser = await chromium.launch();                 // 화면 없는(헤드리스) 크롬
  const page = await browser.newPage({ viewport: { width: 390, height: 844 } });   // 휴대폰 크기
  const base = 'http://127.0.0.1:3300';

  await page.goto(base + '/');
  await page.getByText('지금 할 스텝 열기').click();         // 사람처럼 버튼을 눌러 이동
  await page.waitForURL('**/steps/0-1');
  console.log('1) 첫 스텝 열림:', await page.locator('h1').innerText());

  await page.locator('.checklist button').first().click(); // 첫 체크리스트 항목 체크
  await page.waitForURL('**/steps/0-1#checklist');
  const pressed = await page.locator('.checklist button').first().getAttribute('aria-pressed');
  console.log('2) 체크 저장됨:', pressed);

  await page.getByRole('button', { name: '완료' }).click();  // 상태를 완료로
  await page.goto(base + '/');
  console.log('3) 진행표 반영:', await page.locator('.hero .muted').innerText());

  await page.screenshot({ path: 'e2e-home.png' });          // 결과 화면 저장
  await browser.close();
})();
```

실행 결과 (한 바퀴 앱을 띄워 직접 확인했어요):
```
1) 첫 스텝 열림: 0-1. 목표와 시간 정하기
2) 체크 저장됨: true
3) 진행표 반영: 54개 스텝 중 1개 끝 (1%)
```
- **글자·역할로 찾기**(`getByText`, `getByRole`)를 쓰면 디자인이 조금 바뀌어도 테스트가 덜 깨져요. 접근성(68장)이 좋은 화면일수록 테스트하기도 쉬워요.
- 이 테스트를 CI(79장)에 넣으면 **배포 전마다 자동으로 "손님 경로"를 확인**해요.

> 💡 Claude에게: "Playwright로 우리 쇼핑몰의 가입 → 장바구니 → 테스트 결제 → 주문 완료까지 E2E 테스트를 만들어 줘. 휴대폰 크기와 PC 크기 둘 다, 실패하면 화면 캡처를 남기게 해 줘. 운영 서버가 아니라 스테이징 주소로."

## 4. 내 서비스를 지키는 쪽 — 봇 막기

내 서비스를 운영하면 반대 입장이 돼요. 가짜 가입·크리덴셜 스터핑(84장)·가격 긁어 가기·선착순 싹쓸이 같은 **나쁜 봇**이 와요.

| 방법 | 내용 | 장 |
|---|---|---|
| **요청 제한** | IP·계정·기기별로 1분당 횟수 제한, 넘으면 429 + Retry-After | 41·60 |
| **robots.txt·AI 크롤러 설정** | 착한 봇에게 원하는 범위를 알리기 (나쁜 봇은 무시하니 이것만으론 부족) | 38 |
| **리버스 프록시의 봇 관리** | 클라우드플레어 등의 봇 점수·AI 크롤러 차단·검증된 봇 허용 | 1절 |
| **행동 신호** | 너무 빠른 입력, 사람이 안 하는 순서, 한 기기의 다계정 | 41 |
| **사람 확인** | 의심될 때만 캡차·턴스타일 같은 확인 (모두에게 띄우면 손님이 떠나요) | 41 |
| **중요 행동 보호** | 가입·로그인·결제·쿠폰·선착순에 집중 | 41·65 |
| **정상 봇은 허용** | 검색 엔진 등 검증된 봇은 막지 않기 (63장 검색 노출) | 63 |

> 💡 **User-Agent만 보고 막으면 안 돼요.** 누구나 쉽게 바꿀 수 있어서 보안 장치가 아니에요. 여러 신호를 합쳐서 판단해요.

## 5. 하지 말 것 — 그리고 이 교재가 다루지 않는 것

다음은 **이 교재에서 방법을 다루지 않아요.** 기술적으로 가능하더라도 1인 사업자에게 **법적·사업적 위험이 이익보다 훨씬 커요.**

| 하지 말 것 | 왜 위험한가 |
|---|---|
| 차단·요청 제한을 **IP를 바꿔 가며 피하기** | 상대가 "그만"이라고 명확히 표시한 뒤의 접근 → 업무방해·부정경쟁·약관 위반 주장의 근거가 됨 (69장 판례: 형사 무죄여도 민사 배상) |
| **사람인 척 위장**(브라우저 지문 바꾸기, 봇 탐지 회피) | 같은 이유 + 계정·서비스 영구 차단 |
| **캡차를 대신 풀어 주는 서비스** 쓰기 | 사람 확인을 의도적으로 무력화 |
| 출처 모를 **주거용 프록시** 쓰기 | 동의 없이 끌려온 기기일 수 있음 (IPIDEA 사례) |
| **로그인 뒤 영역·개인정보** 자동 수집 | 접근 권한·개인정보보호법 문제 (69·10장) |
| 자동화로 **가짜 가입·리뷰·예매·클릭** | 표시광고법·업무방해, 광고 계정 정지 (18·41장) |

**정당하게 데이터가 필요하면** 공식 API, 공공데이터, **제휴·라이선스 계약**, 데이터 판매처를 찾으세요. 상대에게 연락해 허락받는 게 가장 빠른 경우도 많아요.

---

### 이 장 요약
1. **프록시**: 1인 사업자에게 필요한 건 내 서비스 앞의 **리버스 프록시**(HTTPS·캐시·DDoS·봇 관리). 출처 모를 **주거용 프록시는 피한다**.
2. **동적 딜레이**는 "상대가 힘들면 내가 느려지는" 장치: robots.txt, 정직한 신분, 429·Retry-After 존중, 캐시. 외부 API 호출에도 똑같이.
3. **브라우저 자동화**는 **내 서비스의 E2E 테스트·모니터링**에 가장 쓸모 있고, 내 서비스는 **요청 제한·봇 관리·행동 신호**로 나쁜 봇을 막는다. **차단 우회는 하지 않는다.**

## 부록 — 2절 실습용 연습 사이트 (내 컴퓨터에서만 실행)

```python
"""연습용 사이트: robots.txt를 주고, 1초에 2번 넘게 요청하면 429(너무 많아요)로 답해요."""
import time
from http.server import BaseHTTPRequestHandler, ThreadingHTTPServer

recent = []

class Site(BaseHTTPRequestHandler):
    def do_GET(self):
        if self.path == "/robots.txt":
            body = b"User-agent: *\nDisallow: /admin\n"
            self.send_response(200); self.send_header("Content-Type", "text/plain"); self.end_headers()
            return self.wfile.write(body)
        now = time.time()
        recent[:] = [t for t in recent if now - t < 1.0] + [now]
        if len(recent) > 2:
            self.send_response(429); self.send_header("Retry-After", "1"); self.end_headers()
            return
        self.send_response(200); self.send_header("Content-Type", "text/plain; charset=utf-8"); self.end_headers()
        self.wfile.write(f"{self.path} 내용".encode())
    def log_message(self, *a): pass

if __name__ == "__main__":
    ThreadingHTTPServer(("127.0.0.1", 8077), Site).serve_forever()
```
실행: 터미널 하나에서 `python3 test_site.py`, 다른 터미널에서 2절의 수집기 실행.

이 연습 사이트는 **내 서비스에 요청 제한을 거는 가장 단순한 예**이기도 해요(4절). 실제 서비스에서는 IP·계정별로 나누고, 리버스 프록시나 프레임워크의 요청 제한 기능을 쓰세요.
