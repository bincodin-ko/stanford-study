## 1. 정규식 — 글자의 "패턴"을 찾는 작은 언어

**정규식(정규 표현식, regex)** = "숫자 3~4개, 하이픈, 숫자 4개" 같은 **글자 모양**을 짧은 기호로 적는 방법이에요. 입력값 검사·로그 정리·데이터 청소에 자주 써요.

### 자주 쓰는 기호
| 기호 | 뜻 | 예 |
|---|---|---|
| `\d` | 숫자 한 개 | `\d\d` → "42" |
| `\s` | 공백(띄어쓰기·탭·줄바꿈) | |
| `\b` | 단어의 경계 | `\bA\d+` |
| `.` | 아무 글자 한 개 | |
| `*` / `+` / `?` | 0개 이상 / 1개 이상 / 있거나 없거나 | `-?` → 하이픈이 있어도 없어도 |
| `{3,4}` | 3~4번 반복 | `\d{3,4}` |
| `[016789]` | 이 중 하나 | |
| `^` / `$` | 처음 / 끝 | |
| `( )` | 묶기 (나중에 꺼내 쓰기) | `\1` = 첫 번째 묶음 |

### 실습

```python
import re

# 1) 입력값 검사: 휴대폰 번호 (010-1234-5678 또는 01012345678)
phone = re.compile(r"^01[016789]-?\d{3,4}-?\d{4}$")
for p in ["010-1234-5678", "01012345678", "02-123-4567", "010-12-5678"]:
    print(p, "→", bool(phone.fullmatch(p)))

# 2) 글 속에서 찾기: 주문번호 "A" + 숫자 6자리
text = "주문 A123456 과 A654321 을 환불해 주세요. B999999 는 아님"
print(re.findall(r"\bA\d{6}\b", text))

# 3) 바꾸기: 로그에 남기기 전 전화번호 가리기 (68장)
log = "고객 010-1234-5678 님이 문의함"
print(re.sub(r"(01[016789])-?(\d{3,4})-?(\d{4})", r"\1-****-\3", log))

# 4) 정리: 여러 칸 띄어쓰기를 한 칸으로
print(re.sub(r"\s+", " ", "무설탕    그래놀라\t  500g").strip())
```

실행 결과 (직접 돌려 확인했어요):
```
010-1234-5678 → True
01012345678 → True
02-123-4567 → False
010-12-5678 → False
['A123456', 'A654321']
고객 010-****-5678 님이 문의함
무설탕 그래놀라 500g
```

### 정규식 쓸 때 주의
- **이메일 주소를 정규식으로 완벽하게 검사하려 하지 마세요.** 규칙이 너무 복잡해요. 간단히 확인하고, **인증 메일**로 진짜인지 확인하는 게 정답이에요(65장).
- 화면(자바스크립트)에서 검사해도 **서버에서 다시 검사**(60장).
- 복잡한 정규식은 읽기 어려워요 → **주석**을 달고, AI에게 만들게 했다면 **예시 입력 여러 개로 테스트**(위처럼)하세요.
- 일부 복잡한 패턴은 특정 입력에서 **엄청 느려져서** 서버를 멈추게 할 수 있어요(ReDoS 공격). 손님 입력에 쓰는 정규식은 단순하게.

> 💡 Claude에게: "한국 휴대폰 번호를 검사하는 정규식을 만들고, 맞는 예 5개·틀린 예 5개로 테스트하는 코드도 같이 만들어 줘. 각 기호가 무슨 뜻인지 주석으로 설명해 줘."

## 2. 도커 — "내 컴퓨터에선 되는데?"를 없애는 상자

**도커(Docker)** = 프로그램과 그 프로그램이 필요한 환경(언어 버전, 라이브러리, 설정)을 **한 상자(컨테이너)**에 담아 어디서나 똑같이 실행하게 하는 도구예요.

| 용어 | 비유 | 뜻 |
|---|---|---|
| **Dockerfile** | 요리 레시피 | 상자를 만드는 순서 |
| **이미지** | 냉동 도시락 | 레시피로 만든 완성품 (변하지 않음) |
| **컨테이너** | 데워서 먹는 중인 도시락 | 이미지를 실행한 것 |
| **레지스트리** | 도시락 창고 | 이미지를 올려 두는 곳 (Docker Hub 등) |

### 언제 필요한가 (1인 사업자 기준)
- ✅ **서버를 직접 운영**할 때(VPS, 36장): 서버를 바꿔도 똑같이 실행
- ✅ 개발 환경 맞추기: 외주 개발자·새 컴퓨터에서도 같은 환경 (53장)
- ✅ DB 같은 도구를 내 컴퓨터에 **깔끔하게** 띄웠다 지우기
- ❌ 빌더나 Vercel 같은 서비스를 쓴다면 **당장 몰라도 돼요** (36장)

### 실습 — 작은 웹 서버를 상자에 담기

`app.py`:
```python
from http.server import BaseHTTPRequestHandler, HTTPServer

class Hello(BaseHTTPRequestHandler):
    def do_GET(self):
        self.send_response(200)
        self.send_header("Content-Type", "text/plain; charset=utf-8")
        self.end_headers()
        self.wfile.write("그래놀라랩 서버가 컨테이너 안에서 돌고 있어요".encode())

HTTPServer(("0.0.0.0", 8000), Hello).serve_forever()
```

`Dockerfile`:
```dockerfile
# 1) 바탕 이미지: 파이썬이 설치된 작은 리눅스
FROM python:3.12-slim
# 2) 컨테이너 안 작업 폴더
WORKDIR /app
# 3) 내 코드 복사
COPY app.py .
# 4) 관리자(root) 대신 일반 사용자로 실행 (보안)
RUN useradd --create-home appuser
USER appuser
# 5) 이 컨테이너가 쓰는 포트 안내
EXPOSE 8000
# 6) 컨테이너가 켜지면 실행할 명령
CMD ["python", "app.py"]
```

실행 명령과 결과 (직접 실행해 확인했어요):
```bash
docker build -t granola-hello .              # 이미지 만들기
docker run -d --rm -p 8000:8000 --name gh granola-hello   # 실행 (내 컴퓨터 8000번 ↔ 상자 8000번)
curl http://127.0.0.1:8000/                  # → 그래놀라랩 서버가 컨테이너 안에서 돌고 있어요
docker exec gh whoami                        # → appuser   (관리자가 아닌 사용자로 실행 중)
docker stop gh                               # 끄기
```
만들어진 이미지 크기는 약 177MB였어요(바탕 이미지 대부분).

### 도커 쓸 때 지킬 것
| 규칙 | 이유 |
|---|---|
| **비밀 키를 이미지에 넣지 않기** | 이미지를 공유하면 키도 같이 퍼져요. 실행할 때 **환경 변수**로 (37·58장) |
| **root로 실행하지 않기** | 위 예처럼 일반 사용자로 → 뚫려도 피해를 줄임 |
| **바탕 이미지 버전 고정** | `python:3.12-slim`처럼. `latest`는 어느 날 갑자기 바뀌어요 |
| **데이터는 상자 밖에** | 컨테이너를 지우면 안의 데이터도 사라져요. DB 파일은 볼륨이나 외부 DB에 (8장 백업) |
| **이미지도 업데이트** | 바탕 이미지의 보안 패치를 반영하려면 주기적으로 다시 빌드 |

## 3. 의존성 관리 — 남이 만든 부품 관리하기

**의존성** = 내 프로그램이 가져다 쓰는 **외부 라이브러리**(npm 패키지, 파이썬 패키지 등)예요. 요즘 프로그램은 코드의 대부분이 의존성이에요. 편리하지만 **남의 부품에 구멍이 생기면 내 서비스도 위험**해요.

### 꼭 할 것
| 할 것 | 방법 |
|---|---|
| **버전 고정 파일을 Git에** | `package-lock.json`, `poetry.lock`, `requirements.txt`(버전 명시) → 어디서나 같은 버전 설치 |
| **자동 보안 알림** | 깃허브 **Dependabot** 알림·자동 업데이트 PR 켜기, `npm audit` / `pip-audit` 주기적 실행 |
| **업데이트는 작게, 자주** | 한 번에 수십 개 올리면 뭐가 고장 냈는지 몰라요. 테스트(50장) 후 배포(7장) |
| **새 패키지 추가 전 확인** | 다운로드 수, 최근 업데이트, 관리자, 라이선스(47장 — AGPL 주의) |
| **이름 확인** | 유명 패키지와 **철자가 한 글자 다른 가짜 패키지**(타이포스쿼팅)가 있어요. AI가 **존재하지 않는 패키지 이름**을 지어내는 경우도 있으니 설치 전에 공식 저장소에서 확인 |
| **안 쓰는 것 지우기** | 부품이 적을수록 구멍도 적어요 |

### 매달 10분 점검 (68장 비용 점검과 같이)
```
□ Dependabot·보안 알림 확인 → 심각한 것부터 업데이트
□ npm audit / pip-audit 실행
□ 바탕 도커 이미지 다시 빌드
□ 안 쓰는 패키지 정리
```

> 💡 Claude에게: "package.json의 의존성 중 보안 취약점이 있는 것, 1년 넘게 업데이트가 없는 것, 실제 코드에서 안 쓰는 것을 표로 찾아 줘. 업데이트는 한 번에 하나씩, 테스트 통과 확인 후 커밋하자."

---

### 이 장 요약
1. **정규식**은 입력 검사·로그 가리기·데이터 정리에 쓰고, **예시 입력으로 꼭 테스트**. 이메일은 정규식보다 인증 메일로.
2. **도커**는 서버를 직접 운영할 때 "어디서나 같게" 실행하는 상자. **비밀은 환경 변수로, root 금지, 버전 고정, 데이터는 밖에**.
3. **의존성**은 잠금 파일·자동 보안 알림·작은 업데이트로 관리하고, **가짜 패키지 이름**에 주의.
