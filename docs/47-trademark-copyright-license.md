# 47. 상표·저작권·오픈소스 라이선스·AI 결과물

서비스 이름, 로고, 사진, 글, 코드 — 사업은 **남의 권리를 침해하지 않고, 내 권리는 지키는** 일이기도 해요.

> ⚠️ 2026년 11월 조사 기준. 수수료·제도는 바뀌고, 권리 판단은 사례마다 달라요. 중요한 결정은 **변리사·변호사**와 확인하세요. ([참고 자료 모음](sources.md))

---

## 1. 지식재산권 한눈에

| 권리 | 지키는 것 | 생기는 방법 | 예 |
|---|---|---|---|
| **상표권** | 이름·로고 (브랜드) | **특허청에 출원·등록**해야 생김 | "그래놀라랩" 이름, 로고 |
| **저작권** | 글·사진·그림·음악·영상·**코드** | 만드는 순간 자동으로 생김 (등록은 선택) | 상세 페이지 글, 상품 사진, 프로그램 |
| **디자인권** | 물건의 모양 | 출원·등록 | 독특한 포장 용기 |
| **특허권** | 새로운 기술 아이디어 | 출원·등록 (어려움·비쌈) | 새로운 기계 장치 |
| 영업비밀 | 공개 안 한 노하우 | 비밀로 관리 | 레시피, 고객 명단 |

> 💡 1인 창업자에게 가장 중요한 건 **상표(이름)** 와 **저작권(콘텐츠·코드)** 이에요.

---

## 2. 상표 — 브랜드 이름 지키기

### 왜 필요한가
- 도메인(34장)이나 사업자등록 상호가 있어도 **상표권은 자동으로 생기지 않아요.**
- 한국은 기본적으로 **먼저 출원한 사람**에게 권리를 줘요(선출원주의). 잘 되던 이름을 남이 먼저 등록하면 **이름을 바꿔야** 할 수도 있어요.

### 절차
```
1. 검색: 특허청 키프리스(KIPRIS)에서 같거나 비슷한 상표가 있는지
2. 분류 고르기: 상품·서비스 분류(예: 식품, 온라인 쇼핑몰 서비스, 소프트웨어)
3. 출원: 특허로(전자출원) 직접 또는 변리사 통해
4. 심사 → 거절 이유가 있으면 의견서로 대응
5. 등록 결정 → 등록료 납부 → 상표권 (10년, 갱신 가능)
```

### 비용 감 (조사 기준, 확인 필요)
- 특허청에 내는 돈(관납료) + 변리사에게 맡기면 수수료.
- 전자출원 관납료는 **1개 분류당 수만 원 수준**인데, 자료마다 금액이 달랐어요(예: 46,000원 / 62,000원). 등록료는 분류당 약 20만 원대라는 안내가 있어요. **특허청 공식 수수료 안내로 확인**하세요.

### 실전 팁
- 이름을 정할 때 **도메인·SNS 아이디·상표 검색을 동시에** (34장)
- 흔한 단어("맛있는빵")는 등록이 어려워요 → 독특한 조어가 유리
- 출원은 **빠를수록** 좋아요 (출시 전이라도)
- 남의 유명 상표와 비슷한 이름은 피하기 (34장 도메인 분쟁)

## 3. 저작권 — 남의 것 쓰기, 내 것 지키기

### 남의 것을 쓸 때 (가장 흔한 사고)
| 대상 | 규칙 |
|---|---|
| **이미지** | 구글 검색 이미지 무단 사용 ✕. 무료 이미지 사이트도 **라이선스 조건**(상업 사용? 출처 표시?) 확인 (17장) |
| **폰트** | 무료 폰트도 **상업용·웹폰트·로고 사용**이 허용되는지 확인. 유료 폰트 무단 사용은 분쟁 단골 |
| **음악** | 영상·매장 배경음악은 허락된 음원만 (24장) |
| **글** | 남의 글 통째 복사 ✕. 짧게 인용 + 출처 |
| **남의 상품 사진** | 도매처·제조사 사진도 사용 허락 확인 (23장) |

### 내 것을 지킬 때
- 저작물은 만들면 자동 보호. 분쟁에 대비해 **만든 날짜·원본 파일**을 보관하고, 필요하면 한국저작권위원회에 **저작권 등록**.
- 외주로 만든 디자인·코드는 **계약서에 권리 귀속을 명시**하지 않으면 분쟁이 생겨요 (53장).

## 4. AI로 만든 결과물의 저작권

- 문화체육관광부와 한국저작권위원회는 2025년 6월 **「생성형 AI 활용 저작물의 저작권 등록 안내서」** 를 냈어요.
- 해설 자료에 따르면 핵심은:
  - **프롬프트(요청문)만 입력해서 나온 결과물**은 사람의 창작으로 인정받기 어려워요.
  - 사람이 **선택·배열·수정**하는 등 결과를 통제하며 창작적으로 기여한 부분은 등록이 될 수 있어요.
- 실무에서는 "기준이 여전히 모호하다"는 반응도 있어요.

### 1인 창업자의 실전 원칙
| 상황 | 원칙 |
|---|---|
| AI로 로고 만들기 | 독점적 권리를 주장하기 어려울 수 있음 → 핵심 로고는 사람이 다듬고, **상표 등록**으로 보호 |
| AI로 상품 설명·블로그 글 | 사실 확인 후 내 말로 수정, 대량 자동 생성은 검색 스팸 위험 (17장) |
| AI로 코드 작성 | 결과 코드를 이해·검토하고, 아래 오픈소스 라이선스 문제 확인 |
| AI 서비스 이용약관 | 각 AI 회사의 약관에 결과물 사용 조건이 있음 → 상업 사용 가능 여부 확인 |
| 남의 저작물을 AI에 넣기 | 남의 그림을 그대로 흉내 내게 하는 건 분쟁 위험 |

## 5. 오픈소스 라이선스 — 남의 코드를 쓸 때

개발할 때 쓰는 라이브러리(8장 패키지)는 대부분 **오픈소스**예요. 무료지만 **라이선스(사용 조건)** 가 있어요.

| 종류 | 대표 | 쉬운 뜻 | 상업 서비스에서 |
|---|---|---|---|
| **허용형** | **MIT**, BSD, **Apache 2.0** | 거의 자유롭게 사용. 저작권 표시 유지 | ✅ 편하게 사용. Apache 2.0은 **특허 사용 허락**도 명시 |
| **카피레프트** | **GPL** | 이 코드를 고쳐서 **배포**하면 내 코드도 같은 라이선스로 공개 | 앱·설치형 프로그램을 **배포**할 때 주의 |
| **네트워크 카피레프트** | **AGPL** | 고쳐서 **웹 서비스로 제공만 해도** 수정한 소스 공개 의무 | ⚠️ **SaaS에서 가장 조심** |
| 약한 카피레프트 | LGPL, MPL | 라이브러리 자체 수정분만 공개 | 조건 확인 |

- GPL은 "배포"할 때 의무가 생겨서, **서버에서만 돌리는 서비스**는 의무가 적다는 해석이 일반적이에요. AGPL은 바로 그 빈틈을 막은 라이선스예요.
- **실전**: `package.json` 등 의존성 목록의 라이선스를 한 번 훑어보기 → AGPL·GPL이 있으면 쓰는 방식을 확인. 라이선스 확인 도구도 있어요.
- 사용한 오픈소스의 **저작권·라이선스 고지**를 앱·사이트 어딘가("오픈소스 라이선스" 페이지)에 두는 게 일반적이에요.

## 6. 체크리스트

- [ ] 서비스 이름: 키프리스 상표 검색 + 도메인 + SNS 아이디 동시 확인
- [ ] 핵심 이름·로고 **상표 출원** (출시 전후 빠르게)
- [ ] 사이트의 이미지·폰트·음악 **라이선스 목록** 작성
- [ ] 외주 계약서에 저작권·소스코드 귀속 명시
- [ ] 사용하는 오픈소스 라이선스 확인 (AGPL·GPL 주의), 고지 페이지
- [ ] AI 결과물은 사람이 수정·검토, AI 서비스 약관 확인

---

### 이 장 요약
1. **상표는 출원해야 생기고 먼저 낸 사람이 유리** → 이름 정하면 바로 검색·출원.
2. 저작권은 자동 발생. **이미지·폰트·음악은 라이선스 확인**, 외주는 계약서에 권리 귀속.
3. AI 결과물은 **프롬프트만으론 권리 인정이 어렵다**는 안내. 오픈소스는 **MIT·Apache는 편하고, AGPL은 SaaS에서 주의**.
