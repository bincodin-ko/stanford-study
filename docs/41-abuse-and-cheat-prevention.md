# 41. 어뷰징·핵 대응 — 미리 막고, 찾아내고, 제재하기

37장은 **해커가 시스템을 뚫는 것**을 막는 보안이었어요.
이 장은 시스템은 정상인데 **규칙을 악용하는 사람들**(어뷰징)과 **게임 핵**을 다뤄요. 쇼핑몰·커뮤니티·광고·게임 모두에 해당해요.

> ⚠️ 2026년 10월 조사 기준. 탐지 기술 세부는 회사마다 비밀인 경우가 많아, 공개 자료·업계 해설 기준으로 정리했어요. ([참고 자료 모음](sources.md))

---

## 1. 어뷰징과 핵의 종류

| 분야 | 어뷰징·핵 | 예 |
|---|---|---|
| **쇼핑몰·앱** | **쿠폰·신규가입 혜택 악용** | 여러 계정을 만들어 첫 구매 쿠폰을 반복 사용 |
| | 추천인 보상 악용 | 내 다른 계정을 추천인으로 등록 |
| | 리셀·사재기 봇 | 한정판을 매크로로 싹쓸이 |
| | 리뷰 조작 | 가짜 후기·별점, 경쟁사 악성 리뷰 |
| | 결제 사기·차지백 사기 | 도용 카드 결제, 받아 놓고 "안 받았다" 이의 제기 (39장) |
| **로그인** | **크리덴셜 스터핑** | 다른 사이트에서 유출된 아이디·비밀번호를 대량으로 넣어 보는 공격 → 계정 탈취 |
| | 가짜 계정 대량 가입 | 스팸·사기용 |
| **커뮤니티** | 도배·스팸 봇, 추천수 조작, 여론 조작용 다계정 | 16장 |
| **광고** | 부정 클릭·가짜 트래픽 | 18장 |
| **게임** | **핵(치트)** | 에임봇(자동 조준), 월핵(벽 너머 보기), 스피드핵 |
| | 매크로·작업장 | 자동 사냥으로 아이템을 대량 수집해 현금 거래 |
| | 버그 악용 | 아이템 복사 버그 |
| | 대리 게임·계정 거래 | 남의 계정으로 랭크 올려 주기 |
| | 고의 패배·승부 조작 | 점수 조작 (20장) |

## 2. 대응의 기본 구조: 4단계

```
① 설계로 막기 (애초에 악용할 구멍을 만들지 않기)
② 입구에서 막기 (가입·로그인·결제 단계의 확인 장치)
③ 운영 중 찾아내기 (로그·패턴·신고로 탐지)
④ 제재하고 배우기 (정지·회수 → 규칙·탐지 개선)
```

> 💡 어뷰징은 **"완벽히 막기"가 아니라 "악용하는 비용 > 얻는 이익"** 으로 만드는 싸움이에요. 정상 손님이 불편해지지 않는 선에서 **여러 겹**으로 막아요.

## 3. 서비스(쇼핑몰·앱·커뮤니티) 어뷰징 대응

### ① 설계로 막기
| 방법 | 예 |
|---|---|
| **혜택 조건 설계** | 가입 즉시 쿠폰 대신 **첫 구매 확정 후 적립**, 본인인증 완료 + 일정 활동 후 지급 같은 복합 조건 |
| **1인 1혜택 기준을 정하기** | "계정당"이 아니라 **사람당**(본인인증 기준) |
| **추천 보상** | 추천받은 사람이 **실제 구매**해야 지급, 같은 기기·결제 수단·주소면 미지급 |
| **수량 제한** | 한정판은 1인 1개, 구매 전 대기열 (7장 큐) |
| **약관에 명시** | "부정한 방법으로 받은 혜택은 회수하고 이용을 제한할 수 있다" → 나중에 회수·제재의 근거 |

### ② 입구에서 막기
| 방법 | 설명 |
|---|---|
| **휴대폰 본인인증(CI/DI)** | 같은 사람을 식별하는 값으로 **중복 가입·중복 혜택** 확인. 국내 업계는 "실명인증 기준 1인 1계정 혜택"을 흔한 규칙으로 쓴다는 설명이 있어요 |
| **기기 식별** | 같은 기기에서 혜택 반복 수령 제한 (단, 가족이 한 기기를 쓰는 경우 고려) |
| **봇 차단** | 캡차·Turnstile, 숨겨진 함정 칸(허니팟), 너무 빠른 제출 차단 (30·38장) |
| **속도 제한** | 같은 IP·계정에서 짧은 시간 많은 요청 제한 (37장) |
| **결제 단계 확인** | 해외 카드·고액·배송지 다른 첫 주문은 추가 확인 (PG의 이상 거래 탐지 기능 활용) |

### ③ 로그인 공격(크리덴셜 스터핑) 막기 — OWASP 권장 요약
- **2단계 인증(MFA)이 가장 효과적인 방어**라고 OWASP가 명시해요. 모든 사용자에게 강제하기 어렵다면 **최소한 관리자 계정은 필수**.
- **IP 차단·속도 제한만으로는 약해요**: 공격자가 수많은 IP로 나눠서 조금씩 시도하기 때문. **여러 겹 방어**가 필요해요.
- **유출된 비밀번호 검사**: 가입·변경 때 이미 유출된 비밀번호 목록에 있는 비밀번호는 거절.
- **새 기기·새 지역 로그인 알림**, 의심스러우면 추가 인증.
- 앞으로는 **패스키(passkey)** 처럼 비밀번호 없는 로그인이 근본 해결책으로 꼽혀요.
- 클라이언트 쪽 기기 지문·자바스크립트 확인은 **위조될 수 있으니 서버 쪽 확인과 함께**.

### ④ 운영 중 찾아내기
| 신호 | 예 |
|---|---|
| 같은 기기·결제 수단·배송지·IP를 공유하는 계정 묶음 | 다계정 쿠폰 악용 |
| 가입 직후 쿠폰만 쓰고 활동 없음 | 체리피커 |
| 짧은 시간 같은 상품 대량 주문 | 리셀 봇 |
| 같은 문구·같은 시간대 리뷰 몰림 | 리뷰 조작 |
| 실패한 로그인 폭증, 다양한 IP에서 같은 패턴 | 크리덴셜 스터핑 |

→ 처음엔 **간단한 규칙(같은 CI·기기·주소면 표시)** 으로 시작하고, 규모가 커지면 **이상 탐지(FDS, 35장)** 시스템을 둬요.

### ⑤ 제재와 회수
- 약관 근거로 **혜택 회수·주문 취소·이용 제한**. 국내에서도 중복 계정으로 신규가입 혜택을 받은 소비자에게 업체가 약관에 따라 부당이득 반환을 요청한 사례가 보도된 적이 있어요.
- **억울한 정상 손님**이 생길 수 있으니 **이의 제기 창구**(30장)와 사람의 검토 단계를 두기.
- 제재 기준과 기록을 남기기 (16장 커뮤니티 제재 기록과 같은 원리).

## 4. 게임 핵·어뷰징 대응

### ① 설계로 막기 — 가장 강력한 방어
| 원칙 | 내용 |
|---|---|
| **서버 권위** (40장) | 이동·체력·명중은 서버가 판정. 클라이언트는 입력만 → 스피드핵·순간이동·체력 조작 무력화 |
| **보이는 것만 보내기** (40장 관심 영역) | 벽 너머 적 정보를 아예 안 보내면 **월핵이 볼 데이터가 없음** |
| **중요한 계산은 서버에서** | 아이템 획득·재화 증가·뽑기 결과는 서버에서만 (20장 확률형 아이템) |
| **거래 설계** | 계정 간 아이템 거래를 제한·추적하면 작업장 수익 ↓ |

> 💡 **에임봇**은 서버 권위만으론 못 막아요. 진짜 마우스 입력처럼 보이기 때문이에요. 그래서 ②③이 필요해요.

### ② 클라이언트 안티치트
| 종류 | 설명 |
|---|---|
| **사용자 영역 안티치트** | 게임이 켜져 있을 때 메모리 변조·알려진 핵 프로그램 검사 |
| **커널 수준 안티치트** | 운영체제 깊은 곳에서 동작. 예: Riot의 **뱅가드(Vanguard)** 는 PC 부팅 때부터 드라이버가 켜지는데, Riot은 "핵이 안티치트보다 먼저 실행되는 걸 막기 위해서"라고 설명했어요. 발로란트에 이어 롤에도 도입 |
| 상용 안티치트 | 여러 게임사가 쓰는 외부 안티치트 솔루션 |

- ⚠️ 커널 안티치트는 강력하지만 **사생활·보안 우려**(권한이 매우 높은 프로그램에 결함이 있으면 위험)라는 비판도 함께 받아요. 작은 게임은 보통 서버 쪽 방어 + 상용 솔루션 조합.

### ③ 서버 쪽 탐지 — 행동으로 잡기
| 신호 | 의심 |
|---|---|
| 비정상적인 조준 정확도·반응 속도 (사람 한계를 넘는 헤드샷 비율) | 에임봇 |
| 벽 뒤 적을 계속 정확히 추적하는 시선·이동 | 월핵 |
| 24시간 같은 경로 반복, 쉬지 않는 접속 | 매크로·작업장 |
| 짧은 시간 레벨·랭크 급상승, 접속 지역·기기 변화 | 대리 게임·계정 거래 |
| 같은 두 계정끼리 반복 대전, 한쪽만 계속 패배 | 승부 조작 (20장) |
| 재화가 비정상적으로 늘어남 | 복사 버그 악용 |

- **신고 + 리플레이 검토**: 플레이어 신고가 몰린 판을 리플레이(기록)로 사람이 검토.
- **몰아서 제재(밴 웨이브)**: 업계에서 흔히, 핵을 찾자마자 바로 정지하지 않고 **모아서 한꺼번에** 제재해요. 핵 제작자가 "어떤 방법이 들켰는지" 알기 어렵게 하려는 목적이에요.

### ④ 제재 단계 예
| 단계 | 예 |
|---|---|
| 경고 | 비매너·경미한 위반 |
| 기간 정지 | 매크로·대리 게임 |
| **영구 정지** | 핵 사용 |
| 기기·하드웨어 단위 제재 | 새 계정으로 돌아오는 것 방지 (게임사별 정책) |
| 재화·아이템 회수, 랭크 초기화 | 버그 악용·작업장 |
| 법적 대응 | 핵 제작·판매자 고소 (아래) |

### ⑤ 법적 대응 (한국)
- **게임산업진흥법**은 게임사가 허용하지 않은 프로그램(핵 등)을 **제작·유통**하는 행위를 처벌해요. 해설 기사들에 따르면 **5년 이하 징역 또는 5천만 원 이하 벌금** (과거 1년·1천만 원에서 상향). 핵을 **쓰기만** 한 사람은 이 조항 대상이 아니라는 설명이 있고, 대신 **약관에 따른 계정 정지** 대상이에요.
- **대리 게임을 업으로** 하는 것은 2019년 6월부터 처벌 대상(2년 이하 징역 또는 2천만 원 이하 벌금으로 보도).
- 게임머니·아이템 **환전 업**도 금지 (20장).
- ⚠️ 정확한 조문·시행일은 국가법령정보센터에서 확인하세요. 실제 사건에서 처벌이 약하다는 지적(집행유예, 범죄수익 추징 문제)도 보도되고 있어요.

## 5. 공통 운영 원칙

| 원칙 | 설명 |
|---|---|
| **로그 없이는 아무것도 못 잡는다** | 가입·로그인·결제·혜택 지급·게임 결과를 기록 (37장, 개인정보는 최소로) |
| **규칙은 비공개로, 결과는 공개로** | 탐지 기준을 자세히 공개하면 우회당해요. 대신 "이번 주 핵 사용 계정 ○○개 정지" 같은 **결과 공지**는 정직한 이용자에게 신뢰를 줘요 |
| **오탐(억울한 제재)을 줄이기** | 자동 탐지 + 사람 검토, 이의 제기 창구, 증거 보관 |
| **정상 이용자의 불편 최소화** | 모두에게 매번 인증을 요구하기보다 **의심될 때만** 추가 확인 |
| **계속 바뀌는 싸움** | 막으면 우회법이 나와요 → 정기적으로 패턴 점검, 새 수법 공유 |
| **개인정보 균형** | 본인인증·기기 정보 수집은 목적·보관 기간을 처리방침에 (10장) |

## 6. 출시 전 어뷰징 대비 체크리스트

**서비스 공통**
- [ ] 혜택(쿠폰·적립·추천)의 "1인" 기준과 지급 조건 정하기
- [ ] 약관에 부정 이용 시 회수·제한 조항
- [ ] 가입·로그인·폼에 봇 차단(캡차·허니팟)과 속도 제한
- [ ] 관리자 계정 2단계 인증 필수, 일반 회원도 선택 제공
- [ ] 유출 비밀번호 거절, 새 기기 로그인 알림
- [ ] 혜택 지급·사용, 로그인 실패 로그
- [ ] 같은 기기·결제 수단·배송지 계정 묶음을 보는 간단한 관리자 화면
- [ ] 이의 제기 창구와 제재 기록 양식

**게임**
- [ ] 서버 권위: 이동·명중·재화·뽑기 결과는 서버 판정
- [ ] 보이는 정보만 클라이언트에 전송
- [ ] 신고 기능 + 리플레이 저장
- [ ] 비정상 통계(명중률·재화 증가·접속 패턴) 대시보드
- [ ] 제재 정책 공개(무엇을 하면 어떤 제재), 이의 제기 절차
- [ ] 안티치트 도입 검토 (규모·장르에 맞게)

---

### 이 장 요약
1. 어뷰징은 **설계로 막기 → 입구에서 막기 → 운영 중 찾기 → 제재·개선** 4단계, 목표는 **"악용 비용 > 이익"**.
2. 서비스는 **혜택 조건 설계 + 본인인증·기기 식별 + 봇 차단 + MFA·유출 비밀번호 검사**(크리덴셜 스터핑엔 MFA가 최고).
3. 게임은 **서버 권위·보이는 것만 전송**이 기본, 에임봇은 **안티치트 + 행동 탐지 + 신고·리플레이**로. 핵 제작·유통과 대리 게임 업은 **법적 처벌 대상**.
