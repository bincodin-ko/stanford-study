# 08. 개발자의 도구

코드를 "쓰는 것"만큼 중요한 게 **도구를 다루는 것**이에요. 현업 개발자의 하루는 이 도구들 사이를 오가며 지나갑니다.

---

## 1. 터미널 (명령줄) — 글자로 컴퓨터에게 명령하기

검은 화면에 명령어를 치는 곳이에요. 윈도우는 PowerShell/터미널, 맥·리눅스는 Terminal.

| 명령 (맥·리눅스) | 하는 일 | 윈도우(PowerShell)에서도 대부분 비슷하게 동작 |
|---|---|---|
| `pwd` | 지금 있는 폴더 위치 | |
| `ls` | 폴더 안 파일 목록 | `dir`도 가능 |
| `cd 폴더명` | 폴더 이동 (`cd ..` 은 위로) | |
| `mkdir 이름` | 폴더 만들기 | |
| `python3 파일.py` | 파이썬 실행 | 윈도우는 `python` 또는 `py` |
| `Ctrl + C` | 실행 중인 프로그램 멈추기 | |
| `↑` 키 | 방금 친 명령 다시 불러오기 | |

> 💡 처음엔 무섭지만, 서버 관리·Git·배포(사업 6~8장)는 대부분 터미널에서 합니다.

---

## 2. 코드 편집기 — VS Code

- **VS Code(Visual Studio Code)**: 무료, 가장 많이 쓰이는 편집기. 거의 모든 언어 지원.
- 꼭 쓰는 기능: 확장 프로그램(언어별 도우미), 자동 완성, 오류 밑줄, 내장 터미널, Git 연동
- 큰 프로젝트용 전문 도구(**IDE**): IntelliJ(자바·코틀린), Visual Studio(C#·C++), Android Studio(안드로이드), Xcode(아이폰), PyCharm(파이썬)

> **IDE** = 통합 개발 환경. 편집기 + 실행 + 디버거 + 프로젝트 관리가 한데 묶인 큰 도구.

---

## 3. Git과 GitHub — 코드의 타임머신

[사업 6장](../06-environments-and-git.md)에서 개념을 봤어요. 여기선 실제 명령어입니다.

```bash
git init                       # 이 폴더를 Git으로 관리 시작
git status                     # 무엇이 바뀌었는지 보기
git add main.py                # 저장할 파일 고르기
git commit -m "계산기 기능 추가"  # 세이브 포인트 만들기
git log --oneline              # 기록 보기
git switch -c fix-bug          # 새 갈래(브랜치) 만들고 이동
git switch main                # main으로 돌아가기
git merge fix-bug              # 갈래 합치기
git push                       # GitHub(인터넷 금고)에 올리기
git pull                       # GitHub의 최신 내용 받기
```

- **`.gitignore`** 파일: Git에 올리지 않을 파일 목록 (비밀번호 파일 `.env`, 큰 임시 파일 등)
- ⚠️ 비밀번호·API 키를 절대 커밋하지 않기 (사업 6장)

## 4. 패키지 관리자 — 남이 만든 라이브러리 설치하기

| 언어 | 패키지 관리자 | 설치 예 |
|---|---|---|
| 파이썬 | `pip` (또는 `uv`) | `pip install requests` |
| 자바스크립트 | `npm`, `pnpm`, `yarn` | `npm install express` |
| 자바 | Maven, Gradle | 설정 파일에 적음 |
| 러스트 | `cargo` | `cargo add serde` |
| Go | `go mod` | `go get ...` |

### 가상 환경 — 프로젝트마다 따로 쓰는 공구함
```bash
python3 -m venv .venv          # 이 프로젝트 전용 공간 만들기
source .venv/bin/activate      # 들어가기 (윈도우: .venv\Scripts\activate)
pip install requests
pip freeze > requirements.txt  # 설치 목록을 파일로 저장 → 다른 컴퓨터에서 똑같이 재현
```
프로젝트 A는 라이브러리 1.0, 프로젝트 B는 2.0이 필요할 때 서로 꼬이지 않게 해 줘요.

> ⚠️ **공급망 공격**: 유명한 라이브러리와 이름이 비슷한 가짜(예: `reqeusts`)를 올려 두고 실수로 설치하게 만드는 수법이 있어요. 설치 전 **이름 철자, 다운로드 수, 관리자**를 확인하세요.

## 5. 디버깅 — 벌레(버그) 잡기

**버그** = 프로그램의 잘못된 부분. **디버깅** = 버그를 찾아 고치는 일.

### 방법 1: print 찍어 보기 (가장 기본)
```python
def average(nums):
    print("DEBUG nums =", nums)      # 값이 예상과 같은지 확인
    return sum(nums) / len(nums)
```

### 방법 2: 디버거 (중급 이상 필수)
- 코드 줄 옆을 클릭해 **중단점(breakpoint)** 을 찍으면, 실행이 거기서 멈춤
- 멈춘 상태에서 **모든 변수 값**을 보고, 한 줄씩 실행해 볼 수 있음
- VS Code: 줄 번호 왼쪽 클릭 → `F5`

### 방법 3: 고무 오리 디버깅
- 책상 위 고무 오리(또는 아무에게나)에게 코드를 **한 줄씩 소리 내어 설명**하다 보면 스스로 실수를 발견하게 돼요. 진짜로 효과 있는 방법이라 개발자들 사이에서 유명해요.

### 디버깅 순서
```
1. 버그를 "항상 똑같이" 다시 일으키는 방법 찾기 (재현)
2. 범위 좁히기 (어느 함수? 어느 줄?)
3. 가설 세우기 ("이 변수가 비어 있어서일 것")
4. 확인 (print/디버거)
5. 고치고 → 같은 버그가 다시 안 생기게 테스트 추가
```

## 6. 테스트 — 코드가 맞는지 자동으로 확인

```python
# calc.py
def add(a, b):
    return a + b
```
```python
# test_calc.py
from calc import add

def test_add():
    assert add(2, 3) == 5        # assert = "이게 참이어야 한다"
    assert add(-1, 1) == 0
```
```bash
pip install pytest
pytest            # test_로 시작하는 함수를 전부 찾아 실행
```

| 테스트 종류 | 무엇을 | 비유 |
|---|---|---|
| **단위 테스트** | 함수 하나 | 부품 하나 검사 |
| **통합 테스트** | 여러 부분이 함께 | 엔진 + 바퀴 조립 검사 |
| **E2E(끝에서 끝) 테스트** | 사용자처럼 처음부터 끝까지 | 실제로 차 몰아 보기 |

> 테스트가 있으면 코드를 고칠 때 **"다른 데가 망가지지 않았나"** 를 몇 초 만에 확인할 수 있어요. [사업 7장](../07-deploy-and-update.md)의 CI(자동 테스트)가 이걸 자동으로 돌리는 장치예요.

## 7. 문서와 검색 — 개발자는 검색을 잘하는 사람

- **공식 문서**가 1순위 (파이썬 공식 문서, MDN(웹), 각 라이브러리 문서)
- 오류 메시지는 **그대로 복사해서** 검색
- 질문할 때는: ① 무엇을 하려 했는지 ② 실제로 무슨 일이 일어났는지(오류 전문) ③ 무엇을 시도해 봤는지

## 8. AI 코딩 도우미

요즘은 AI(Claude, ChatGPT, GitHub Copilot, Claude Code 등)가 코드를 설명하고, 오류를 찾고, 코드를 써 주기도 해요.

| 잘 쓰는 법 | 위험한 쓰는 법 |
|---|---|
| "이 오류가 왜 나는지 설명해 줘" | 이해 못 한 코드를 그대로 붙여 넣기 |
| "이 코드를 한 줄씩 설명해 줘" | 비밀번호·회사 비밀 코드를 그대로 붙여 넣기 |
| "테스트 코드 만들어 줘" → 직접 검토 | AI가 만든 코드를 테스트 없이 배포 |
| 내가 먼저 풀어 보고, 막힐 때 힌트 요청 | 처음부터 다 맡기기 (배우는 게 없음) |

> 💡 AI는 **그럴듯하게 틀린 코드**를 만들 때가 있어요. **"내가 설명할 수 있는 코드만 쓴다"** 를 원칙으로 하세요. 고수로 가는 길에서 AI 활용은 11장에서 더 다룹니다.

---

### 이 장 요약
1. **터미널·VS Code·Git**은 개발자의 기본 3종 세트.
2. 라이브러리는 **패키지 관리자 + 가상 환경**으로, 가짜 패키지 주의.
3. **디버깅(재현→범위 좁히기→가설→확인)** 과 **테스트**가 코드 품질을 만든다.
