컴퓨터공학 전공의 핵심 과목(운영체제, 네트워크, 컴퓨터 구조)이 이 장의 내용입니다.

## 1. 메모리 — 스택과 힙

프로그램이 쓰는 메모리는 크게 두 구역이 있어요.

| 구역 | 비유 | 특징 | 무엇이 들어가나 |
|---|---|---|---|
| **스택(Stack)** | 책상 위 메모지 | 빠름, 함수가 끝나면 자동으로 치워짐, 크기 작음 | 함수 안의 작은 변수 |
| **힙(Heap)** | 창고 | 크고 오래 쓸 수 있음, 누군가 치워야 함 | 큰 데이터, 오래 살아야 하는 객체 |

### 창고(힙)는 누가 치우나? — 언어마다 다름
| 방식 | 언어 | 설명 | 장단점 |
|---|---|---|---|
| **직접 치우기** | C, C++ | `malloc`/`free`, `new`/`delete` | 빠르고 정밀 ↔ 잊으면 **메모리 누수**, 두 번 치우면 **프로그램 터짐** |
| **청소부(가비지 컬렉터, GC)** | 자바, 파이썬, JS, Go, C# | 안 쓰는 걸 자동으로 찾아 치움 | 편하고 안전 ↔ 청소하는 동안 잠깐 멈출 수 있음 |
| **소유권 규칙** | 러스트 | 컴파일러가 "누가 주인인지" 검사해서, 주인이 사라지면 자동으로 치움 | 빠르고 안전 ↔ 배우기 어려움 |

## 2. 포인터 — 주소를 담는 변수 (C/C++)

```c
#include <stdio.h>

int main(void) {
    int apple = 10;
    int *p = &apple;     // p에는 apple의 "메모리 주소"가 들어감

    printf("%d\n", apple);   // 10
    printf("%d\n", *p);      // 10   (주소를 따라가서 값을 읽음)

    *p = 20;                 // 주소를 따라가서 값을 바꿈
    printf("%d\n", apple);   // 20
    return 0;
}
```
- `&` = "~의 주소", `*` = "주소를 따라가서"
- 비유: `apple`은 집, `p`는 **집 주소가 적힌 쪽지**. 쪽지를 따라가서 집 안 물건을 바꿀 수 있어요.

### 포인터가 위험한 이유 — C/C++ 보안 사고의 큰 원인
| 실수 | 결과 |
|---|---|
| 배열 범위 밖에 쓰기 (**버퍼 오버플로**) | 옆 메모리를 덮어씀 → 해킹 통로 |
| 이미 치운 메모리 쓰기 (**use-after-free**) | 이상한 동작, 해킹 통로 |
| 빈 주소(`NULL`) 따라가기 | 프로그램 즉시 종료 |

> 이런 문제 때문에 최근에는 보안이 중요한 곳에서 **메모리 안전한 언어**(러스트, Go, 자바 등)를 권하는 흐름이 커지고 있어요.

## 3. 동시성 — 여러 일을 한꺼번에

| 개념 | 비유 | 설명 |
|---|---|---|
| **프로세스** | 별도의 식당 | 실행 중인 프로그램 하나. 메모리를 따로 씀 |
| **스레드** | 한 식당 안의 요리사들 | 한 프로그램 안에서 동시에 일하는 실행 흐름. 메모리를 같이 씀 |
| **비동기(async)** | 한 요리사가 라면 물 올려 두고 그동안 김치 썰기 | 기다리는 시간(네트워크·파일)에 다른 일 하기 |
| **병렬** | 요리사 여러 명이 진짜 동시에 | CPU 코어 여러 개가 동시에 계산 |

### 비동기 예 (파이썬)
```python
import asyncio

async def download(name, seconds):
    print(f"{name} 다운로드 시작")
    await asyncio.sleep(seconds)          # 기다리는 동안 다른 일을 할 수 있음
    print(f"{name} 완료")

async def main():
    await asyncio.gather(
        download("사진1", 0.2),
        download("사진2", 0.1),
        download("사진3", 0.3),
    )                                     # 하나씩 하면 0.6초, 동시에 하면 약 0.3초

asyncio.run(main())
```

### 동시성의 함정
| 문제 | 설명 | 비유 |
|---|---|---|
| **경쟁 상태(race condition)** | 두 스레드가 같은 값을 동시에 바꿔서 결과가 꼬임 | 두 직원이 동시에 재고 1개 남은 상품을 판매 → 재고 -1 |
| **교착 상태(deadlock)** | 서로 상대가 가진 자원을 기다리며 영원히 멈춤 | 좁은 골목에서 마주친 두 차가 서로 비켜 주길 기다림 |
| 해결 도구 | **락(lock)**, 원자적 연산, 메시지 전달, DB 트랜잭션 | "한 번에 한 명만 들어가는 방" |

> 사업 쪽에서 보면: 쇼핑몰의 **"재고 1개 남은 상품을 두 명이 동시에 결제"** 문제가 바로 경쟁 상태예요. DB **트랜잭션**과 **락**으로 막습니다.

## 4. 운영체제(OS) — 컴퓨터의 관리인

윈도우, 맥OS, 리눅스, 안드로이드, iOS가 하는 일:
| 역할 | 설명 |
|---|---|
| **프로세스 관리** | 여러 프로그램이 CPU를 나눠 쓰게 순서 정하기(스케줄링) |
| **메모리 관리** | 프로그램마다 메모리 나눠 주기, 서로 침범 못 하게 |
| **파일 시스템** | 파일·폴더 저장 |
| **입출력·장치** | 키보드, 디스크, 네트워크 카드 다루기 |
| **권한·보안** | 사용자·프로그램별 권한 |

> 서버는 대부분 **리눅스**에서 돌아가요. 백엔드 개발자라면 리눅스 터미널 사용법(8장)이 필수예요.

## 5. 네트워크 — 컴퓨터끼리 대화하기

| 개념 | 쉬운 설명 |
|---|---|
| **IP 주소** | 인터넷상의 집 주소 (예: `142.250.0.1`) |
| **포트** | 그 집의 방 번호 (웹은 보통 443, 개발용 서버는 8000 등) |
| **DNS** | 도메인 → IP 바꿔 주는 전화번호부 (사업 5장) |
| **TCP** | 순서와 도착을 보장하는 등기 우편 (웹, 메일) |
| **UDP** | 빠르지만 일부 잃어버려도 되는 일반 우편 (영상 통화, 게임) |
| **HTTP / HTTPS** | 웹의 대화 규칙 (9장) / 암호화 버전 |
| **웹소켓** | 계속 연결된 전화선 (채팅, 실시간 게임 — 사업 20장) |
| **지연 시간(latency)** | 편지가 도착하는 데 걸리는 시간. 서울↔미국은 물리적으로 수십~100ms 이상 |

### 숫자로 보는 속도 감각 (대략적인 크기 차이)
| 작업 | 대략 |
|---|---|
| CPU 계산 한 번 | 1나노초 미만 |
| 메모리 읽기 | 약 100나노초 |
| SSD 읽기 | 수십~수백 마이크로초 |
| 같은 지역 서버 왕복 | 약 1밀리초 미만~수 밀리초 |
| 대륙 간 왕복 | 약 100밀리초 이상 |

→ **메모리는 디스크보다, 디스크는 네트워크보다 훨씬 빨라요.** 그래서 자주 쓰는 데이터를 메모리에 저장해 두는 **캐시**가 성능 개선의 핵심 도구입니다.

## 6. 성능 최적화 — 순서가 중요하다

```
1. 측정한다 (어디가 느린지 추측하지 말고 프로파일러로 잰다)
2. 알고리즘·자료구조를 바꾼다 (O(n²) → O(n log n)이 가장 효과 큼, 7장)
3. 불필요한 반복 작업을 없앤다 (DB를 반복문 안에서 여러 번 부르는 "N+1 문제" 등)
4. 캐시를 쓴다
5. 그래도 부족하면 더 빠른 언어·병렬 처리
```
> 유명한 말: **"섣부른 최적화는 모든 악의 근원이다."** 먼저 맞게 만들고, 측정한 뒤에 빠르게.

## 8. 컴퓨터 구조 맛보기

- **CPU 코어**: 동시에 일하는 요리사 수
- **캐시(L1/L2/L3)**: CPU 바로 옆의 아주 빠른 작은 메모리
- **32비트 / 64비트**: 한 번에 다루는 데이터 크기, 쓸 수 있는 메모리 양에 영향
- **GPU**: 단순한 계산을 수천 개 동시에 하는 장치 → 그래픽, **AI 학습**에 필수

---

### 이 장 요약
1. 메모리는 **스택(자동)·힙(관리 필요)**. C/C++는 직접, 자바·파이썬은 GC, 러스트는 소유권으로 관리.
2. 동시성은 빠르지만 **경쟁 상태·교착 상태**를 조심. 락·트랜잭션으로 막는다.
3. 성능은 **측정 → 알고리즘 → 캐시** 순서. 보안은 **입력을 믿지 않는 것**에서 시작.
