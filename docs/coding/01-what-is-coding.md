# 01. 코딩이란? — 컴퓨터가 일하는 방식

## 1. 코딩 = 컴퓨터에게 주는 아주 자세한 요리법

컴퓨터는 엄청 빠르지만 **스스로 생각하지 못해요.** 시키는 것만, 시킨 순서대로, 정확히 합니다.

| 사람에게 말할 때 | 컴퓨터에게 말할 때 (코드) |
|---|---|
| "라면 끓여 줘" | 1. 냄비에 물 550ml 넣기 2. 불 켜기 3. 물이 끓을 때까지 기다리기 4. 면과 스프 넣기 5. 4분 기다리기 6. 불 끄기 |

- **프로그램(Program)** = 이런 명령들을 모아 놓은 것
- **코드(Code)** = 그 명령을 컴퓨터가 알아듣는 말(프로그래밍 언어)로 쓴 글
- **코딩 / 프로그래밍** = 코드를 쓰는 일
- **개발자(Developer)** = 코드를 써서 프로그램을 만드는 사람

---

## 2. 컴퓨터 안에서 일하는 부품 4가지

| 부품 | 비유 | 하는 일 |
|---|---|---|
| **CPU** (중앙처리장치) | 요리사 | 명령을 하나씩 실행. 1초에 수십억 번 |
| **메모리 (RAM)** | 조리대 | 지금 작업 중인 재료(데이터)를 올려 둠. 빠르지만 전원 끄면 사라짐 |
| **저장장치 (SSD/HDD)** | 냉장고·창고 | 파일을 오래 보관. 메모리보다 느리지만 전원 꺼도 남음 |
| **입출력 장치** | 주문서·서빙 | 키보드·마우스(입력), 화면·스피커(출력), 네트워크 |

프로그램을 실행하면: **창고(저장장치)에서 요리법(프로그램)을 꺼내 → 조리대(메모리)에 올리고 → 요리사(CPU)가 한 줄씩 실행**합니다.

---

## 3. 컴퓨터는 0과 1만 안다

- 컴퓨터 안은 전기가 **켜짐(1) / 꺼짐(0)** 두 가지 상태뿐이에요. 이걸 **비트(bit)** 라고 해요.
- 비트 8개 = **바이트(byte)**. 영어 글자 하나 ≈ 1바이트, 한글 한 글자 ≈ 3바이트(UTF-8 기준).
- 숫자 13은 2진수로 `1101`, 글자 "A"는 정해진 번호 65(2진수 `01000001`)로 저장돼요.

| 단위 | 크기 | 감각 |
|---|---|---|
| KB (킬로바이트) | 약 1,000바이트 | 짧은 글 한 편 |
| MB (메가바이트) | 약 100만 바이트 | 사진 한 장 |
| GB (기가바이트) | 약 10억 바이트 | 영화 한 편 |
| TB (테라바이트) | 약 1조 바이트 | 노트북 저장장치 전체 |

---

## 4. 사람의 말 → 컴퓨터의 말: 번역 방법 2가지

사람이 0과 1로 코드를 쓰기는 너무 어려우니까, **사람이 읽기 쉬운 언어**로 쓰고 **번역**해서 실행해요.

| 방식 | 비유 | 어떻게 | 대표 언어 | 장점 | 단점 |
|---|---|---|---|---|---|
| **컴파일 방식** | 책 전체를 미리 번역해서 출판 | 실행 전에 코드 전체를 기계어 파일(예: `.exe`)로 변환 | C, C++, Go, Rust | **실행이 빠름**, 실행 전에 오류를 많이 잡아 줌 | 고칠 때마다 다시 번역(컴파일) 필요 |
| **인터프리터 방식** | 동시통역사 | 실행하면서 한 줄씩 번역 | 파이썬, 자바스크립트, 루비, PHP | **바로 실행해 볼 수 있음**, 배우기 쉬움 | 상대적으로 느림, 실행해 봐야 오류를 알 때가 많음 |
| **중간 방식** | 공통어로 번역해 두고 현지에서 통역 | 중간 코드(바이트코드)로 바꿔 두고, 가상 머신이 실행 | 자바, C#, 코틀린 | 여러 운영체제에서 같은 코드가 돌아감 | 가상 머신 필요 |

> 요즘은 경계가 흐려졌어요. 예를 들어 자바스크립트는 인터프리터 방식이지만, 브라우저가 자주 쓰는 부분을 실행 중에 기계어로 바꿔서(JIT 컴파일) 꽤 빠르게 돌려요.

## 5. 저수준 언어 vs 고수준 언어

| 구분 | 뜻 | 예 | 비유 |
|---|---|---|---|
| **기계어** | 0과 1 그 자체 | `10110000 01100001` | 요리사의 근육 신호 |
| **어셈블리** | 기계어에 이름표를 붙인 것 | `MOV AL, 61h` | "오른손 들어, 칼 잡아" |
| **저수준(시스템) 언어** | 메모리를 직접 다룸 | C, C++, Rust | 자세한 요리법 |
| **고수준 언어** | 사람 말에 가까움, 메모리를 알아서 관리 | 파이썬, 자바스크립트, 자바 | "라면 끓여 줘"에 가까운 요리법 |

- **저수준일수록**: 빠르고 기계를 세밀하게 제어 ↔ 어렵고 실수하기 쉬움
- **고수준일수록**: 쉽고 빨리 만듦 ↔ 상대적으로 느림, 세밀한 제어가 어려움

## 6. 코드가 실행되기까지 (파이썬 예)

```python
print("안녕하세요")
```

1. 이 한 줄을 `hello.py` 라는 파일에 저장 (저장장치)
2. 터미널에서 `python3 hello.py` 실행
3. 파이썬 프로그램(인터프리터)이 파일을 읽어서 → 컴퓨터가 할 일로 번역
4. 화면에 `안녕하세요` 출력

이게 코딩의 전부이자 시작이에요. 나머지는 전부 **"어떤 명령을, 어떤 순서로, 어떻게 묶을까"** 의 문제입니다.

## 7. 처음 시작하는 방법 (설치 없이도 가능)

| 방법 | 설명 |
|---|---|
| **브라우저에서 바로** | 온라인 코드 실행 사이트(예: 파이썬 온라인 실행기, 구글 Colab)에서 바로 쳐 보기 |
| **내 컴퓨터에 설치** | python.org에서 파이썬 설치 + 편집기 **VS Code** 설치 (8장) |
| **브라우저 개발자 도구** | 크롬에서 `F12` → Console 탭 → 자바스크립트를 바로 쳐 볼 수 있음 |

---

### 이 장 요약
1. 코딩 = 컴퓨터에게 **아주 자세한 순서**를 알려 주는 것.
2. 컴퓨터는 **0과 1**만 알아서, 사람이 쓴 코드를 **컴파일**(미리 번역) 또는 **인터프리터**(실시간 통역)로 번역한다.
3. **저수준 언어**는 빠르고 어렵고, **고수준 언어**는 쉽고 상대적으로 느리다.
