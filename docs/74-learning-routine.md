# 74. 1인 창업가·개발자의 공부와 정보 수집 루틴

> 코딩 공부 순서는 [코딩 노트](coding/README.md), 진로별 로드맵은 [코딩 12장](coding/12-career-roadmaps.md), 시간 관리는 [54장](54-burnout-and-time.md)에 있어요.

이 자료의 많은 장에 "**자주 바뀌니 공식 문서를 확인하세요**"라고 적혀 있어요. 법·세금·광고 플랫폼·AI 도구는 몇 달마다 바뀌어요. 그래서 1인 사업자에게는 **"한 번 배우기"보다 "계속 따라가는 습관"**이 더 중요해요.

---

## 1. 공부 방법 — 오래 남게 배우기

| 방법 | 하는 법 |
|---|---|
| **만들면서 배우기** | 책을 끝까지 읽기 전에 작은 것을 만들고, 막히는 곳만 찾아보기 (55장 실습) |
| **떠올려 보기** | 다 읽고 나서 책을 덮고 핵심 3가지를 적어 보기 → 기억에 훨씬 오래 남아요 (15장 퀴즈) |
| **나눠서 반복** | 하루에 몰아서보다 1일 뒤·1주 뒤·1달 뒤 다시 보기 |
| **남에게 설명하기** | 블로그 글로 쓰기 → 공부 + 콘텐츠 마케팅(63장)이 동시에 |
| **질문 노트** | 모르는 것을 바로 적고, 답을 찾으면 그 옆에 |

### AI로 공부할 때
- "설명해 줘"에서 멈추지 말고 **"나에게 문제를 내 줘"**, **"내 설명이 맞는지 틀린 곳을 지적해 줘"**까지.
- AI가 만든 코드를 그대로 붙이지 말고 **"한 줄씩 무슨 뜻인지 설명해 줘"** → 설명할 수 없는 코드는 쓰지 않기 (49장).
- 법·세금·숫자는 AI 답도 **반드시 공식 출처로 확인**. AI도 오래된 정보를 말할 수 있어요.

---

## 2. 영어 문서 읽기 — 피할 수 없다면 쉽게

개발 도구·결제·광고·AI의 **최신 공식 문서는 영어가 먼저** 나오는 경우가 많아요.

- 처음엔 **번역기 + 원문을 나란히**. 기술 용어(request, response, token, deploy)는 번역하지 말고 원문 그대로 익히기 (03장 용어 사전).
- 공식 문서는 보통 이 순서로 읽어요: **Quickstart(빠른 시작) → Guides(가이드) → API Reference(사전처럼 찾기)**. 처음부터 Reference를 다 읽지 않아요.
- 오류 메시지는 **그대로 복사해서 검색** → 영어 결과가 훨씬 많아요.
- 자주 보는 단어장 만들기: deprecated(곧 없어질 예정), breaking change(기존 것이 깨지는 변경), rate limit(호출 횟수 제한), sandbox(테스트 환경), webhook(알림 요청).

## 3. 정보 수집 — 무엇을, 어디서, 얼마나

### 꼭 따라가야 할 것 (내 사업에 직접 영향)
| 분야 | 어디서 | 얼마나 자주 |
|---|---|---|
| 내가 쓰는 도구의 변경 | 각 서비스의 **변경 이력(changelog)·공지 메일** — 가입 메일을 스팸 처리하지 말기 | 올 때마다 |
| 결제·광고 플랫폼 정책 | PG사·메타·구글·네이버·쿠팡 공지 | 월 1회 |
| 법·세금 | 국세청, 개인정보보호위원회, 공정위 보도자료, 고용노동부 | 분기 1회 + 사업 관련 뉴스 |
| 보안 | 내가 쓰는 프레임워크·라이브러리의 보안 공지, GitHub 보안 알림 | 올 때마다 |

### 넓게 보면 좋은 것
| 분야 | 예 |
|---|---|
| 1인 창업 사례 | 인디 해커스, 국내 창업 커뮤니티·뉴스레터 |
| 마케팅 | 마케팅 실무 커뮤니티, 광고 대행사 인사이트 글 (단, 업체 글은 홍보가 섞여 있다는 점 기억) |
| 개발 | 공식 블로그, 개발자 커뮤니티 |
| 내 업계 | 업계 뉴스, 경쟁사 공지·블로그 (35장 도메인 지식) |

### 정보 다이어트
- 뉴스레터·채널을 **10개 넘게 구독하면 결국 안 읽어요.** 정말 읽는 것 5개만.
- **"지금 내 사업에 쓸 수 있나?"**로 걸러요. 아니면 북마크만 하고 넘기기.
- 유행하는 도구로 매번 갈아타지 않기. 지금 도구로 **손님이 불편하지 않으면** 그대로.

## 5. 주간 공부 루틴 예시 (1인 사업자)

| 언제 | 무엇을 | 시간 |
|---|---|---|
| 월 아침 | 도구·플랫폼 공지 훑기 | 15분 |
| 화·목 저녁 | 지금 막힌 기술 하나 깊게 (만들면서) | 1시간 |
| 수 | 손님 의견 다시 읽기 (73장) — 가장 중요한 공부 | 20분 |
| 금 | 이번 주 배운 것 3줄 기록 / 블로그 글 | 30분 |
| 월 1회 | 경쟁사·업계 살펴보기, 이 자료의 관련 장 다시 보기 | 1시간 |

**공부도 사업처럼**: 목적(무엇을 해결하려고), 작게, 결과물(글·코드·개선된 페이지)로 끝내기.

### 이 장 요약
1. **만들면서, 떠올려 보며, 나눠서 반복**하고, 배운 걸 글로 써서 마케팅까지.
2. 영어 공식 문서는 **빠른 시작 → 가이드 → 레퍼런스** 순서로, 오류 메시지는 그대로 검색.
3. 내 사업에 직접 영향 주는 **도구 공지·정책·법·보안**은 꼭 따라가고, 나머지는 **5개만** 구독. 이 자료도 **분기마다 다시 확인**.
