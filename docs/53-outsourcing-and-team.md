# 53. 외주·팀·협업 관리

혼자 다 할 수는 없어요. 디자인·개발·영상·세무 등 **맡길 것은 맡기는** 게 1인 사업의 핵심 기술이에요.
26장이 "내가 외주를 받을 때"였다면, 이 장은 **"내가 외주를 맡기고, 사람과 함께 일할 때"** 예요.

> ⚠️ 2026년 11월 조사 기준. 계약은 금액이 크면 **법률 전문가 검토**를 권해요. ([참고 자료 모음](sources.md))

---

## 1. 무엇을 맡기고 무엇을 직접 할까

| 직접 하는 게 좋은 것 | 맡기기 좋은 것 |
|---|---|
| 손님 이해, 기획, 우선순위 결정 | 디자인(로고·상세 페이지), 사진·영상 촬영 |
| 가격·브랜드 결정 | 반복적인 개발 작업, 번역 |
| 핵심 지표 보기 | 세무·법률 (전문가) |
| 손님 문의 초기 응대 (손님의 목소리를 직접 듣기) | 광고 운영 대행 (규모가 커지면) |

> 💡 **사업의 핵심(손님 이해·결정)은 직접**, 시간이 많이 드는 실행은 맡기기.

---

## 2. 외주 맡기는 순서

```
1. 무엇을 원하는지 문서로 (요구사항 정의서)
2. 견적 받기: 2~3곳 이상, 포트폴리오·후기 확인
3. 계약서 작성 (3절)
4. 착수금 → 중간 확인 → 검수 → 잔금
5. 결과물·원본·계정 인수인계
6. 유지보수 계약 (필요하면)
```

### 요구사항 정의서 (한두 장이면 충분)
```
- 목적: 그래놀라 쇼핑몰 상세 페이지 디자인
- 대상: 30대 직장인, 모바일 중심
- 범위: 상세 페이지 3종 (PC·모바일), 배너 2종
- 참고: 좋아하는 사이트 3곳 링크, 싫어하는 스타일
- 제공 자료: 상품 사진, 문구 초안, 로고
- 산출물: 피그마 원본 + JPG, 폰트 라이선스 목록
- 일정: 시안 1주, 수정 2회, 최종 3주 안
- 예산: ○○만 원
```
→ 범위가 모호하면 **"이것도 해 주세요" 분쟁**(스코프 크립, 26장)이 생겨요.

### 외주처 찾기
- 재능 마켓(크몽 등), 프리랜서 플랫폼, 지인 소개, 포트폴리오 사이트
- 확인: 비슷한 작업 경험, 후기, 소통 속도, **계약서를 쓰는지**

---

## 3. 외주 계약서에 꼭 넣을 것

| 항목 | 내용 |
|---|---|
| **작업 범위** | 무엇을, 몇 개, 몇 페이지 (요구사항 정의서 첨부) |
| **일정** | 단계별 날짜, 지연 시 처리 |
| **금액·지급** | 착수금·중도금·잔금 비율과 조건 |
| **수정 횟수** | 예: 시안 수정 2회, 이후 추가 비용 |
| **검수 기준** | 무엇이 되면 "완료"인가 (50장 테스트 시나리오 활용) |
| **권리 귀속** | **저작권·소스코드·디자인 원본이 누구 것인지** 명시 (47장). 안 쓰면 분쟁 |
| **하자보수** | 완료 후 일정 기간 무상 수정 (공정위 SW 표준 하도급계약서는 무상 하자보수 기간을 1년 이내로 명문화했다는 보도) |
| **비밀 유지** | 고객 정보·사업 정보 |
| **인수인계** | 원본 파일, 계정(도메인·호스팅·관리자)은 **내 명의로** (5·34장) |
| **중도 해지** | 중간에 그만둘 때 정산 방법 |

- 과학기술정보통신부는 SW 사업용 **표준계약서**(개발 구축·유지관리 등)를 배포했다고 알려져 있어요. 민간 계약에도 참고할 수 있어요.

## 4. 외주 관리 요령

| 요령 | 설명 |
|---|---|
| **작게 먼저** | 큰 프로젝트 전에 작은 일로 함께 일해 보기 |
| **중간 확인** | 끝날 때까지 기다리지 말고 주 1회 진행 상황 |
| **피드백은 구체적으로** | "별로예요" ✕ → "버튼이 작아서 모바일에서 누르기 어려워요" ○ |
| **기록** | 요청·변경은 메신저 말고 **문서·이메일**에 남기기 |
| **개발 외주라면** | 코드는 **내 Git 저장소**에서 작업하게, 비밀 키는 직접 관리 (6·37장) |
| **검수** | 50장 시나리오로 직접 테스트한 뒤 잔금 |

---

## 5. 첫 팀원·공동 창업자

| 상황 | 확인할 것 |
|---|---|
| **공동 창업자** | 역할, **지분**, 의사결정 방식, 떠날 때 규칙(**베스팅**: 일정 기간 일해야 지분이 확정되는 방식)을 **문서로** — 친한 사이일수록 꼭 |
| **직원 채용** | 근로계약서, 4대보험, 최저임금 (44장), 채용 지원금 확인 (45장) |
| **프리랜서 상시 협업** | 업무 지시·근무 시간 통제가 강하면 근로자로 볼 수 있음 (44장) |
| **계정 권한** | 사람마다 개인 계정, 필요한 권한만, 퇴사 시 즉시 회수 (37장) |

## 6. 협업 도구

| 용도 | 예 |
|---|---|
| 할 일·일정 관리 | 노션, 트렐로, 지라, 깃허브 이슈 |
| 문서 | 노션, 구글 문서 |
| 소통 | 슬랙, 카카오톡(업무용 채널 분리) |
| 디자인 협업 | 피그마 (코멘트 기능) |
| 코드 협업 | 깃허브 (PR·코드 리뷰, 코딩 11장) |
| 비밀번호 공유 | **비밀번호 관리자의 공유 기능** (메신저로 비밀번호 보내기 ✕) |

### 혼자서도 쓰는 업무 보드
```
할 일 → 진행 중 → 검토 → 완료
- 진행 중은 최대 3개까지 (동시에 너무 많이 하면 아무것도 안 끝남)
```

---

### 이 장 요약
1. **핵심 결정은 직접, 실행은 맡기기.** 요구사항을 **문서**로 쓰고 2~3곳 견적.
2. 계약서엔 **범위·일정·금액·수정 횟수·검수 기준·권리 귀속·하자보수·인수인계**.
3. 공동 창업은 **지분·역할·떠날 때 규칙**을 문서로, 팀원은 **개인 계정·최소 권한**.
