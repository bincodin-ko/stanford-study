# 09. 매일의 운영과 장애 대응

사이트를 열고 나면 일의 대부분은 **"운영"** 입니다.
운영 = **사이트 지키기** + **손님 응대** + **주문·정산 처리** + **숫자 보고 개선하기**.

---

## 1. 운영 업무 지도

| 분야 | 하는 일 |
|---|---|
| **사이트 관리** | 살아 있는지 확인, 속도 점검, 오류 수정, 보안 업데이트 |
| **상품·콘텐츠 관리** | 상품 등록, 재고, 가격, 배너·이벤트, 품절 처리 |
| **주문·배송(CS 포함)** | 주문 확인, 출고, 송장 입력, 교환·반품·환불 |
| **고객 응대(CS)** | 문의 답변, 리뷰 관리, 불만 처리 |
| **정산·회계** | PG 정산 확인, 세금계산서, 부가세 신고 준비 |
| **마케팅** | 광고 집행, SNS, 이메일/문자 발송 |
| **데이터 분석** | 매출·전환율 보고, 개선점 찾기 |

> **CS** = Customer Service, 고객 서비스.
> **정산** = 카드 결제 대금이 PG사를 거쳐 내 통장에 들어오는 것. 보통 며칠 걸리고 수수료가 빠져요.

---

## 2. 모니터링 — 사이트를 대신 지켜보는 장치

내가 자는 동안에도 사이트가 멈췄는지 알려면 **자동 감시**가 필요합니다.

| 무엇을 보나 | 어떻게 | 도구 예 |
|---|---|---|
| **살아 있나 (업타임)** | 1~5분마다 사이트에 접속해 보고, 안 되면 문자/메신저 알림 | UptimeRobot, Better Stack 등 |
| **오류가 늘었나** | 프로그램 오류가 생기면 자동 보고 | Sentry 등 |
| **느려졌나** | 페이지 열리는 속도 | 구글 PageSpeed Insights |
| **서버가 힘든가** | CPU·메모리·디스크 사용량 | 클라우드 기본 대시보드 |
| **장사가 되고 있나** | 1시간 동안 주문 0건이면 이상 신호 | 직접 만든 알림, 매출 대시보드 |

> 💡 의외로 중요한 감시: **"평소보다 주문이 너무 적다"**. 결제 페이지만 고장 나면 사이트는 멀쩡히 열리지만 매출은 0이 됩니다.

---

## 3. 장애가 났을 때 — 5단계

```
① 알아채기   → 모니터링 알림, 손님 문의
② 알리기     → 팀에 공유, 필요하면 사이트에 "일시 장애" 공지
③ 멈추기     → 최근 배포가 있었다면 먼저 롤백 (7장)
④ 고치기     → 원인 찾고 수정
⑤ 돌아보기   → 포스트모템(사후 보고서) 작성
```

### 심각도 나누기 (예시)

| 등급 | 상황 | 대응 |
|---|---|---|
| **1급** | 사이트 전체 안 열림, 결제 불가, 개인정보 유출 의심 | 즉시, 밤이라도 |
| **2급** | 일부 기능 고장 (쿠폰 적용 안 됨) | 몇 시간 안에 |
| **3급** | 오타, 사소한 화면 깨짐 | 다음 정기 업데이트 때 |

### 포스트모템 양식 (짧게)

```
- 언제: 2026-10-20 14:05 ~ 14:40 (35분)
- 무슨 일: 결제 버튼 눌러도 반응 없음
- 영향: 주문 약 20건 실패 추정
- 원인: 결제 모듈 업데이트 후 설정값 누락
- 어떻게 고쳤나: 이전 버전으로 롤백
- 재발 방지: 배포 체크리스트에 "스테이징에서 실제 테스트 결제" 추가
```

> **포스트모템은 누구를 탓하려는 게 아니라 "구조"를 고치기 위한 것**입니다. (블레임리스, blameless)

## 4. 정기 점검 루틴

| 주기 | 할 일 |
|---|---|
| **매일** | 주문·문의 확인, 모니터링 알림 확인, 전날 매출 보기 |
| **매주** | 백업 성공 확인, 데이터 내보내기, 보안 업데이트 확인, 주간 지표 정리 |
| **매월** | 도메인·인증서·카드 만료일 확인, 쓰지 않는 계정·권한 정리, 월간 손익 |
| **분기** | **복구 훈련**, 비밀번호/키 교체, 약관·개인정보처리방침 점검 |

전체 표는 [14장 체크리스트](14-checklists.md)에 있어요.

## 5. 고객 응대(CS) 운영 팁

- **자주 묻는 질문(FAQ)** 을 먼저 만들면 문의가 크게 줄어요. (배송 기간, 교환 방법, 영수증)
- **답변 템플릿**(자주 쓰는 답장 미리 써 두기)을 만들어 두기.
- 응답 시간 목표 정하기: 예) 평일 24시간 안에 1차 답변.
- 불만 손님은 **빨리, 공감 먼저, 해결책 제시** 순서로.
- 문의 내용을 분류해서 쌓으면 → **다음 업데이트의 가장 좋은 아이디어 목록**이 됩니다.

---

## 6. 사람이 바뀌어도 돌아가게 — 운영 문서

- **운영 매뉴얼**: 주문 처리, 환불, 장애 대응 방법을 순서대로.
- **계정 목록**: 어떤 서비스에 가입했고, 누가 관리자이고, 언제 갱신하는지. (비밀번호 자체는 문서에 쓰지 말고 **비밀번호 관리자**에)
- **연락처**: 호스팅·PG·택배사 고객센터 번호.

---

### 이 장 요약
1. 운영 = 사이트 지키기 + 손님 응대 + 주문·정산 + 개선.
2. **자동 감시(모니터링)** 를 켜 두고, "주문이 너무 적은 것"도 감시한다.
3. 장애 때는 **알리기 → 롤백 → 고치기 → 돌아보기**.
