# 38. 출시 전 Claude에게 추가해 달라고 할 것들

웹사이트를 Claude 같은 AI와 함께 만들 때, **"이것도 넣어 줘"** 라고 따로 말하지 않으면 빠지기 쉬운 것들을 모았어요.
각 항목마다 **왜 필요한지 → Claude에게 보낼 말 → 직접 확인하는 법**을 적었어요. 맨 아래엔 **한 번에 복사해서 보낼 수 있는 전체 요청문**이 있어요.

> ⚠️ 2026년 10월 조사 기준. 검색 엔진 정책은 바뀌니, 구글 Search Central·네이버 서치어드바이저 도움말도 확인하세요. ([참고 자료 모음](sources.md))

## A. 첫인상과 전환

### A1. 스크롤하기 전 첫 화면에 명확한 행동 유도(CTA)
- **왜**: 닐슨 노먼 그룹 연구(2018)에서 사람들은 페이지를 볼 때 **시간의 약 57%를 스크롤 전 첫 화면**에서 보냈어요(첫 두 화면까지 합치면 약 74%). 첫 화면에서 "뭐 하는 곳인지 + 뭘 하면 되는지"가 보여야 해요.
- **Claude에게**: "첫 화면(모바일 기준)에 ① 누구를 위한 무엇인지 한 줄 제목 ② 한 줄 부연 ③ 눈에 띄는 버튼 하나('무료로 시작하기' 등) ④ 신뢰 요소 하나(후기 수·별점 등)가 스크롤 없이 보이게 해 줘. 버튼은 하나만 강조해 줘."
- **확인**: 휴대폰으로 열었을 때 스크롤 없이 버튼이 보이는지.

### A2. 모바일에서 스크롤해도 고정되는 행동 유도 버튼
- **왜**: 긴 상세 페이지를 내려 읽다가 바로 구매·문의할 수 있게.
- **Claude에게**: "모바일 화면 하단에 고정되는 버튼('구매하기'/'상담 신청')을 만들어 줘. 본문·입력창·쿠키 안내를 가리지 않게 하단 여백을 주고, 키보드가 올라오면 숨겨지게, 아이폰 하단 안전 영역(safe-area)도 고려해 줘."
- **확인**: 실제 폰에서 맨 아래 내용이 가려지지 않는지, 입력할 때 버튼이 키보드를 덮지 않는지.
- ⚠️ 화면을 덮는 큰 팝업(전면 광고)은 사용자 경험과 검색에 나쁘다는 게 정설이에요. **작은 고정 바** 정도로.

### A3. 신뢰 요소
- **Claude에게**: "후기, 고객 수, 보안 결제 표시, 환불 정책 링크, 대표 사진/회사 소개 같은 신뢰 요소를 CTA 근처에 배치해 줘. 숫자는 내가 줄 실제 값만 써 줘(지어내지 마)."
- ⚠️ 가짜 후기·부풀린 숫자는 법 위반(10·32장).

### A4. 문의 답변 시간 표시
- **왜**: "언제 답이 오나"를 알면 손님이 불안해하지 않고, 같은 문의를 여러 번 보내지 않아요 (30장).
- **Claude에게**: "문의 페이지와 폼 제출 완료 화면에 '평일 10~18시 운영, 영업일 기준 24시간 안에 답변드려요'를 넣고, 자동 회신 메일 문구도 만들어 줘."

### A5. 자주 묻는 질문(FAQ)
- **왜**: 문의가 줄고, 구매 전 불안이 풀려요 (9장).
- **Claude에게**: "배송·교환·환불·결제·계정 관련 FAQ 페이지를 접었다 펴는 형태로 만들어 줘. 질문은 손님이 실제로 쓰는 말투로. 내용은 내가 준 정책 그대로."
- 참고: 예전엔 FAQ에 구조화된 데이터를 넣으면 구글 검색에 질문 목록이 펼쳐져 보였는데, 2023년부터 크게 줄었고 2026년엔 완전히 중단됐다는 보도가 있어요. **FAQ 페이지 자체는 여전히 손님에게 유용**해요.

### A6. 감사(완료) 페이지
- **왜**: 구매·가입·문의 완료를 측정(D1)하고, 다음 행동(카톡 채널 추가, 공유)을 유도.
- **Claude에게**: "결제·가입·문의 완료 후 별도의 완료 페이지로 이동하게 하고, 다음 단계 안내와 GA4 이벤트를 넣어 줘."

## B. 검색 노출 (SEO)

### B1. 페이지마다 서로 다른 제목 (`<title>`)
- **왜**: 구글은 모든 페이지에 제목이 있고, **페이지마다 구체적으로 다르게** 쓰라고 안내해요. 같은 제목을 여러 페이지에 반복하지 말라고 해요.
- **Claude에게**: "모든 페이지에 고유한 title을 넣어 줘. 형식은 '페이지 핵심 내용 | 브랜드명', 핵심 단어를 앞쪽에. 상품·글 페이지는 상품명·글 제목이 자동으로 들어가게."
- **확인**: 브라우저 탭 제목이 페이지마다 다른지.

### B2. 검색 결과에 표시될 설명 (meta description)
- **왜**: 검색 결과에서 제목 아래 보이는 설명. 구글은 이걸 **참고**해서 설명을 고르며(항상 쓰진 않음), 클릭할지 결정하게 만드는 문구예요.
- **Claude에게**: "페이지마다 다른 meta description을 넣어 줘. 이 페이지에서 무엇을 얻는지 한두 문장으로, 너무 길지 않게. 상품 페이지는 상품 정보로 자동 생성."
- 참고: `meta keywords` 태그는 구글이 순위에 쓰지 않는다고 오래전부터 밝혀 왔어요. 굳이 안 넣어도 돼요.

### B3. 제목 구조 (h1 하나 + h2·h3 순서)
- **Claude에게**: "페이지마다 h1은 하나, 그 아래 h2·h3를 순서대로 써 줘. 글자 크기를 위해 제목 태그를 쓰지 말고 CSS로 해 줘."

### B4. 이미지 대체 텍스트 (alt)
- **왜**: 화면을 못 보는 사람이 화면 낭독기로 이미지 내용을 듣고, 검색 엔진도 이미지를 이해해요(이미지 검색 노출).
- **Claude에게**: "모든 의미 있는 이미지에 내용을 설명하는 alt를 넣어 줘(예: '그래놀라 500g 봉지 앞면'). 꾸밈용 이미지는 alt=''로 비워 줘. 키워드를 억지로 나열하지 마."

### B5. 내부 페이지 연결 (내부 링크)
- **왜**: 손님이 다음 페이지로 이어서 보고, 검색 로봇도 페이지를 빠짐없이 찾아요.
- **Claude에게**: "관련 상품·관련 글 링크, 빵부스러기 경로(홈 > 카테고리 > 상품), 푸터의 주요 페이지 링크를 넣어 줘. 링크 글자는 '여기'가 아니라 내용이 보이게('환불 정책 보기')."

### B6. robots.txt
- **왜**: 검색 로봇에게 **어디를 수집하지 말지** 알려 주는 파일. 관리자 페이지·장바구니·검색 결과 페이지 등을 빼요.
- ⚠️ **중요**: 구글은 robots.txt가 **페이지를 검색에서 숨기는 방법이 아니라고** 명시해요. 막아도 다른 곳에서 링크되면 주소가 검색에 뜰 수 있어요. 숨기려면 **noindex 태그**나 **비밀번호 보호**를 쓰고, 이때 robots.txt로 막으면 noindex를 못 읽으니 함께 쓰지 마세요.
- ⚠️ **스테이징(연습용) 사이트**는 비밀번호로 막고, **출시할 때 운영 사이트가 통째로 막혀 있지 않은지** 꼭 확인 (`Disallow: /` 실수가 흔함).
- **Claude에게**: "robots.txt를 만들어 줘: 관리자·장바구니·마이페이지·내부 검색 결과는 제외, 사이트맵 주소 포함. 숨겨야 할 페이지는 robots.txt 말고 noindex로 처리해 줘."

### B7. sitemap.xml (사이트맵)
- **왜**: 검색 엔진에 "내 사이트 페이지 목록"을 알려 줘요. 서치 콘솔·네이버 서치어드바이저에 제출.
- **Claude에게**: "공개 페이지만 담은 sitemap.xml을 자동 생성해 줘(상품·글이 추가되면 자동 반영, 수정일 포함)."

### B8. canonical (대표 주소)
- **왜**: 같은 내용이 여러 주소로 열리면(`?utm=...`, 정렬 옵션 등) 검색 엔진에 "이게 진짜 주소"라고 알려 줌.
- **Claude에게**: "모든 페이지에 자기 자신을 가리키는 canonical 태그를 넣고, 필터·정렬·UTM 주소는 대표 주소를 가리키게 해 줘."

### B9. 구조화된 데이터 (Structured Data, JSON-LD)
- **왜**: 검색 엔진이 "이건 상품이고 가격은 얼마, 별점은 몇"처럼 **내용의 종류를 정확히** 이해하게 하는 표시. 일부는 검색 결과에 별점·가격 같은 **리치 결과**로 보여요.
- **추천 종류**: Organization(회사 정보·로고), WebSite, BreadcrumbList(경로), Product(상품·가격·재고·리뷰), Article(글), LocalBusiness(동네 가게: 주소·영업시간)
- ⚠️ HowTo 리치 결과는 2023년에 중단됐고, FAQ 리치 결과도 2026년 완전 중단됐다는 보도가 있어요. 구글이 지원하는 종류는 바뀌니 **구글 검색 갤러리 문서**를 확인.
- ⚠️ 화면에 없는 내용(가짜 별점 등)을 표시하면 **스팸 정책 위반**.
- **Claude에게**: "JSON-LD로 Organization, WebSite, BreadcrumbList를 전체에, 상품 페이지엔 Product(가격·재고·실제 리뷰가 있을 때만 별점), 글엔 Article을 넣어 줘. 화면에 보이는 정보와 똑같이."
- **확인**: 구글 **리치 결과 테스트**, 스키마 검사 도구.

### B10. 맞춤형 404 오류 페이지
- **왜**: 없는 주소로 들어온 손님이 바로 나가지 않게. 동시에 서버는 **진짜 404 상태 코드**를 보내야 해요(겉만 404 화면이고 200을 보내면 검색 엔진이 헷갈림, "소프트 404").
- **Claude에게**: "브랜드 디자인의 404 페이지를 만들어 줘: '페이지를 찾을 수 없어요' 안내 + 검색창 + 인기 페이지 링크 + 홈 버튼. HTTP 상태 코드는 404로."
- **확인**: 아무 주소(`/asdfgh`)나 쳐 보기, 개발자 도구에서 상태 코드 404 확인.

### B11. 깔끔한 주소와 리디렉트
- **Claude에게**: "주소는 짧고 읽히게(`/products/granola-500g`). http→https, www→루트(또는 반대) 한쪽으로 301 리디렉트. 예전 주소를 바꾸면 새 주소로 301 리디렉트 표를 만들어 줘."

## C. 공유와 브랜드

### C1. SNS 공유 링크 썸네일 (Open Graph 태그)
- **왜**: 카카오톡·인스타 DM·페이스북·스레드에 링크를 붙였을 때 뜨는 **제목·설명·이미지 카드**. 이게 없으면 썰렁하거나 엉뚱한 이미지가 떠요.
- **넣을 태그**: `og:title`, `og:description`, `og:image`, `og:url`, `og:type`, `og:site_name` (+ X용 `twitter:card`)
- **이미지**: 가로가 긴 이미지(흔히 1200×630 사용, 카카오 개발자 포럼에선 2:1 비율 800×400 안내도 있음) — **핵심 글자는 가운데**에 두면 잘려도 안전.
- **Claude에게**: "모든 페이지에 OG 태그를 넣어 줘. 기본 공유 이미지를 하나 정하고, 상품·글 페이지는 대표 이미지가 자동으로 들어가게. og:url은 실제 공유 주소(https, 끝 슬래시까지)와 똑같이."
- **확인 & 주의 — 카카오톡 캐시**: 카카오톡은 같은 주소의 미리보기를 **일정 시간 저장(캐시)** 해 둬서, 이미지를 바꿔도 예전 게 계속 보일 수 있어요. **카카오 공유 디버거**에서 캐시를 초기화하거나, 이미지 주소에 `?v=2`처럼 버전을 붙여 바꾸는 게 확실해요. 페이스북은 **공유 디버거**로 새로고침.

### C2. 파비콘·앱 아이콘
- **Claude에게**: "브라우저 탭 아이콘(favicon), 아이폰 홈 화면 아이콘(apple-touch-icon), 웹 앱 manifest 아이콘을 만들어 줘."

### C3. 공유 버튼
- **Claude에게**: "상품·글 페이지에 '링크 복사'와 카카오톡 공유 버튼, 모바일에선 기기 공유 창(Web Share)을 띄우는 버튼을 넣어 줘." (33장: 공유가 제품 안에 있게)

## D. 측정

### D1. 구글 애널리틱스(GA4)와 핵심 이벤트
- **왜**: 몇 명이 어디서 와서 무엇을 했는지 (11장).
- 2024년 구글이 GA4의 "전환"을 **"핵심 이벤트(key events)"** 로 이름을 바꿨어요. `purchase`(구매)는 기본 핵심 이벤트이고, 리드(문의·상담 신청)는 `generate_lead` 같은 **추천 이벤트 이름**을 쓰면 보고서가 잘 정리돼요.
- **Claude에게**: "GA4를 설치하고 이벤트를 넣어 줘: 회원가입 sign_up, 문의·상담 제출 generate_lead(서버가 제출 성공을 확인한 뒤에만), 장바구니 add_to_cart, 결제 시작 begin_checkout, 구매 purchase(금액·상품 포함), CTA 버튼 클릭. 측정 ID는 환경 변수로."
- **개인정보**: 처리방침에 **분석 도구 사용(행태정보 수집)과 거부 방법**을 적어 두기 (10장). 해외 손님(특히 유럽)이 있다면 쿠키 동의 배너가 필요할 수 있어요.
- **확인**: GA4 실시간 보고서·DebugView에서 이벤트가 찍히는지.

### D2. UTM과 캠페인 추적
- **Claude에게**: "인스타·카카오·네이버 광고용 UTM 링크 만드는 규칙표를 만들어 줘" (11·32장).

### D3. 검색 엔진 등록
- **구글 서치 콘솔**: 소유 확인 → sitemap.xml 제출 → 색인 상태·검색어 확인

- **Claude에게**: "구글·네이버 소유 확인용 메타 태그를 넣을 자리를 만들고, 내가 받은 코드를 환경 변수로 넣을 수 있게 해 줘."

## 📋 Claude에게 한 번에 보내는 요청문 (복사해서 쓰기)

```
다음 웹사이트를 출시하기 전에 아래 항목을 모두 점검하고, 빠진 것은 추가해 줘.
이미 있는 건 "있음"으로, 추가한 건 무엇을 바꿨는지 목록으로 알려 줘.
실제 정보(숫자·후기·정책·연락처)는 지어내지 말고, 모르면 빈칸 표시 후 나에게 물어봐.

[사이트 정보]
- 사이트 종류: (예: 수제 그래놀라 쇼핑몰)
- 주요 손님: (예: 30대 직장인, 대부분 모바일)
- 가장 중요한 행동: (예: 구매 / 상담 신청 / 회원가입)
- 사업자 정보: 상호, 대표, 사업자번호, 통신판매업 번호, 주소, 전화, 이메일
- 문의 운영 시간·답변 목표: (예: 평일 10~18시, 24시간 안에 답변)
- 사용 중인 도구: (예: GA4 측정 ID는 환경 변수 GA_ID)

[A. 첫인상·전환]
1. 모바일 첫 화면에 한 줄 제목 + 부연 + 강조 버튼 1개 + 신뢰 요소 (스크롤 없이 보이게)
2. 모바일 하단 고정 CTA 버튼 (본문·입력창 가리지 않게, 키보드 올라오면 숨김, safe-area)
3. 신뢰 요소: 실제 후기·환불 정책·보안 결제 표시 (내가 준 값만)
4. 문의 페이지·폼 완료 화면에 운영 시간·답변 목표 시간 + 자동 회신 메일 문구
5. FAQ 페이지 (배송·교환·환불·결제·계정)
6. 구매·가입·문의 완료 페이지 + 다음 행동 안내

[B. 검색 노출]
7. 페이지마다 고유한 title ("핵심 내용 | 브랜드")
8. 페이지마다 고유한 meta description
9. 페이지당 h1 하나, h2·h3 순서
10. 의미 있는 이미지 alt, 꾸밈 이미지는 alt=""
11. 내부 링크: 관련 상품/글, 빵부스러기 경로, 푸터 링크, 설명이 담긴 링크 글자
12. robots.txt (관리자·장바구니·마이페이지·내부 검색 제외, 사이트맵 주소 포함). 숨길 페이지는 noindex. 운영 사이트 전체가 막혀 있지 않은지 확인
13. sitemap.xml 자동 생성 (공개 페이지만, 수정일 포함)
14. canonical 태그 (UTM·정렬·필터 주소는 대표 주소로)
15. JSON-LD 구조화된 데이터: Organization, WebSite, BreadcrumbList, Product 또는 Article, (가게면) LocalBusiness — 화면 내용과 동일하게
16. 맞춤형 404 페이지 (검색창·인기 링크·홈 버튼, 실제 404 상태 코드)
17. 짧고 읽히는 주소, http→https·www 통일 301 리디렉트

[C. 공유·브랜드]
18. OG 태그 (og:title, og:description, og:image, og:url, og:type, og:site_name) + twitter:card, 기본 공유 이미지(가로형, 핵심 글자는 가운데)
19. favicon, apple-touch-icon, manifest
20. 링크 복사·카카오톡 공유·기기 공유 버튼

[D. 측정]
21. GA4 + 이벤트: sign_up, generate_lead(서버 성공 후), add_to_cart, begin_checkout, purchase(금액 포함), CTA 클릭
22. UTM 링크 규칙표
23. 구글 서치 콘솔·네이버 서치어드바이저 소유 확인 태그 자리

[E. 법·신뢰·품질]
24. 개인정보처리방침·이용약관 초안 (내가 준 정보로, 분석 도구·위탁·국외 이전 포함) + 모든 페이지 푸터 링크
25. 사업자 정보 푸터

28. 접근성: 대비 4.5:1, 키보드 사용, label, button 태그
29. 보안: HTTPS 강제, 보안 헤더, 쿠키 설정, 디버그 끄기, 오류 정보 숨김, API 권한 확인, 비밀 키 환경 변수 + 보안 코드 리뷰
30. 폼 스팸 방지(허니팟·Turnstile·속도 제한), 오류 모니터링·업타임 알림 설정 방법

마지막에 내가 직접 확인해야 할 것(외부 도구 검사, 계정 등록 등)을 체크리스트로 정리해 줘.
```
