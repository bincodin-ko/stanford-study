# 30. 문의 창구와 이메일 설정

사이트를 열면 손님 문의, 신고, 제휴 제안, 광고 문의가 들어오기 시작해요.
이 장은 **"어디로 받고, 어떻게 설정하고, 어떻게 답할까"** 를 다룹니다. 광고·제휴 문의는 [31장](31-ad-and-partnership-inquiries.md)에서 따로 다뤄요.

> ⚠️ 법 내용과 메일 서비스 정책은 2026년 10월 조사 기준이에요. 실제 설정 전에는 각 서비스의 공식 도움말과 법령 원문을 확인하세요.

---

## 1. 문의 창구의 종류

| 창구 | 예 | 장점 | 단점 | 어울리는 곳 |
|---|---|---|---|---|
| **이메일** | `help@내도메인.com` | 기록이 남음, 첨부 파일, 모든 사업에 기본 | 답장이 느리다고 느낌 | **모든 사업 (필수)** |
| **문의 폼** | 사이트 안 "문의하기" 페이지 | 필요한 정보를 정해진 칸으로 받음, 스팸 줄이기 쉬움 | 폼을 만들어야 함 | 정보 사이트, B2B, 광고 문의 |
| **1:1 문의 게시판** | 쇼핑몰 마이페이지 안 | 주문과 연결돼 처리 쉬움 | 로그인 필요 | 쇼핑몰, 회원 서비스 |
| **메신저 상담** | 카카오톡 채널, 네이버 톡톡 | 손님이 익숙함, 빠름 | 실시간 응답 압박 | B2C 쇼핑몰, 예약 서비스 |
| **채팅 위젯** | 사이트 오른쪽 아래 말풍선 상담 | 바로 물어볼 수 있음, 챗봇 연결 | 유료인 경우 많음 | 쇼핑몰, SaaS |
| **전화** | 대표 번호 | 급한 문제에 빠름 | 기록이 안 남음, 시간 많이 듦 | B2B, 고가 상품, 법적 표시용 |
| **앱 안 문의** | 앱 설정 → 고객센터 | 기기·버전 정보를 자동으로 함께 받음 | 앱 개발 필요 | 앱, 게임 |
| **마켓 문의 기능** | 스마트스토어·쿠팡 상품 문의 | 마켓이 관리 | 마켓 밖 연락 유도 금지 | 오픈마켓 셀러 |
| **SNS DM** | 인스타그램 메시지 | 젊은 손님이 편해함 | 기록·관리가 흩어짐 | 크리에이터, 브랜드 |

> 💡 처음엔 **이메일 1개 + 문의 폼 1개**면 충분해요. 손님이 늘면 메신저·채팅을 더하세요. 창구가 많을수록 **놓치는 문의도 늘어나요.**

## 2. 용도별 이메일 주소 나누기

주소를 용도별로 나누면 정리하기 쉽고, 사람이 늘어도 넘겨주기 쉬워요. 처음엔 **전부 한 메일함으로 모으고**(전달 설정) 나중에 나눠도 돼요.

| 주소 예 | 용도 | 어디에 공개 |
|---|---|---|
| `help@` 또는 `support@` | 일반 고객 문의 | 사이트 하단, 고객센터 |
| `ads@` 또는 `partnership@` | 광고·제휴 제안 (31장) | 광고 문의 페이지 |
| `privacy@` | 개인정보 열람·삭제 요청 | 개인정보처리방침 (보호책임자 연락처) |
| `report@` 또는 `abuse@` | 불법 게시물·권리침해 신고 | 커뮤니티 신고 안내, 이용약관 |
| `billing@` | 결제·환불·세금계산서 | 결제 안내 페이지 |
| `press@` | 언론 문의 | 회사 소개 |
| `noreply@` | 자동 발송 메일용 (주문 확인 등) | 공개 안 함 |

> ⚠️ `noreply@`로 보낸 메일에 손님이 답장하면 아무도 못 봐요. 요즘은 자동 메일에도 **답장을 받을 수 있는 주소**를 쓰거나, 본문에 "문의는 help@…로" 를 꼭 적는 추세예요.

## 3. 도메인 이메일 만드는 법

`myshop@gmail.com` 보다 **`help@myshop.com`** 이 훨씬 믿음직해 보이고, 스팸으로도 덜 분류돼요.

### 방법 3가지

| 방법 | 예 | 비용 | 특징 |
|---|---|---|---|
| **① 업무용 메일 서비스** | Google Workspace, Microsoft 365, 네이버 웍스, Zoho Mail | 사용자당 월 이용료 (Zoho 등은 소규모 무료 요금제가 있기도 함) | 주고받기 모두 가능, 가장 안정적, **추천** |
| **② 전달(포워딩)만** | Cloudflare Email Routing, 도메인 업체의 메일 전달 기능 | 무료인 경우가 많음 | `help@myshop.com`으로 온 메일을 내 Gmail로 **받기만** 함. 보낼 때 주소 설정이 까다로움 |
| **③ 호스팅·빌더에 포함된 메일** | 웹호스팅·쇼핑몰 빌더의 메일 기능 | 상품에 포함 | 용량·기능 제한이 있을 수 있음 |

> 💡 혼자 시작한다면: **② 전달로 시작**해서 받기만 하다가, 답장을 많이 보내게 되면 **①로 옮기는** 경우가 많아요.

### 설정 순서 (① 업무용 메일 서비스 기준)
```
1. 메일 서비스 가입 → 내 도메인 입력
2. 도메인 소유 확인 (서비스가 준 TXT 기록을 DNS에 추가)
3. DNS에 MX 기록 추가 (메일을 어느 서버로 받을지)
4. DNS에 SPF · DKIM · DMARC 기록 추가 (스팸 방지 인증, 아래 4절)
5. 계정 만들기 (help@, ads@ …) 또는 별칭/그룹 설정
6. 테스트: 다른 메일(Gmail 등)에서 보내고 받아 보기
```
DNS는 [5장](05-how-websites-work.md)에서 본 "주소 → 서버 위치 전화번호부"예요. 도메인을 산 곳(또는 Cloudflare 같은 DNS 관리 서비스)의 관리 화면에서 기록을 추가해요.

## 4. 메일이 스팸함에 빠지지 않게 — SPF · DKIM · DMARC

이 세 가지는 "**이 메일은 진짜 myshop.com이 보낸 게 맞다**"는 것을 증명하는 장치예요. 없으면 내 메일이 스팸함에 가거나, 누군가 내 도메인을 사칭해서 피싱 메일을 보낼 수 있어요.

| 기록 | 비유 | 하는 일 |
|---|---|---|
| **MX** | 우편함 위치 | 내 도메인으로 오는 메일을 어느 서버가 받는지 |
| **SPF** | "이 우체국들만 우리 편지를 보냅니다" 명단 | 내 도메인 이름으로 메일을 보내도 되는 서버 목록 |
| **DKIM** | 봉투에 찍는 도장 | 메일에 전자 서명을 붙여 중간에 바뀌지 않았음을 증명 |
| **DMARC** | "도장 없는 편지는 이렇게 처리하세요" 지침 | SPF·DKIM 검사에 실패한 메일을 받는 쪽이 어떻게 처리할지, 보고서는 어디로 보낼지 |

### DNS 기록 예시 (Google Workspace를 쓴다고 가정)
```
종류   이름(호스트)          값
MX     @                    smtp.google.com          (우선순위 1)
TXT    @                    v=spf1 include:_spf.google.com ~all
TXT    google._domainkey    (메일 서비스 관리 화면에서 만들어 준 긴 DKIM 값)
TXT    _dmarc               v=DMARC1; p=none; rua=mailto:dmarc@myshop.com
```
- 위 MX 값은 조사 시점에 Google이 새 도메인에 권장한다고 안내된 값이에요. **반드시 내가 쓰는 메일 서비스가 알려 주는 값을 그대로** 넣으세요.
- **SPF는 도메인당 하나만.** 메일 발송 서비스(뉴스레터, 주문 알림 등)를 추가로 쓰면, 새 기록을 만들지 말고 기존 SPF에 `include:`를 **합쳐서** 넣어요.
- **DMARC는 `p=none`(지켜보기)으로 시작** → 보고서를 보며 문제없으면 `p=quarantine`(스팸함으로) → `p=reject`(거부)로 단계적으로 올려요.

### 대량 발송자 규칙 (Gmail · Yahoo, 2024년부터)
조사한 자료들에 따르면:
- **하루 약 5,000통 이상** Gmail로 보내는 발송자는 **SPF·DKIM·DMARC 모두** 필요해요.
- 마케팅 메일에는 **원클릭 수신거부** 기능을 넣고, 거부 요청은 **이틀 안에** 반영해야 해요.
- **스팸 신고율 0.3% 미만**을 유지해야 해요(0.1% 미만 권장). 구글 **Postmaster Tools**로 확인할 수 있어요.

> 작은 사이트라도 세 가지를 다 설정해 두는 게 기본이에요. 한 번 해 두면 거의 손댈 일이 없어요.

## 5. 자동으로 보내는 메일 — 거래 메일 vs 광고 메일

| 구분 | 예 | 수신 동의 | 보내는 도구 예 |
|---|---|---|---|
| **거래(트랜잭션) 메일** | 회원가입 인증, 비밀번호 재설정, 주문·배송 안내, 결제 영수증 | 서비스 이용에 필요한 안내라 보통 별도 광고 동의 불필요 | Amazon SES, SendGrid, Postmark, Resend 등 발송 API, 빌더 기본 기능 |
| **광고(마케팅) 메일** | 할인 쿠폰, 신상품 소개, 뉴스레터 속 광고 | **사전 동의 필수** (아래) | 스티비, 메일침프 등 뉴스레터 서비스 |

> ⚠️ 거래 메일에 슬쩍 할인 광고를 넣으면 **광고 메일로 볼 수 있어요.** 주문 안내 메일에는 주문 안내만.

### 광고 메일·문자·푸시를 보낼 때 (정보통신망법 제50조 요약)
| 규칙 | 내용 |
|---|---|
| **사전 동의** | 받는 사람의 **명시적인 사전 동의**가 필요. 이용약관에 뭉뚱그려 넣는 것만으로는 부족할 수 있음 → 회원가입 때 **"광고성 정보 수신 동의(선택)"** 를 따로 (10장) |
| **(광고) 표시** | 제목(문자는 맨 앞)에 **(광고)** 표시, 보낸 사람 이름·연락처 |
| **수신거부 방법** | 쉽게, 무료로 거부할 수 있는 방법을 넣기. 거부하려면 로그인하라고 하는 등 **방해하면 안 됨** |
| **야간 발송** | 밤 시간대(흔히 오후 9시~다음 날 오전 8시로 안내)에 보내려면 **별도 동의** 필요 |
| **동의 결과 알림** | 동의·거부·철회 의사를 받으면 **14일 안에** 처리 결과를 알려야 한다고 안내됨 |
| **2년마다 확인** | 수신 동의를 받은 날부터 **2년마다** 계속 받을지 확인 안내 |

## 6. 문의 폼 만들기

### 도구
| 방법 | 예 |
|---|---|
| 노코드 폼 서비스 | 구글 폼, Tally, Typeform 등 → 링크나 페이지에 붙이기 |
| 빌더 기본 기능 | 쇼핑몰·홈페이지 빌더의 "문의 게시판/폼" |
| 직접 개발 | HTML 폼 + 서버 + 메일 발송 API ([코딩 9장](coding/09-web-development.md)) |

### 좋은 문의 폼의 조건
1. **문의 종류를 고르게** (주문/배송, 결제/환불, 오류 신고, 광고·제휴, 기타) → 담당·우선순위 자동 분류
2. **필요한 것만 받기**: 이름(또는 닉네임), 답장 받을 이메일, 내용, (필요할 때만) 주문번호·첨부 파일
3. **개인정보 수집·이용 동의** 체크박스: 무엇을, 왜, 얼마나 보관하는지 짧게 (10장)
4. **스팸 방지**: reCAPTCHA나 Cloudflare Turnstile 같은 "로봇이 아닙니다" 확인, 또는 보이지 않는 함정 칸(허니팟)
5. **접수 확인 메시지**: "접수되었습니다. 영업일 기준 1~2일 안에 답변드려요." + 자동 회신 메일

### 문의 폼 문구 예
```
[문의 종류 ▼]  주문·배송 / 결제·환불 / 오류 신고 / 광고·제휴 / 기타
[이름]
[답변 받을 이메일]
[주문번호 (선택)]
[문의 내용]
[파일 첨부 (선택, 10MB 이하)]
☐ (필수) 문의 답변을 위해 이름·이메일을 수집하며, 처리 후 1년간 보관 뒤 파기합니다. 동의합니다.
[문의 보내기]
```
(보관 기간 등은 예시예요. 내 사업의 처리방침과 맞춰서 쓰세요.)

## 7. 문의를 처리하는 방법 — 받은 편지함에서 헬프데스크까지

| 단계 | 도구 | 이럴 때 |
|---|---|---|
| **1단계: 메일함 + 라벨** | Gmail 라벨·필터, 별표 | 혼자, 하루 10건 이하 |
| **2단계: 공유 메일함 / 그룹** | Google 그룹스, 공유 받은편지함 | 2~3명이 같이 볼 때 |
| **3단계: 헬프데스크(티켓 시스템)** | Zendesk, Freshdesk, 채널톡 등 | 문의가 많고 담당자가 여럿일 때 |

### 헬프데스크(티켓)란?
문의 하나하나에 **번호(티켓)** 를 붙여서 "누가 맡았는지, 답했는지, 해결됐는지"를 관리하는 도구예요. 이메일·채팅·폼으로 들어온 문의를 **한 화면에** 모아 줘요.

### 문의 처리 규칙 만들기
| 규칙 | 예 |
|---|---|
| **응답 목표 시간** | 평일 24시간 안에 첫 답변 (B2B 계약 고객은 SLA대로, 12장) |
| **우선순위** | 결제 오류·개인정보·불법 게시물 신고 → 가장 먼저 |
| **답변 템플릿** | 배송 지연, 환불 절차, 비밀번호 재설정 등 자주 쓰는 답장 미리 작성 |
| **자동 회신** | "접수됐어요. 영업시간은 평일 10~18시예요." |
| **넘겨주기 규칙** | 광고 문의 → ads 담당, 개인정보 요청 → 보호책임자 |
| **기록** | 문의 유형별로 쌓아서 → FAQ와 다음 업데이트의 재료로 (9장) |

### 좋은 답변의 순서
```
1. 인사 + 문의 내용 확인 ("주문번호 1234의 배송 지연 문의 주셨죠.")
2. 공감 한 줄 ("기다리시게 해서 죄송합니다.")
3. 결론 먼저 ("내일(목) 출고 예정입니다.")
4. 다음 행동 안내 (송장 번호, 환불 방법 등)
5. 추가 문의 방법
```

## 8. 사이트에 꼭 표시해야 하는 연락처

| 무엇 | 어디에 | 근거·이유 |
|---|---|---|
| 사업자 정보 + **전화번호 + 이메일** | 사이트 하단 | 전자상거래법상 통신판매업자 표시 (10장) |
| **개인정보 보호책임자** 이름·연락처 | 개인정보처리방침 | 개인정보보호법 (10장) |
| **청소년보호책임자** | 사이트 하단·약관 | 일정 규모 이상(전년도 말 기준 직전 3개월 하루 평균 이용자 10만 명 이상 등)의 정보통신서비스는 지정 의무가 있다고 안내돼요 |
| 권리침해·불법 게시물 신고 창구 | 커뮤니티 이용약관, 신고 버튼 | 정보통신망법 삭제·임시조치 (16장) |
| 앱 지원 연락처 | 앱스토어·구글플레이 등록 정보 | 앱 마켓이 지원 연락처를 요구함 (25장) |

### 개인 정보를 지키면서 연락처 공개하기
- **집 주소가 사업장 주소로 공개**되는 게 걱정되면: 공유 오피스·비상주 사무실 주소를 쓰는 사업자가 많아요(사업자등록 가능 여부는 세무서에 확인).
- **개인 휴대폰 번호** 대신 인터넷 전화나 대표 번호 서비스를 쓰는 방법이 있어요.
- 이메일 주소를 사이트에 그대로 쓰면 스팸 수집 봇이 가져가요 → **문의 폼 위주**로 받고, 주소는 이미지 대신 텍스트로 쓰되 스팸 필터를 강하게.

## 9. 이메일 보안 — 사칭·피싱 막기

| 위험 | 대비 |
|---|---|
| **업무 메일 계정 해킹** | 2단계 인증 필수 (10장), 비밀번호 공유 금지 → **그룹·위임** 기능으로 함께 보기 |
| **내 도메인 사칭 메일** | SPF·DKIM·DMARC 설정 (4절) |
| **가짜 협찬·광고 제안 메일**의 첨부 파일·링크 | 모르는 압축 파일·실행 파일 열지 않기. 크리에이터 채널 해킹의 대표 수법 (24장) |
| **"결제 정보 변경" 사기 메일** | 거래처 계좌가 바뀌었다는 메일은 **전화로 다시 확인** |
| **퇴사자 계정** | 바로 정지, 메일은 다른 담당자에게 전달 설정 |

## 10. 분야별 문의 운영 요약

| 분야 | 주된 창구 | 꼭 챙길 것 |
|---|---|---|
| 쇼핑몰 (13장) | 1:1 게시판, 카카오톡 채널, 이메일 | 주문번호로 바로 조회, 교환·환불 템플릿 |
| 오픈마켓 셀러 (23장) | **마켓 안 문의 기능** | 답변 시간이 판매자 점수에 반영, 마켓 밖 직거래 유도 금지 |
| 커뮤니티 (16장) | 신고 버튼, `report@`, 운영자 문의 게시판 | 권리침해 신고 → 삭제·임시조치 절차와 기록 |
| 정보 사이트 (17장) | 문의 폼 | 오류 제보 받기 → 글 업데이트, 광고 문의 분리 (31장) |

| 앱 (25장) | 앱 안 문의, 앱 마켓 리뷰 답변 | 마켓 등록 정보의 지원 연락처, 리뷰에 정중히 답변 |
| 강의·외주 (26장) | 이메일, 상담 예약 링크 | 견적 문의 양식(예산·일정·범위)으로 받기 |

| AI 서비스 (28장) | 앱 안 피드백 버튼 | "AI 답변이 틀렸어요" 신고 받기 → 품질 개선 |

### 이 장 요약
1. 시작은 **도메인 이메일 1개 + 문의 폼 1개**. 주소는 용도별(help·ads·privacy·report)로 나눠 한곳에 모은다.
2. 도메인 메일은 **MX + SPF + DKIM + DMARC**까지 설정해야 스팸함·사칭을 피한다.
3. 광고 메일은 **사전 동의·(광고) 표시·쉬운 수신거부·야간 별도 동의·2년마다 확인**. 문의는 응답 시간·템플릿·기록으로 관리한다.
