# 87. 사업용 연락처 만들기 — 도메인 이메일 실전과 사업용 전화번호

> 도메인 이메일의 기본(주소 나누기, 만드는 법 3가지, SPF·DKIM·DMARC 개념, 문의 처리)은 [30장](30-inquiries-and-email.md)에 있어요. 이 장은 **실제로 따라 하는 순서**와, 30장에 없던 **사업용 전화번호**를 다뤄요. DNS가 뭔지는 [86장](86-internet-fundamentals.md), 문자 발신번호 등록은 [76장](76-platform-gatekeepers.md), 사이트 하단 표시 의무는 [10장](10-security-and-law.md)에 있어요.

---

## 0. 먼저 결론 — 1인 사업자 추천 시작 세트

| 무엇 | 처음 (돈 거의 안 듦) | 손님이 늘면 |
|---|---|---|
| 이메일 | 도메인 메일 **전달(포워딩)** → 내 Gmail로 받기 | 업무용 메일 서비스(Google Workspace 등) 1계정 + 별칭 |
| 보내는 메일 | 메일 서비스의 "다른 주소로 보내기" + **SPF·DKIM·DMARC 통과 확인** | 자동 메일은 발송 서비스(Resend·Brevo 등)로 분리 |
| 전화 | **카카오톡 채널 + 문의 폼**만, 또는 **투넘버(두 번째 번호)** | 070 인터넷전화 앱 또는 **대표번호(1588류)** |
| 사이트 하단 | 상호·대표자·사업자등록번호·통신판매업 신고번호·주소·**전화·이메일** + 공정위 사업자정보 확인 링크 | 같음 |

**핵심 원칙 3가지**
1. **개인 휴대폰 번호와 개인 Gmail 주소는 공개하지 않는다.** 한 번 퍼지면 회수가 안 돼요 (사업을 접어도 전화가 와요).
2. **연락처는 "내가 바꿀 수 있는 것"으로.** 도메인 메일·두 번째 번호는 사람이 바뀌거나 서비스를 옮겨도 그대로 유지돼요.
3. **보내는 메일은 인증 통과를 눈으로 확인.** 설정만 하고 확인 안 하면, 손님 스팸함에 가 있어도 몰라요.

## 1. 도메인 이메일 — 받기만 할까, 메일함을 둘까?

| | **전달(포워딩)** | **업무용 메일함** |
|---|---|---|
| 예 | Cloudflare Email Routing, 도메인 업체의 메일 전달 | Google Workspace, Microsoft 365, 네이버 웍스, Zoho Mail |
| 비용 | 무료인 경우가 많음 | 계정당 월 이용료 (요금제마다 다름, 가입 화면에서 확인) |
| 받기 | `help@내도메인` → 내 Gmail로 전달 | 그 주소의 메일함에서 직접 |
| 보내기 | 따로 설정해야 함 (아래 3절, **까다로움**) | 그냥 됨, 인증도 서비스가 맞춰 줌 |
| 맞는 사람 | 문의가 하루 몇 통, 혼자 | 답장을 자주 보냄, 직원·외주와 나눠 봄 |

> 💡 처음엔 전달로 시작해도 충분해요. 다만 **답장을 "help@내도메인"으로 보내고 싶어지는 순간**이 메일함으로 옮길 때예요.

---

## 2. 따라 하기 A — Cloudflare Email Routing으로 받기 (무료)

도메인의 DNS를 Cloudflare에서 관리하고 있다는 전제예요 (86장의 "네임서버").

```
1. Cloudflare 대시보드 → 내 도메인 → Email → Email Routing → 시작
2. "목적지 주소"에 내 Gmail 추가 → Gmail로 온 확인 메일의 버튼 누르기
3. 규칙 추가: help@내도메인 → 내 Gmail
             (privacy@, ads@ 도 같은 Gmail로. 나중에 사람별로 나누기)
4. Cloudflare가 MX 기록과 SPF 기록을 자동으로 넣어 줌 → "추가" 누르기
   ⚠️ 이미 다른 메일 서비스의 MX가 있으면 충돌해요. 하나만 남기기
5. 다른 메일(친구 Gmail 등)에서 help@내도메인으로 보내 보기 → 내 Gmail에 오면 성공
```

- **"전체 받기(catch-all)"** 는 아무 주소(`asdf@내도메인`)나 다 받는 기능이에요. 편하지만 스팸이 늘어요. 필요한 주소만 규칙으로 만드는 게 좋아요.
- 전달 서비스는 **받기 전용**이에요. 이 상태에서 Gmail로 답장하면 손님에게는 **내 개인 Gmail 주소가 보여요.** → 3절로.

## 3. 따라 하기 B — 도메인 주소로 "보내기"

### 방법 ①: 업무용 메일함 (가장 쉬움, 추천)
Google Workspace 같은 서비스는 가입할 때 화면이 시키는 대로 하면 돼요.
```
1. 가입 → 도메인 입력 → 소유 확인용 TXT 기록 추가
2. MX 기록 추가 (서비스가 알려 주는 값 그대로, 기존 MX는 지우기)
3. SPF: 기존 SPF 기록에 그 서비스의 include: 를 "합쳐서" 넣기 (기록은 하나만!)
4. DKIM: 관리 화면에서 "DKIM 키 만들기" → 나온 TXT 기록 추가 → "인증 시작" 누르기
5. DMARC: _dmarc 이름으로 TXT 추가 (처음은 p=none)
6. 계정 1개 + 별칭(help@, privacy@, ads@)  ← 계정을 여러 개 만들면 요금이 늘어요
```

### 방법 ②: 전달 + Gmail "다른 주소에서 메일 보내기" — 함정 주의
Gmail 설정 → 계정 → "다른 주소에서 메일 보내기"로 `help@내도메인`을 추가할 수 있어요. 그런데 **Gmail 자기 발송 서버로 보내면**:
- 보낸 사람은 `help@내도메인`으로 보이지만, **봉투 주소와 DKIM 서명은 gmail.com** 이에요.
- DMARC는 "보낸 사람 주소의 도메인 = SPF나 DKIM이 통과한 도메인"(**정렬, alignment**)을 요구해요 → **DMARC 실패**, 스팸함 행 가능성이 커져요. 해설 글들에서 공통으로 지적하는 문제예요.

해결: "다른 주소에서 보내기"를 추가할 때 **SMTP 서버를 메일 발송 서비스**(SMTP2GO, Brevo, Mailjet, Resend 등 — 무료 구간이 있는 곳이 많음)로 지정하고, 그 서비스의 **도메인 인증(SPF include + DKIM 기록)** 을 내 DNS에 넣어요. 그래야 DKIM 서명이 `내도메인`으로 찍혀 정렬이 맞아요.

> 💡 이 설정이 번거롭게 느껴지면 그게 바로 **방법 ①로 갈 신호**예요. 월 몇천~1만 원대로 이 문제를 통째로 없앨 수 있어요.

### 방법 ③: 서비스가 자동으로 보내는 메일 (가입 확인·비밀번호 재설정·주문 확인)
- 사람이 쓰는 메일과 **분리**하세요: 발송 서비스 API(Resend·Postmark·SES·Brevo 등)로 보내고, 가능하면 **하위 도메인**(`mail.내도메인`, `notify.내도메인`)을 써요.
  - 이유: 자동 메일이 스팸 신고를 받아도 **사람이 쓰는 help@의 평판**이 같이 망가지지 않아요.
- 보내는 사람: `noreply@` 대신 **답장 받을 수 있는 주소**(30장 2절), 또는 본문에 "문의는 help@…" 명시.
- 광고 메일이면 정보통신망법의 **(광고) 표시·수신 동의·수신 거부** (30장 5절, 64장).

## 4. 설정이 맞는지 확인하기 — 반드시 눈으로

### 4-1. 받은 메일의 "원본 보기"
도메인 주소로 내 다른 Gmail에 메일을 보내고, 받은 쪽에서 **⋮ → 원본 보기**를 눌러요. 위쪽에 이렇게 나오면 성공이에요.
```
SPF:   PASS   (도메인 myshop.com)
DKIM:  'PASS' (도메인 myshop.com)   ← gmail.com이 아니라 "내 도메인"이어야 함
DMARC: 'PASS'
```

### 4-2. 연습용 검사기 — 기록을 붙여 넣어 점검 (실행 예제)
DNS 관리 화면에서 내 TXT 기록을 복사해 넣으면, 흔한 실수 4가지를 찾아 줘요. **인터넷 연결 없이** 글자만 봐요.
```python
"""SPF·DMARC 기록을 '붙여 넣은 글자'만으로 점검하는 연습용 검사기 (인터넷 연결 불필요)."""

import re

# DNS 조회를 일으키는 SPF 항목 — 이게 합쳐서 10개를 넘으면 SPF가 실패(permerror)해요.
LOOKUP_TERMS = {"include", "a", "mx", "ptr", "exists", "redirect"}


def check_spf(txt_records):
    """도메인(@)의 TXT 기록 목록을 받아 SPF 문제를 찾아요."""
    spf = [r for r in txt_records if r.lower().startswith("v=spf1")]
    problems = []
    if not spf:
        return ["SPF 기록이 없어요 → 'v=spf1 ... ~all' 기록 하나 추가"]
    if len(spf) > 1:
        problems.append(f"SPF 기록이 {len(spf)}개예요 → 하나로 합치세요 (여러 개면 전부 무효)")
    terms = spf[0].split()[1:]
    lookups = 0
    for t in terms:
        # "include:x" "a/24" "redirect=x" → 앞 단어(include, a, redirect)만 떼어 보기
        name = re.split(r"[:=/]", t.lstrip("+-~?").lower())[0]
        if name in LOOKUP_TERMS:
            lookups += 1
    # include: 안쪽에서도 조회가 더 일어나므로, 여기 숫자는 '최소' 개수예요.
    if lookups > 10:
        problems.append(f"DNS 조회 항목이 최소 {lookups}개 → 10개 한도 초과")
    elif lookups > 7:
        problems.append(f"DNS 조회 항목이 최소 {lookups}개 → include 안쪽까지 치면 10개를 넘기 쉬워요")
    last = terms[-1].lower() if terms else ""
    if last in ("+all", "all"):
        problems.append("'+all'은 '누구나 우리 이름으로 보내도 됨' → 절대 쓰지 마세요")
    elif last not in ("~all", "-all") and not any(t.startswith("redirect=") for t in terms):
        problems.append("끝에 '~all'(처음) 또는 '-all'(안정되면)을 붙이세요")
    return problems or ["SPF 문제 없음"]


def check_dmarc(txt):
    """_dmarc 이름의 TXT 기록 하나를 받아 점검해요."""
    if not txt or not txt.startswith("v=DMARC1"):
        return ["DMARC 기록이 없거나 'v=DMARC1'로 시작하지 않아요"]
    tags = dict(p.strip().split("=", 1) for p in txt.split(";") if "=" in p)
    problems = []
    policy = tags.get("p")
    if policy not in ("none", "quarantine", "reject"):
        problems.append("p= 값이 없거나 틀려요 (none → quarantine → reject 순서로)")
    elif policy == "none":
        problems.append("p=none은 '지켜보기'예요. 보고서로 확인 후 quarantine으로 올리세요")
    if "rua" not in tags:
        problems.append("rua=mailto:… 가 없으면 보고서를 못 받아요")
    return problems or ["DMARC 문제 없음"]


def read_auth_results(header):
    """받은 메일의 Authentication-Results 줄에서 spf/dkim/dmarc 결과만 뽑아요."""
    return {k: v for k, v in re.findall(r"\b(spf|dkim|dmarc)=(\w+)", header.lower())}


if __name__ == "__main__":
    cases = {
        "좋은 예": ["v=spf1 include:_spf.google.com include:_spf.mx.cloudflare.net ~all",
                   "google-site-verification=abc"],
        "두 개로 나뉨": ["v=spf1 include:_spf.google.com ~all",
                     "v=spf1 include:sendgrid.net ~all"],
        "너무 많은 include": ["v=spf1 " + " ".join(f"include:s{i}.example" for i in range(11)) + " -all"],
        "+all 사용": ["v=spf1 mx +all"],
        "없음": ["google-site-verification=abc"],
    }
    for name, recs in cases.items():
        print(f"[SPF] {name}: " + " / ".join(check_spf(recs)))
    print("[DMARC] 시작 단계:", " / ".join(check_dmarc("v=DMARC1; p=none; rua=mailto:dmarc@myshop.com")))
    print("[DMARC] 완성:", " / ".join(check_dmarc("v=DMARC1; p=reject; rua=mailto:dmarc@myshop.com")))
    print("[DMARC] 보고서 없음:", " / ".join(check_dmarc("v=DMARC1; p=quarantine")))
    hdr = ("Authentication-Results: mx.google.com; dkim=pass header.i=@myshop.com; "
           "spf=pass smtp.mailfrom=myshop.com; dmarc=pass (p=NONE) header.from=myshop.com")
    print("[받은 메일 헤더]", read_auth_results(hdr))
```
실행 결과 (`python3 mailcheck.py`):
```
[SPF] 좋은 예: SPF 문제 없음
[SPF] 두 개로 나뉨: SPF 기록이 2개예요 → 하나로 합치세요 (여러 개면 전부 무효)
[SPF] 너무 많은 include: DNS 조회 항목이 최소 11개 → 10개 한도 초과
[SPF] +all 사용: '+all'은 '누구나 우리 이름으로 보내도 됨' → 절대 쓰지 마세요
[SPF] 없음: SPF 기록이 없어요 → 'v=spf1 ... ~all' 기록 하나 추가
[DMARC] 시작 단계: p=none은 '지켜보기'예요. 보고서로 확인 후 quarantine으로 올리세요
[DMARC] 완성: DMARC 문제 없음
[DMARC] 보고서 없음: rua=mailto:… 가 없으면 보고서를 못 받아요
[받은 메일 헤더] {'dkim': 'pass', 'spf': 'pass', 'dmarc': 'pass'}
```
| 실수 | 왜 문제 | 고치기 |
|---|---|---|
| **SPF 기록 2개** | 규칙상 여러 개면 **전부 무효(permerror)** 처리돼요. 서비스를 하나 추가할 때마다 새 기록을 만드는 실수가 가장 흔해요 | 하나에 `include:`를 이어 붙이기 |
| **DNS 조회 10개 초과** | SPF 검사 중 DNS를 10번 넘게 찾게 되면 실패해요. `include:` 안쪽의 조회도 세요(그래서 이 검사기 숫자는 "최소") | 안 쓰는 서비스 include 빼기 |
| **`+all`** | "누구나 우리 이름으로 보내도 됨" → 사칭 메일 허용 | `~all`로 시작, 안정되면 `-all` |
| **DMARC `rua` 없음** | 누가 내 도메인으로 보내는지(사칭 포함) 보고서를 못 받아요 | `rua=mailto:dmarc@내도메인` |

> 실제 DNS를 조회해서 확인하려면: 터미널에서 `dig +short TXT myshop.com`, `dig +short TXT _dmarc.myshop.com` (86장의 DNS 조회). 온라인 점검 도구(MXToolbox 등)도 있어요.

### 4-3. DMARC를 단계적으로 올리기
```
1~2주:  p=none        보고서(rua)만 받기 — 내 메일이 다 PASS인지 확인
그다음: p=quarantine  실패한 메일은 스팸함으로
안정되면: p=reject    실패한 메일은 거부 → 누가 내 도메인을 사칭해도 손님에게 안 감
```
- 보고서는 기계가 읽는 XML이라 사람이 보기 힘들어요. 무료 보고서 요약 서비스가 여러 곳 있어요(요금·개인정보 처리 조건 확인).

## 5. 역할 주소 — 무엇을 만들고 어디에 쓰나

30장 2절의 주소에 더해, 실무에서 자주 빠뜨리는 것들이에요.

| 주소 | 쓰는 곳 | 왜 |
|---|---|---|
| `security@` | 사이트의 `/.well-known/security.txt` | 취약점을 발견한 사람이 연락할 곳 (82·83장) |
| `dmarc@` | DMARC `rua=` | 보고서 받기 (메일함을 따로 두거나 필터로 분리) |
| `privacy@` | 개인정보처리방침의 보호책임자 연락처 | 열람·삭제 요청 (10장) |
| `billing@` | 결제 서비스·세금계산서 | 결제사·국세청 관련 메일을 놓치지 않게 |
| `admin@` 또는 개인 계정 | **도메인 업체·호스팅·결제사 가입용** (공개 안 함) | 공개된 help@로 가입하면, 그 주소를 노린 피싱이 계정 탈취로 이어질 수 있어요 |

`security.txt` 예 (사이트의 `/.well-known/security.txt`에 올리는 글자 파일):
```
Contact: mailto:security@myshop.com
Expires: 2027-11-30T00:00:00.000Z
Preferred-Languages: ko, en
```
- `Expires`는 꼭 넣고, 지나기 전에 날짜를 갱신해요.

> ⚠️ **도메인 자체를 지키는 게 이메일보다 먼저예요.** 도메인 갱신을 놓치면 메일·사이트가 같이 멈추고, 남이 그 도메인을 사서 내 손님 메일을 받을 수도 있어요 → **자동 갱신 + 결제 카드 유효기간 확인 + 도메인 업체 계정 2단계 인증** (37장).

## 6. 사업용 전화번호 — 종류와 고르는 법

### 6-1. 종류 한눈에 보기 (조사 시점 공개 자료 기준, 요금은 바뀔 수 있음)

| 종류 | 생김새 | 어떻게 동작 | 비용 감각 | 장점 | 단점 |
|---|---|---|---|---|---|
| **투넘버 / 듀얼번호** | 010-xxxx-xxxx (두 번째 번호) | 내 휴대폰 하나에 번호를 하나 더 붙임 | 통신사 부가서비스 월 몇천 원대 (예: KT 듀얼번호·LG U+ 듀얼넘버·SKT 넘버플러스 계열, 2026년 SKT "마이투넘버" 출시 보도) | 가장 쉬움, 개인 번호 숨김, 업무 시간 끄기 가능 | 두 번째 번호로 걸 때 **앞에 특수번호**(통신사마다 다름)를 눌러야 하는 방식이 있음, 통신사 바꾸면 유지 어려움 |
| **070 인터넷전화** | 070-xxxx-xxxx | 인터넷으로 통화, 앱·전화기 | 월 기본료 수천 원대 + 통화료 (상품·자료마다 금액 차이 큼) | 앱으로 어디서나, 통화 녹음·착신 전환 기능 상품 많음 | **"070 = 광고 전화" 인식**이 있어 손님이 안 받기도 함 |
| **050 안심번호 (평생번호)** | 0505-xxx-xxxx 등 | 가상 번호로 받으면 내 진짜 번호로 연결 | 개인용은 월 1천 원대 상품이 있음 (KT 안심번호 월 1,100원 안내), 사업자용은 업체마다 | 내 번호 완전 숨김, 주문·배달·중고거래에 흔함 | **받기 전용**인 상품이 많음 (그 번호로 걸 수 없음) |
| **대표번호** | 1588·1544·1644·1661·1800-xxxx | 하나의 번호로 여러 전화기에 연결, 안내 멘트·시간대별 연결 | 회선당 월 1만 원 안팎 + 통화료 (LG U+ 공개 요금 기준 월 11,000원) | 가장 "회사" 같아 보임, 사람이 늘어도 번호 유지 | **손님 통화료 부담**(무제한 요금제에 포함 안 되는 경우가 많음) → 손님 불만, 1인 초기엔 과함 |
| **카카오톡 채널** | (번호 아님) | 카톡으로 문의·상담 | 기본 무료 (메시지 발송은 유료) | 손님이 가장 편해함, 기록이 남음 | 전화 표시 의무를 대신하진 못함 (아래 7절) |

> 대표번호 종류별 요금 구조: "기본형"은 **손님이 통화료를 내고**(시외 요금 수준), "분리과금형/수신자 부담"은 **사업자가 냄** 이라고 통신사 상품 안내에 나와요. 1800·080 계열이 사업자 부담 쪽이에요. 정확한 조건은 가입 전 통신사에 확인하세요.

### 6-2. 상황별 추천
| 내 상황 | 추천 |
|---|---|
| 혼자, 온라인 서비스(SaaS·앱·콘텐츠), 전화 문의 거의 없음 | **투넘버** 하나 + 사이트엔 문의 폼·카카오톡 채널을 먼저 보이게 |
| 쇼핑몰, 배송·교환 전화가 꽤 옴 | **070 앱**(녹음·착신 전환) 또는 투넘버 + 업무 시간 안내 |
| 배달·예약·중고 등 손님과 1:1 통화가 많음 | **050 안심번호** (내 번호 숨김) |
| 직원·외주가 생겨 전화를 나눠 받아야 함 | **대표번호** 또는 여러 명이 받는 070 상품 |

### 6-3. 전화 운영 규칙 — 번호보다 중요해요
- **업무 시간을 사이트에 적기**: "평일 10~17시 (점심 12~13시), 그 외엔 카톡·메일로 남겨 주세요". 그리고 업무 시간 밖엔 **번호를 꺼 두기**(투넘버·070 앱 대부분 가능) — 54장 번아웃 방지.
- **부재중 안내 멘트·자동 문자**: "지금은 통화가 어려워요. 문의 폼 주소 …" → 놓친 손님을 다른 창구로.
- **통화 녹음**: 상품에 녹음 기능이 있어도, 녹음한다면 **통화 시작 때 안내**하는 게 분쟁·개인정보 면에서 안전해요. 녹음 파일도 **개인정보**라 보관 기간·접근자를 정해 두세요 (10장).
- **스팸 번호로 찍히지 않게**: 짧은 시간에 많은 번호로 거는 패턴은 통신사·스팸 차단 앱에서 "광고"로 분류되기 쉬워요. 먼저 걸기보다 **받는 창구**로 쓰고, 단체 연락은 문자·알림톡(64장)으로.
- **문자 발송에 이 번호를 쓰려면** 문자 서비스에 **발신번호 사전 등록**(통신서비스 이용증명원 등 서류)이 필요해요 → 76장. 투넘버·070 번호도 등록 가능한지 문자 서비스에 확인하세요.

## 7. 사이트에 연락처를 "표시해야 하는" 이유와 모양

통신판매(온라인으로 물건·서비스를 파는 것)를 하면 **전자상거래법 제10조**와 그 시행령·시행규칙에 따라 **사이버몰 첫 화면**에 사업자 신원 정보를 표시하고, **공정거래위원회 사업자정보 공개 페이지로 연결**해야 한다고 안내돼요. 2025년에도 표시 의무 위반으로 과태료를 받은 사례가 보도됐어요(해외 사업자 포함).

### 하단(푸터) 예시 — 그대로 고쳐 쓰기
```
상호: 한바퀴 | 대표: 홍길동 | 사업자등록번호: 123-45-67890 [사업자정보 확인]
통신판매업 신고: 제2026-서울○○-0000호 | 주소: 서울시 ○○구 ○○로 00, 0층 (공유오피스)
전화: 010-0000-0000 (평일 10~17시) | 이메일: help@hanbakwi.com
개인정보 보호책임자: 홍길동 (privacy@hanbakwi.com) | 호스팅 제공: ○○
이용약관 · 개인정보처리방침 · 환불 정책
```
- `[사업자정보 확인]` = 공정위 사업자정보 공개 페이지로 가는 링크.
- 여기 적는 **전화**가 개인 휴대폰이면 영원히 공개돼요 → 6절의 두 번째 번호를 쓰세요.
- **주소**도 공개돼요. 집 주소가 걱정되면 공유 오피스·비상주 사무실 (30장 8절, 사업자등록 가능 여부는 세무서에 확인).
- 이메일은 사이트·약관·개인정보처리방침·앱스토어 등록 정보에서 **같은 주소**로 맞춰 두면 손님이 덜 헷갈려요.
- 숫자 하나라도 틀리면(신고번호·사업자번호) 신뢰가 떨어지고 단속 대상이 될 수 있어요. 바뀌면 **즉시 같이 고치기**.

> ⚠️ 어떤 정보가 필수인지는 업종·판매 방식(통신판매업 신고 대상인지, 면제인지)에 따라 달라요. 10장과 공정위 안내를 확인하고, 애매하면 관할 구청(통신판매업 신고 창구)이나 전문가에게 물어보세요.

## 8. 체크리스트 — 출시 전에 하나씩

| # | 확인 | ✅ |
|---|---|---|
| 1 | `help@내도메인`으로 메일을 보내면 내가 받는다 | |
| 2 | 내가 `help@내도메인`으로 보낸 메일의 원본에서 **SPF·DKIM·DMARC 모두 PASS**, DKIM 도메인이 **내 도메인** | |
| 3 | SPF 기록이 **하나**, `+all` 없음, 위 검사기로 문제 없음 | |
| 4 | DMARC `p=none` + `rua` 설정, 2주 뒤 `quarantine`으로 올릴 날짜를 달력에 적음 | |
| 5 | 자동 발송 메일(가입·비밀번호)은 발송 서비스·하위 도메인으로 분리, 답장 가능한 주소 | |
| 6 | `privacy@`·`security@`(+ security.txt) 준비, 가입용 관리 주소는 공개 주소와 분리 | |
| 7 | 도메인 **자동 갱신**, 도메인·메일·호스팅 계정 **2단계 인증** | |
| 8 | 공개용 전화번호는 **개인 번호가 아님**, 업무 시간·부재 안내 설정 | |
| 9 | 사이트 하단에 신원 정보 + 전화 + 이메일 + 공정위 확인 링크, 약관·방침과 같은 값 | |
| 10 | 문자를 보낼 계획이면 발신번호 등록 신청 완료 (76장) | |

> 💡 Claude에게 맡길 때: "내 도메인 DNS 기록을 붙여 넣을게. 메일 받기는 Cloudflare Email Routing, 보내기는 Google Workspace, 자동 메일은 Resend를 써. SPF를 하나로 합친 값과 빠진 기록을 알려 주고, 바꾸기 전에 지금 무엇이 깨질 수 있는지도 말해 줘." (기록 값 자체는 공개 정보지만, **도메인 업체 비밀번호·API 키는 붙여 넣지 마세요**.)

---

### 이 장 요약
1. **개인 번호·개인 메일은 공개하지 않는다** — 도메인 메일 + 두 번째 번호.
2. 메일은 **전달로 받기 → 답장이 많아지면 업무용 메일함**. Gmail "다른 주소로 보내기"는 **DMARC 정렬** 함정이 있으니 발송 서비스 SMTP를 쓰거나 메일함으로.
3. **SPF 하나·조회 10개 이하·`~all`/`-all`, DKIM은 내 도메인 서명, DMARC는 none → quarantine → reject.** 원본 보기로 PASS를 눈으로 확인.
4. 전화는 **투넘버(가장 쉬움) / 070(앱·녹음) / 050(번호 숨김) / 대표번호(회사형, 손님 통화료 주의)** 중 상황에 맞게. 업무 시간·부재 안내·녹음 고지.
5. 통신판매를 하면 **사이트 첫 화면에 신원 정보 + 공정위 확인 링크**. 값이 바뀌면 모든 곳을 같이 고치기.
