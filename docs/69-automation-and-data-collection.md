# 69. 업무 자동화 도구와 데이터 모으기 (크롤링·공공데이터)

> 1인 사업자의 시간 관리는 [54장](54-burnout-and-time.md), 예약 작업은 [66장](66-common-service-features.md), 정보 사이트의 저작권은 [17장](17-info-sites.md)에 있어요.

> 프록시·동적 딜레이(예의 바른 수집기 실습)·브라우저 자동화를 바르게 쓰는 법과 하지 말아야 할 것은 [85장](85-proxy-delay-browser-automation.md)에 있어요.

---

## 1. 코드 없이 자동화하기 — 노코드 자동화 도구

**자동화 도구** = "A가 일어나면 B를 해라"를 화면에서 블록 연결하듯 만드는 도구예요.

| 도구 | 특징 |
|---|---|
| **Zapier (재피어)** | 가장 쉬움, 연결되는 서비스가 매우 많음, 많이 쓰면 비쌈 |
| **Make (메이크)** | 복잡한 흐름을 그림처럼, 비교적 저렴 |
| **n8n** | 공개 소스, **내 서버에 설치** 가능(설치·관리는 내 몫), 개발자 친화적 |
| 각 서비스의 자체 자동화 | 노션·구글 시트·슬랙·쇼핑몰 빌더의 기본 자동화 기능 |

### 1인 사업자에게 쓸모 있는 자동화 예
| 언제 (트리거) | 무엇을 (동작) |
|---|---|
| 새 주문 | 구글 시트에 한 줄 추가 + 휴대폰으로 알림 |
| 문의 폼 제출 | 노션 문의 보드에 카드 생성 + 자동 접수 메일 |
| 새 리뷰 | 슬랙·카톡 알림, 별점 2점 이하면 "급함" 표시 (56장 위기 대응) |
| 매주 월요일 | 지난주 매출·광고비를 모아 나에게 메일 (61장) |
| 새 블로그 글 | SNS에 자동 공유 (63장 재활용) |
| 계약서 서명 완료 | 폴더 정리 + 입금 요청서 발송 |

### 주의할 점
- **개인정보가 지나가는 길**이 늘어나요. 자동화 도구도 **처리 위탁**에 해당할 수 있으니 개인정보처리방침 확인(10장), 꼭 필요한 정보만 넘기기.
- 연결에 쓰는 **계정·키 관리**: 2단계 인증, 퇴사자 접근 회수 (37장).
- **조용히 멈추는 자동화**가 가장 위험해요. 실패 알림 켜기 (66장).
- 자동화가 10개를 넘으면 **목록 문서**(무엇이·언제·어디로)를 만드세요 (56장 운영 문서).
- 사용량이 늘면 요금이 빠르게 올라요. 많이 쓰는 흐름은 나중에 **직접 코드로**(66장 예약 작업) 옮기는 걸 고려.

> 💡 Claude에게 자동화를 맡길 때: "새 주문이 오면 구글 시트에 추가하는 Make 시나리오를 단계별로 설명해 줘. 손님 전화번호는 넘기지 말고 주문번호·금액·상품만."

## 2. 공공데이터·오픈 API — 합법적으로 데이터 얻기

남의 사이트를 긁기 전에 **공식으로 제공하는 데이터**가 있는지 먼저 찾으세요.

| 곳 | 예 |
|---|---|
| **공공데이터포털** (data.go.kr) | 날씨, 교통, 부동산 실거래가, 사업자 상태 조회, 각종 통계 |
| 지자체·기관 열린 데이터 | 서울 열린데이터광장 등 |
| 기업 오픈 API | 지도, 검색, 쇼핑, 번역 등 (회원가입 후 키 발급) |
| 통계 사이트 | 통계청 KOSIS 등 |

- 데이터마다 **이용 조건(출처 표시, 상업 이용 가능 여부, 호출 횟수 제한)**이 달라요. 꼭 읽어 보세요.
- API 키는 서버에만 (37장), 호출 결과는 **저장해 두고(캐시)** 필요할 때만 새로 받기 → 횟수 제한·속도 문제 해결.
- 19장 로또 통계, 17장 정보 사이트, 55장 계산기 사이트에 바로 쓸 수 있어요.

## 3. 크롤링(스크래핑) — 할 수 있지만 조심해서

**크롤링** = 프로그램이 웹페이지를 자동으로 열어 정보를 모으는 것이에요.

### 국내 대표 판례 — 야놀자 vs 여기어때 (기사·변호사 칼럼 기준)
| 구분 | 결과 |
|---|---|
| **형사** (정보통신망 침입, 데이터베이스권 침해 등) | 2022년 대법원 **무죄** 확정. 공개된 정보를 일부 수집한 점, 크롤링을 막는 조치가 충분하지 않았던 점 등이 고려됐다고 해설돼요 |
| **민사** (손해배상) | 항소심에서 **데이터베이스 제작자 권리 침해·부정경쟁행위**가 인정돼 배상 판결(기사 기준 10억 원) |

→ **"형사 처벌을 피했다"와 "해도 된다"는 달라요.** 돈을 물어 줄 수 있어요.

### 크롤링 전 체크리스트
| 확인 | 왜 |
|---|---|
| 공식 API나 공공데이터가 있나? | 있으면 그걸 쓰기 |
| 이용약관에 자동 수집 금지가 있나? | 위반 시 계약 위반·민사 책임 근거 |
| robots.txt에서 막아 둔 곳인가? | 사이트 주인의 의사 표시 (38장) |
| **로그인해야 보이는 정보**인가? | 접근 권한 문제가 커져요. 피하기 |
| 남의 **데이터베이스를 통째로·반복적으로** 가져와 경쟁 서비스를 만드나? | 위 판례의 민사 쟁점. 가장 위험 |
| **개인정보**(이름·연락처·사진)가 섞여 있나? | 공개돼 있어도 수집·이용에 개인정보보호법 문제 |
| 글·사진을 **그대로 다시 게시**하나? | 저작권 침해 (17·47장) |
| 상대 서버에 **부담**을 주나? | 너무 잦은 요청은 업무방해·차단 대상. 요청 간격 두기 |

비교적 안전한 쪽: 공개된 **사실 정보**(가격·일정)를 **적은 양**, **느린 속도로**, 출처를 밝히고, **원문 링크로 보내 주는** 방식.

> ⚠️ 판례 해석은 기사·칼럼 기준이에요. 크롤링이 사업의 핵심이라면 **시작 전에 변호사 상담**을 받으세요.

---

### 이 장 요약
1. 반복 업무는 **Zapier·Make·n8n**으로 자동화하되, **개인정보 최소 전달·실패 알림·자동화 목록 문서**.
2. 데이터는 **공공데이터·오픈 API**부터, 이용 조건 확인 + 결과 캐시.
3. 크롤링은 **약관·robots.txt·로그인 여부·개인정보·저작권·서버 부담**을 확인. 형사 무죄 판례가 있어도 **민사 배상**은 별개.
