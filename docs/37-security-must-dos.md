# 37. 꼭 해야 하는 보안 — 출시 전·운영 중 체크리스트

> 시스템을 뚫는 공격이 아니라 **규칙을 악용하는 어뷰징·게임 핵**은 [41장](41-abuse-and-cheat-prevention.md)에서 다뤄요.

10장에서 보안 기본 10가지를 봤어요. 이 장은 **"실제로 무엇을, 어떤 순서로 설정하나"** 를 빌더 사용자와 직접 개발자로 나눠 정리했어요.

> ⚠️ 2026년 10월 조사 기준. 개인정보 관련 의무는 사업 규모·업종마다 다르니 개인정보보호위원회 안내서로 확인하세요. ([참고 자료 모음](sources.md))

---

## 1. 웹 보안 위험 순위 — OWASP Top 10 (2025)

**OWASP**는 웹 보안 비영리 단체이고, 몇 년마다 "가장 흔하고 위험한 웹 취약점 10가지"를 발표해요. 2025년판(2025년 11월 공개, 일부 자료는 2026년 1월 최종본이라고 소개)은 이래요.

| 순위 | 이름 | 쉬운 뜻 | 막는 법 |
|---|---|---|---|
| A01 | **접근 권한 실패** | 남의 주문·회원 정보를 주소만 바꿔서 볼 수 있음 | 서버에서 매번 "이 사람이 이 데이터의 주인인가" 확인 |
| A02 | **보안 설정 오류** | 기본 비밀번호 그대로, 관리자 페이지 공개, 오류 화면에 내부 정보 노출 | 출시 전 설정 점검표 (아래) |
| A03 | **소프트웨어 공급망 실패** (신규) | 내가 쓰는 라이브러리·플러그인·도구가 오염되거나 오래됨 | 검증된 것만, 정기 업데이트, 자동 취약점 알림 |
| A04 | **암호화 실패** | 비밀번호를 그대로 저장, HTTP로 통신 | HTTPS, 비밀번호 해시, 민감 정보 암호화 |
| A05 | **인젝션** | SQL 인젝션 등 입력값으로 명령 실행 | 자리표시자 사용 ([코딩 9장](coding/09-web-development.md)) |
| A06 | **안전하지 않은 설계** | 처음부터 보안을 고려하지 않은 구조 | 기획 단계부터 "악용하면?" 질문 |
| A07 | **인증 실패** | 비밀번호 무한 시도 가능, 세션 관리 허술 | 로그인 시도 제한, 2단계 인증 |
| A08 | **소프트웨어·데이터 무결성 실패** | 검증 안 된 업데이트·데이터를 믿음 | 서명·출처 확인 |
| A09 | **로그·알림 실패** | 해킹당해도 모름 | 로그 남기기 + 이상 알림 |
| A10 | **예외 상황 처리 실패** (신규) | 오류가 났을 때 엉뚱하게 동작하거나 정보가 샘 | 오류 처리 꼼꼼히, 오류 화면엔 내부 정보 숨기기 |

> 💡 **1위가 "권한 확인 실패"** 예요. "로그인한 사람"인지만 보고 "**그 데이터의 주인**"인지 안 보는 실수가 가장 흔해요. 예: `/orders/1001`을 `/orders/1002`로 바꾸면 남의 주문이 보이는 경우.

## 2. 누구나 해야 하는 것 (빌더 사용자 포함)

| # | 할 일 | 확인 방법 |
|---|---|---|
| 1 | **모든 관리자 계정 2단계 인증** (빌더, 도메인 업체, 호스팅, 이메일, PG, SNS, 광고 계정) | 계정 목록 문서에 2FA 여부 칸 (9장) |
| 2 | **비밀번호 관리자** 사용, 서비스마다 다른 긴 비밀번호 | |
| 3 | **공유 계정 금지** → 직원마다 개인 계정 + 필요한 권한만 | 퇴사 시 바로 삭제 |
| 4 | **HTTPS** 강제 (http로 들어오면 https로 이동) | 주소창 자물쇠 |
| 5 | **플러그인·앱·테마 최소화 + 업데이트** | 안 쓰는 건 삭제 |
| 6 | **백업 + 복구 훈련** (8장) | 분기마다 |
| 7 | **도메인 잠금·자동 갱신** (34장) | |
| 8 | **이메일 인증(SPF·DKIM·DMARC)** — 내 도메인 사칭 메일 방지 (30장) | |
| 9 | **개인정보처리방침 + 최소 수집** (10장) | |
| 10 | **피싱 교육** — "결제 정보 변경", "협찬 제안 첨부 파일" 메일 주의 (24·30장) | |

## 3. 직접 개발한 사이트라면 추가로

### 계정·로그인
- [ ] 비밀번호는 **해시(bcrypt, argon2 등)** 로만 저장
- [ ] 로그인 실패 횟수 제한(속도 제한), 캡차
- [ ] 비밀번호 재설정 링크는 **짧은 유효시간 + 한 번만 사용**
- [ ] 세션 쿠키에 **Secure · HttpOnly · SameSite** 설정
- [ ] 관리자 페이지 주소·접근 IP 제한, 관리자 2단계 인증

### 데이터·입력
- [ ] 모든 요청에서 **권한(주인 여부) 확인** — A01
- [ ] DB 쿼리는 **자리표시자** — A05
- [ ] 출력 시 특수문자 처리(XSS 방지) — 프레임워크 기본 기능 끄지 않기
- [ ] **파일 업로드**: 종류·크기 제한, 실행 파일 차단, 업로드 폴더에서 실행 금지
- [ ] 결제·쿠폰 금액은 **서버에서 다시 계산** (화면에서 보낸 가격을 믿지 않기)

### 비밀 정보
- [ ] API 키·DB 비밀번호는 **환경 변수**, Git에 절대 커밋 금지 (6장)
- [ ] 실수로 올렸으면 **키를 즉시 교체**(삭제만으론 부족 — 기록에 남음)
- [ ] 키마다 필요한 권한만, 정기 교체(분기)

### 서버·설정
- [ ] **보안 헤더**: HSTS(항상 HTTPS), CSP(허용한 스크립트만 실행), X-Content-Type-Options, Referrer-Policy, 다른 사이트에 내 페이지를 몰래 넣지 못하게(frame-ancestors)
- [ ] 오류 화면에 **코드·경로·DB 정보 숨기기** — A10
- [ ] 개발용 디버그 모드 **끄기**
- [ ] 안 쓰는 포트·서비스 닫기, 서버 OS 자동 보안 업데이트 (VPS라면)
- [ ] CORS는 내 도메인만 허용
- [ ] 속도 제한(rate limit)으로 무차별 요청·봇 막기, 필요하면 CDN·방화벽 서비스(DDoS 방어)

### 공급망 — A03
- [ ] 라이브러리 **철자 확인**(가짜 패키지 주의, [코딩 8장](coding/08-developer-tools.md)), 다운로드 수·관리 상태 확인
- [ ] 자동 취약점 알림(GitHub Dependabot 등) 켜기
- [ ] 잠금 파일(package-lock.json 등)로 버전 고정

### 로그·모니터링 — A09
- [ ] 로그인·관리자 작업·권한 실패 **로그 남기기** (비밀번호·카드번호는 로그에 남기지 않기)
- [ ] 이상 징후 알림 (짧은 시간 로그인 실패 폭증, 관리자 새 IP 로그인)
- [ ] 오류 모니터링 도구 연결 (9장)

## 4. 개인정보보호법상 "안전성 확보조치" 핵심 (요약)

개인정보를 다루는 사업자는 **개인정보의 안전성 확보조치 기준**(개인정보보호위원회 고시)을 지켜야 해요. 2023년 9월 개정으로 기존 기준들이 하나로 합쳐졌어요.

| 항목 | 내용 (요약) |
|---|---|
| **내부 관리계획** | 누가 개인정보를 어떻게 다루는지 규칙 문서 (규모가 작으면 간소화 가능 여부 안내서 확인) |
| **접근 권한 관리** | 필요한 사람만, 퇴직·변경 시 바로 회수, 권한 변경 기록 보관 |
| **접근 통제** | 외부에서 개인정보처리시스템 접속 시 안전한 인증 수단 등 |
| **암호화** | 비밀번호는 복원 불가능하게(해시), 주민번호·계좌 등 고유식별·금융 정보는 암호화, 전송 시 HTTPS |
| **접속기록 보관** | 개인정보처리시스템 접속기록(누가·언제·어디서·무엇을)을 **원칙 1년 이상**, 5만 명 이상 정보를 다루는 등 일정 조건이면 **2년 이상** 보관하고 정기 점검 |
| **악성 프로그램 방지** | 백신 등 보안 프로그램, 업데이트 |
| **물리적 안전** | 서류·보조저장장치 잠금 보관 |
| **파기** | 다 쓴 개인정보 복구 불가능하게 삭제 |

> 💡 빌더를 쓰면 이 중 상당 부분을 업체가 처리하지만, **관리자 계정 관리·권한·다운로드한 엑셀 파일 보관**은 내 몫이에요. 회원 엑셀을 내 PC에 내려받아 방치하는 게 흔한 유출 경로예요.

## 5. 해킹·유출이 의심될 때

```
1. 침착하게 기록: 언제 무엇을 발견했나 (화면 캡처)
2. 피해 확산 막기: 관련 계정 비밀번호 변경, 세션 끊기, API 키 교체, 필요하면 사이트 점검 모드
3. 증거 보존: 로그를 지우지 말 것
4. 신고·상담: 한국인터넷진흥원(KISA) 118 상담, 경찰 사이버수사
5. 개인정보 유출이면: 이용자 통지 + 일정 규모 이상은 개인정보보호위원회·KISA 신고 (기한 있음, 10장)
6. 복구: 깨끗한 백업으로 복구, 구멍 막고 재오픈
7. 포스트모템: 원인과 재발 방지 (9장)
```

## 6. 보안 점검 도구 (무료로 확인해 볼 수 있는 것)

| 도구 | 무엇을 |
|---|---|
| 브라우저 개발자 도구(F12) → 네트워크·보안 탭 | HTTPS, 보안 헤더, 쿠키 설정 |
| 보안 헤더 검사 사이트 | 보안 헤더가 있는지 점수로 |
| SSL 검사 사이트 | 인증서·암호화 설정 |
| GitHub Dependabot / `npm audit` / `pip-audit` | 라이브러리 취약점 |
| Claude 같은 AI에게 **"보안 관점으로 코드 리뷰해 줘"** | 권한 확인 누락, 인젝션, 비밀 키 노출 찾기 (결과는 직접 검증) |

> ⚠️ 남의 사이트를 허락 없이 스캔·공격 테스트하는 건 **불법**이에요. 반드시 **내 사이트**만.

### 이 장 요약
1. 웹 보안 1위 위험은 **권한 확인 실패**. 새로 **공급망**과 **예외 처리**가 순위에 들어왔다 (OWASP 2025).
2. 누구나: **2단계 인증·개인 계정·HTTPS·업데이트·백업·도메인 잠금·메일 인증**. 개발자는 추가로 **해시·자리표시자·보안 헤더·비밀키 관리·로그**.
3. 개인정보는 **권한 관리·암호화·접속기록 보관(원칙 1년, 조건에 따라 2년)·파기**. 유출이 의심되면 **확산 차단 → 증거 보존 → 신고**.
