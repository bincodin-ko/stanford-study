# 68. 속도·오류 추적·접근성·클라우드 비용 관리

> 모니터링·장애 대응 기본은 [9장](09-operations.md), 호스팅 선택은 [36장](36-choosing-hosting.md), 출시 전 점검은 [38장](38-launch-checklist-for-claude.md)에 있어요. 이 장은 **출시 후 품질과 돈을 지키는** 운영 기술이에요.

---

## 1. 속도 — 느리면 손님이 떠나요

### 구글이 보는 3가지 숫자 (코어 웹 바이탈)
web.dev(구글 공식) 기준 "좋음" 기준이에요. 실제 방문자의 **75%가 이 안에 들어와야** 해요.

| 지표 | 뜻 | 좋음 | 나쁨 |
|---|---|---|---|
| **LCP** | 가장 큰 내용(대표 이미지·제목)이 보이기까지 | 2.5초 이하 | 4초 초과 |
| **INP** | 버튼을 누르고 화면이 반응하기까지 | 0.2초 이하 | 0.5초 초과 |
| **CLS** | 읽는 중에 화면이 갑자기 밀리는 정도 | 0.1 이하 | 0.25 초과 |

- 구글은 이 숫자가 검색 순위에 **작은 영향**만 준다고 해요. 더 중요한 건 **손님이 답답해서 나가는 것**이에요.
- 확인 도구: **PageSpeed Insights**(주소만 넣으면 됨), 구글 서치 콘솔의 "코어 웹 바이탈" 보고서, 크롬 개발자 도구의 Lighthouse.

### 흔한 원인과 해결 (효과 큰 순서)
| 원인 | 해결 |
|---|---|
| **너무 큰 이미지** (폰 사진 5MB 그대로) | 화면 크기에 맞게 줄이기, **WebP/AVIF** 형식, 화면 아래 이미지는 **나중에 불러오기(lazy loading)** |
| 이미지·광고 자리 크기를 안 정해 둠 | 이미지에 `width`·`height` 지정 → CLS 해결 |
| 외부 스크립트가 많음 (채팅 위젯, 분석 도구 여러 개, 광고) | 꼭 필요한 것만, 늦게 불러오기 |
| 느린 서버·먼 서버 | CDN(5장), 한국 손님이면 가까운 지역 서버 (36장) |
| DB 조회가 느림 | 인덱스 (59장), 같은 데이터 반복 조회 줄이기 |
| 매번 새로 계산 | 캐시 (코딩 10장) |
| 글꼴 파일이 큼 | 한글 글꼴은 용량이 커서 **필요한 글자만(서브셋)** 또는 웹폰트 서비스 |

> 💡 Claude에게: "PageSpeed Insights 결과를 붙여 줄게. 효과 큰 순서로 고칠 목록을 만들고, 하나씩 고친 뒤 다시 측정하자."

## 2. 오류 추적 — 손님보다 먼저 알기

손님 대부분은 오류를 겪어도 **말없이 떠나요.** 오류를 자동으로 모아 알려 주는 도구가 필요해요.

| 도구 종류 | 예 | 하는 일 |
|---|---|---|
| **오류 추적** | Sentry 등 | 화면·서버에서 난 오류를 모아 **어느 코드, 몇 명, 어떤 기기**인지 알려 줌 |
| **업타임 감시** | 9장 | 사이트가 열리는지 몇 분마다 확인 |
| **로그** | 호스팅 로그, 로그 수집 서비스 | 무슨 일이 있었는지 기록 |

### 로그 잘 남기기
- **무엇을 남기나**: 시각, 요청 주소, 결과(성공/실패), 오류 내용, 주문번호 같은 **추적용 번호**
- **남기면 안 되는 것**: 비밀번호, 카드 번호, 주민번호, API 키, 로그인 토큰 (37장). 이메일·전화도 꼭 필요할 때만
- 오류마다 **번호(요청 ID)**를 붙여 손님 화면에도 보여 주면, 문의가 왔을 때 바로 찾아요: "오류 번호 A7F3을 알려 주세요"
- 보관 기간을 정하고 지나면 지우기

### 알림 피로 줄이기
- 모든 오류를 알림으로 받으면 결국 아무것도 안 보게 돼요.
- **새로운 종류의 오류**, **갑자기 많아진 오류**, **결제·로그인 오류**만 즉시 알림. 나머지는 주간 정리 (9장 심각도).

## 3. 접근성 — 누구나 쓸 수 있게

**웹 접근성** = 시각·청각·운동 장애가 있는 사람, 노인, 일시적으로 불편한 사람(팔 다침, 햇빛 아래)도 쓸 수 있게 만드는 것이에요. 많은 부분이 **모든 손님의 편의**와 겹쳐요.

| 할 것 | 이유 |
|---|---|
| 이미지 **대체 텍스트(alt)** (38장) | 화면 낭독기가 읽어 줌 |
| 글자와 배경의 **충분한 대비** | 저시력·햇빛 아래 |
| 글자 크기를 키워도 깨지지 않게 | 노안 |
| **키보드만으로** 모든 기능 사용 가능 | 마우스를 못 쓰는 사람 |
| 입력 칸마다 **이름표(label)** | 화면 낭독기, 자동 입력 |
| **색만으로 정보 전달 금지** ("빨간 칸이 오류") | 색각 이상 → 글자로도 표시 |
| 버튼·링크 터치 영역 넉넉히 | 손 떨림, 큰 손가락 |
| 영상에 자막 | 청각 장애, 소리 끄고 보는 사람 |

- 확인: Lighthouse의 접근성 점수, 키보드 Tab 키로 사이트 끝까지 가 보기.
- 공공기관·일정 규모 이상 사업자에게는 법적 의무가 있을 수 있어요(장애인차별금지법 등). 해당 여부는 확인하세요.
- **다크 모드**: 손님 기기 설정을 따르는 다크 모드는 요즘 기대하는 기능이에요. 처음부터 색을 **변수(토큰)**로 정해 두면(48장 디자인 시스템) 쉽게 추가할 수 있어요.

## 4. 클라우드·도구 비용 관리 — 요금 폭탄 막기

1인 사업자의 흔한 사고: **"자고 일어났더니 클라우드 요금 수백만 원"**. 원인은 대부분 API 키 유출(57장), 무한 반복 코드, 예상 못 한 트래픽, 끄는 걸 잊은 서버예요.

### 반드시 할 것
| 할 것 | 내용 |
|---|---|
| **예산 알림** | 클라우드(AWS·구글 클라우드·버셀 등)마다 **월 예산 알림**을 50%·80%·100%에 설정 |
| **사용량 상한(하드 리밋)** | 넘으면 멈추게 할 수 있는 서비스는 상한 설정 (AI API, 문자 발송, 지도 API 등) |
| **결제 카드 분리** | 사업용 카드 하나에 모으고, 한도를 적당히 |
| **비밀 키 관리** | 키 유출 = 남이 내 돈을 씀. Git에 올리지 않기, 정기 교체 (37장) |
| **매달 비용 점검** | 44장 월간 루틴에 "구독·클라우드 비용 목록" 추가 |

### 구독 도구 정리 (매달 10분)
| 도구 | 월 비용 | 지난달 썼나? | 대안 |
|---|---|---|---|
| 호스팅 | | | |
| 도메인·이메일 | | | |
| AI 도구 | | | |
| 디자인·분석·자동화 | | | |

- 무료 체험 후 **자동 결제**되는 것 주의. 가입할 때 해지 날짜를 달력에 적어 두세요.
- 같은 일을 하는 도구가 2개면 하나로.
- 연간 결제 할인은 **3개월 이상 써 보고** 확신이 들 때만.

---

### 이 장 요약
1. 속도는 **LCP 2.5초·INP 0.2초·CLS 0.1** 기준, 가장 흔한 원인은 **큰 이미지**.
2. **오류 추적 도구 + 요청 번호**로 손님보다 먼저 알고, 로그에 **비밀번호·카드·키는 남기지 않는다**.
3. 접근성은 **alt·대비·키보드·이름표**부터, 비용은 **예산 알림·사용량 상한·매달 구독 점검**으로 지킨다.
