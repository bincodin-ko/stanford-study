# 80. 이 교재로 만드는 제품 — "한 바퀴" 기획 (실습 사례)

> 지금까지 배운 내용을 **실제 제품 하나에 적용한 기획 문서**예요. 55장 실습 프로젝트의 실제 사례이자, 교재를 외우는 대신 **만들면서 단계별로 안내받는 웹 서비스**의 설계도예요.
> 원본 문서는 저장소의 `product/` 폴더에 있고, 이 장은 `tools/make-ch80.py`로 다시 만들어요. (2026-11-02 기준)

**이 장을 읽는 법**
- 1부 기획서: 42장(검증)·62장(포지셔닝)·4장(MoSCoW)을 적용한 예
- 2부 진행표: 1~81장을 **"순서대로 하는 일"**로 다시 묶은 것 — 교재 전체의 **실천용 목차**로도 쓸 수 있어요
- 3부 설계: 58~60장(설계·DB·API)·65장(로그인)·67장(AI)·81장(최적화·안정화)을 적용한 예
- 4~5부 결정 기록: 58장 ADR 양식으로 남긴 실제 결정

---

## 1부. 기획서 (PRD)

> 가제: **"한 바퀴"** — 아이디어에서 첫 손님까지 한 바퀴를 같이 돌아 주는 코치
> 이름은 나중에 상표 검색 후 확정해요([47장](47-trademark-copyright-license.md)).

---

### 1. 왜 만드나 (문제)

- 1인 창업 지식은 너무 많아요. 이 저장소만 해도 74장 + 코딩 13장, PDF로 384쪽이에요. **다 외우는 건 불가능**해요.
- 실제로 필요한 건 "지금 내 단계에서 **무엇을 해야 하고**, **무엇을 봐야 하고**, **AI에게 뭐라고 시켜야 하는지**"예요.
- 초보자는 **순서**를 몰라서 만들기부터 시작하고(검증 생략), 출시 직전에 법·보안을 놓쳐요(57장 실패 사례).

### 2. 누구를 위한 것인가

| 순서 | 사용자 | 설명 |
|---|---|---|
| 1단계 | **나** | 이 가이드로 이 가이드를 만들며 직접 써 보기 (도그푸딩) |
| 2단계 | **초보 1인 창업 지망생** | 코딩·사업 경험이 거의 없고, AI로 혼자 만들어 보고 싶은 사람 |

**페르소나**: "29세 회사원. 퇴근 후 주 5~8시간. 클로드·챗GPT는 써 봤지만 사업은 처음. 유튜브 강의는 봤는데 막상 뭘부터 할지 모름. 실패해서 돈 날리는 게 무서움."

### 3. 대안 (손님이 지금 쓰는 것 — 62장 포지셔닝)

| 대안 | 부족한 점 |
|---|---|
| 챗GPT·클로드에 그냥 물어보기 | 순서·진행 상황을 기억 못 함, 매번 처음부터 설명, 한국 법·세금 빠뜨림 |
| 온라인 강의 | 듣고 끝, 내 프로젝트에 적용은 혼자 |
| 책·블로그 | 흩어져 있고 오래된 정보 섞임 |
| 노션 템플릿 | 체크리스트만 있고 "왜·어떻게"와 AI 도움이 없음 |

### 4. 포지셔닝 한 문장 (62장)

> **AI로 혼자 첫 서비스를 만들고 싶은 초보자**를 위한 **단계별 창업 코치**예요.
> 그냥 AI에게 묻는 것과 달리, **내 진행 단계를 기억하고 한국 법·세금·출시 체크리스트까지 순서대로 챙겨 줘서** 빠뜨리지 않고 첫 손님까지 갈 수 있어요.

### 5. 핵심 기능 (MVP — MoSCoW, 4장)

#### Must (나만 쓰는 첫 버전에 꼭)
| # | 기능 | 설명 |
|---|---|---|
| M1 | **프로젝트 만들기** | 아이디어·손님·주당 가능 시간 입력 |
| M2 | **진행표** | 0~7단계, 약 51개 스텝 ([02-roadmap-steps](#2부-진행표--단계와-스텝)). 지금 단계 표시 |
| M3 | **스텝 화면** | 목표 · 할 일 체크 · 완료 기준 · 관련 장 바로 읽기 · **복사용 Claude 요청문** · 산출물 메모 칸 |
| M4 | **장 읽기** | 이 저장소의 docs를 앱 안에서 읽기 |
| M5 | **AI 코치** | 현재 스텝과 내 프로젝트 정보, 관련 장 내용을 알고 답함. "다음에 뭐 해?"에 답함 |
| M6 | **로그인** | 내 진행 상황 저장 (65장) |

#### Should (판매 전에)
| # | 기능 |
|---|---|
| S1 | 주간 계획: "이번 주 5시간이면 이것만" (54장) |
| S2 | 산출물 모아 보기 (페르소나, 가격 계산, 기획서) → PDF 내보내기 |
| S3 | AI 사용 한도·비용 표시 (67장) |
| S4 | 카카오 로그인 |
| S5 | 소개 페이지 + 사전 신청 (42장 검증용) |

#### Could (나중에)
- 결제·구독 (39장), 여러 프로젝트, 커뮤니티, 진행 알림 메일 (64장), 모바일 앱

#### Won't (이번엔 안 함)
- 코드를 대신 짜 주는 기능 (Claude Code가 이미 잘함 — 우리는 **"무엇을 시킬지"**를 알려 줌)
- 법률·세무 확정 답변 (항상 "공식 확인 필요" 표시)

### 6. 성공 기준 (11·42장)

| 단계 | 기준 |
|---|---|
| 나만 쓰는 버전 | 내가 이 앱으로 **이 앱의 0~4단계를 실제로 완료** (출시 직전까지) |
| 판매 검증 | 소개 페이지 방문자 중 **사전 신청 10% 이상**, 초보자 5명 인터뷰에서 "써 보고 싶다" 3명 이상 |
| 유료 전환 검증 | 베타 사용자 중 "못 쓰게 되면 매우 실망" **40% 이상** (42장 PMF 테스트) |

### 7. 위험과 대응

| 위험 | 대응 |
|---|---|
| 법·세금 정보가 틀리거나 낡음 | 모든 법·세금 스텝에 **확인일 + 공식 확인 링크**, "확인하지 못한 것" 표시 유지, 분기별 재확인 (74장) |
| AI 코치가 틀린 말 | 답에 관련 장 근거 표시, 법·돈 관련은 "공식 확인" 안내 고정 (67장) |

| 혼자 만들다 지침 | 스텝을 작게(2시간 이내), 주간 계획 (54장) |

| 주 | 할 일 | 끝나면 |
|---|---|---|
| 0주 | 이 기획서·설계 확정 (언어: Rust), 새 저장소 만들기 | 승인된 문서 |
| 1주 | 진행표 + 스텝 화면 + 장 읽기 (로그인 없이 내 PC에서) + 테스트·CI·상태 확인 주소 | 스텝을 따라갈 수 있음 |

| 4주~ | 이 앱으로 이 앱의 검증·출시 단계 진행 + 소개 페이지로 판매 검증 | 판매 여부 결정 |

## 2부. 진행표 — 단계와 스텝

이 표가 앱의 **뼈대**예요. 74장짜리 교재를 "순서대로 하는 일"로 다시 묶은 거예요. 앱에서는 이 내용이 데이터 파일(`roadmap.json` 등)로 들어가요.

각 스텝은 이렇게 생겼어요.
```
제목 · 목표(한 줄) · 할 일 체크리스트 · 완료 기준(산출물) · 관련 장 · 복사용 Claude 요청문 · 예상 시간
```
- 스텝 하나는 **2시간 안팎**으로 끝나게 쪼개요 (54장, 퇴근 후 1~2회).
- **[선택]** 스텝은 프로젝트 종류에 따라 건너뛰어요 (결제 없는 사이트, AI 기능 없는 서비스 등).

### 5. AI 코치 설계 (67장)

```
[손님 질문]
   ▼
[서버: coach 모듈]
 ① 로그인·하루 한도 확인 (usage_daily)
 ② 맥락 조립:
    - 시스템 지시: 역할, 말투(쉬운 한국어), 규칙(법·세금은 "공식 확인 필요")
    - 내 프로젝트 정보 (아이디어·손님·현재 스텝)
    - 현재 스텝 정의 (목표·체크·완료 기준)
    - 관련 장 본문 (스텝에 연결된 장의 해당 절만 — 처음엔 검색 없이)
    - 최근 대화 몇 개
 ③ Claude API 호출 (features/coach, 타임아웃·출력 길이 제한)
 ④ 토큰 기록 → 답 + "근거: ○장 ○절" 링크
```
- **처음엔 RAG 검색 없이** "스텝 → 연결된 장"으로 넣어요. 장이 정해져 있어서 충분하고 단순해요. 나중에 자유 질문이 많아지면 검색 추가.
- **프롬프트 인젝션 대비**: 코치는 **읽기·조언만**, DB 수정·스텝 완료 처리는 손님이 버튼으로 (AI에게 권한 없음).
- **비용**: 나만 쓰는 단계는 하루 50회 한도로 시작, 화면에 이번 달 사용량 표시.

## 4부. 결정 기록 0001 — 웹 서비스 + AI 코치

- 상태: 채택 (2026-11-02)

### 배경
1인 창업 교재(74장 + 코딩 13장)는 외우기에 너무 많다. 만들면서 그때그때 필요한 내용을 안내받는 도구가 필요하다.
처음 사용자는 나 자신이고, 나중에 초보 1인 창업 지망생에게 판매하는 것을 검토한다.

### 고려한 선택지
- Claude 안에서 쓰는 코치 설정(스킬): 며칠이면 되지만 판매·결제가 어렵다.
- 모바일 앱: 알림이 좋지만 심사·수수료가 있고 가장 오래 걸린다.
- **웹 서비스 + AI 코치**: 회원·구독 결제·진행 저장이 쉽고, 휴대폰 브라우저에서도 된다.

### 결정
웹 서비스 + AI 코치. 첫 번째로 진행해 볼 사업은 이 가이드 제품 자체로 한다(도그푸딩).
판매 대상은 "코딩·사업 경험이 거의 없는 초보 1인 창업 지망생"으로 둔다.

### 결과
- 좋아지는 점: 판매로 이어가기 쉽고, 만드는 과정 자체가 교재 55장 실습이 된다.
- 나빠지는 점: 스킬 방식보다 만드는 데 오래 걸린다(나만 쓰는 버전 약 3주).
- 모바일 앱은 웹으로 검증한 뒤 다시 검토한다.

## 5부. 결정 기록 0002 — Rust(Axum) + 서버 렌더링

- 상태: 채택 (2026-11-02)

### 배경
처음 제안은 Next.js + Supabase + Vercel이었다. 사용자가 개발 언어로 Rust를 원했다.

### 결정
- 서버: Rust + Axum(Tokio)
- 화면: 서버에서 HTML을 만들어 보낸다(Askama 템플릿). 처음엔 자바스크립트 없이 HTML 폼으로 동작
- 로그인·DB: Supabase(Auth + Postgres + RLS)는 그대로 — 2주차
- 배포: Vercel 대신 도커 컨테이너를 실행하는 호스팅(Fly.io·Render 등) — 2주차에 결정
- AI: Claude API를 서버에서 HTTP로 호출 — 3주차
- 1주차부터 테스트·CI(fmt·clippy·test)·상태 확인 주소·안전한 종료를 넣는다(81장)

### 결과
- 좋아지는 점: 빠르고 적은 자원으로 실행(호스팅 비용↓), 컴파일러가 많은 실수를 미리 잡음, 하나의 실행 파일로 배포가 단순
- 나빠지는 점: Rust는 배우기 어렵고 컴파일이 느림. AI 도구가 만든 Rust 코드도 컴파일 오류가 잦을 수 있다 → 작게 나눠 만들고 매번 cargo test
- Next.js용으로 쓰여 있던 설계(폴더 구조 등)는 Rust 구조로 바꿨다(03-architecture)

---

### 이 장 요약
1. 교재를 외우지 않고 **만들면서 그때그때 필요한 장을 안내받는** 웹 서비스 + AI 코치를 기획했다. 첫 사용자는 나, 첫 프로젝트는 이 제품 자체(도그푸딩).
2. 진행표는 **0~7단계, 51개 스텝** — 각 스텝에 목표·체크리스트·완료 기준·관련 장·Claude 요청문이 있다. 출시 후 **안정화 기간**과 **측정 기반 최적화**까지 포함.
3. 기술은 **Rust(Axum) + 서버 렌더링 + Supabase + 도커 호스팅**, 1주차부터 **테스트·CI·상태 확인·안전한 종료**를 넣고, AI 코치는 **서버에서만 호출하고 읽기·조언만** 한다.
